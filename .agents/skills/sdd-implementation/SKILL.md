# SDD Implementation

## 适用范围

仅在用户已经确认产品行为、任务范围和验收边界后使用。若需求仍有互斥解释，先回到 `AGENTS.md` 的需求确认门。

## 最小节拍

1. 阅读 `AGENTS.md`、相关 `SPEC.md` 章节、`TESTING.md`、追踪矩阵和活动计划。
2. 检查 `git status --short` 与相关 diff，保护既有工作树改动。
3. 跨文件、高风险或不可逆变更前执行 checkpoint。
4. 先写/更新回归测试，运行目标测试并确认真实失败原因。
5. 实现最小变更，不删旧测试、不放宽断言、不改变未确认产品规则。
6. 做同类实现的全局扫描，检查用户隔离、事务、幂等、离线降级和 UI 链路。
7. 分层运行测试；明确区分单测、集成、浏览器 E2E、构建和未运行项。
8. 更新追踪矩阵；有重要决策或 OSS 复用时更新相应文档。

## 停止条件

遇到需求歧义、数据语义变化、许可证不清、密钥/服务依赖缺失或测试与 SPEC 冲突时暂停实现并报告证据；不得静默裁定。

## 交付报告

报告批次、对应 SPEC、修改文件、测试命令及 pass/fail/skipped、真实 E2E、未完成项和本批次以外的既存改动是否保留。测试未运行或有 skipped 时，不得报告为全绿。
