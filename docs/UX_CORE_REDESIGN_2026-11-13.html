EasyExam Core UX 重设计

这不是七个界面缺陷，是六个结构机制的七个症状：一个实体两条路由、返回是静态树而不是历史、状态没有唯一源、学习状态挂在错的那条边上、生命周期只被逐段实现、控件层缺失。视觉方向保留，结构重做。

01

题库不该有两个页面

只读详情页与可写管理页各自带 questions / structure / members，权限决定了页面结构。用户被迫先判断"我在哪一层"。

02

归档不是删除，也不是没有去处

题目归档写的是 questions.is_deleted，与删除同一列；而学习状态只挂题目、不挂"题目在某库中"，所以"归档后去哪了"没有答案。

03

学习闭环没有闭环

报告只在内存、"重新练习"实际退出、模考错题永不进复习、17 个开始按钮互不等价、完成与放弃在库里是同一个值。

01 / 证据

先看真实使用，而不是文档假设

只读副本取自 2026-11-13 的生产库，32 张表逐表计数。产品实际服务的不是"多用户协作题库平台"，而是"一个人 + 一个大题库 + 标签"。

这四组零很关键：章节树、多解释体系、考试蓝图、个人资料——SPEC 里都有，界面上也都有入口，但真实使用从未产生一行数据。它们可以保留，但不能占据主航道。反过来，标签是唯一被真正使用的组织维度，而它现在只出现在一个筛选下拉里。

另一个数字更刺眼：162 个会话的 score 全部是 0.0，216 条作答的 time_spent 全部是 0。成绩与用时从未落值——所以现在的"报告"本质上是完赛瞬间算出来、离开页面就消失的一张纸。

02 / 结构

现状：一个实体，两条路；一个任务，十七个入口

现在

题库 ─┬─→ 列表

      │     │            └─ 管理 ──→ /manage（6 tab）

      └─ 点开始 = 与题库、今天互不相同的参数

目标

今天 ──→ 今日队列 ──→ 开始学习面板
                        └─→ 会话 ──→ 报告（可回看）

左侧每一个分叉都是一次"用户要先做判断"的地方；右侧每个实体只有一个规范页面。返回一律走历史，不再声明父子。

03 / 根因

六个机制，解释全部七个抱怨

R1

按"编辑能力"分层，而不是按"用户任务"分层

同一实体拆成只读页与可写页，两页三个同名 tab；同一任务复制成 17 个开始练习、8 个导入、5 个进入管理的入口。权限只该决定"有没有按钮"，不该决定"页面长什么样"。 router/index.js:22-23 · BankDetailView:414 · BankManageView:865

R2

全局没有唯一状态源

筛选/排序写进 URL+sessionStorage，tab 写进 URL，页码与选中在内存，导入步骤由"有没有预览"推导，草稿 id 只在内存。刷新、返回、分享、换设备各丢一部分现场。 BankManageView:961,990 · ImportView:703-708

R3

导航是一棵静态声明的树，不是历史

二级页声明 meta.back，返回按钮据此 push 一个未必访问过的父级。多入口页面在树里无解。全仓没有路由守卫，也没有一个 <router-link>。 AppLayout:251-281 · router/index.js 无 beforeEach

R4

学习状态挂在题目上，不挂"题目在某库中"

fsrs_cards、mistake_records、kill_records 主键都是 (user, question)；questions.is_deleted 同时是归档与删除。界面的单位是"这个库里的这道题"，系统里没有这个状态可放。 question_repository.py:444-450

R5

生命周期只被逐段实现，没有一条线

导入不是向导、无离开守卫；会话有 4 种模式、2 个 runner、两套快捷键，报告不落库；"到期""锁定""归档"各有两三套定义。每段都说得通，连起来走不通。 PracticeViewV1:2061 · practice_repository:456,761

R6

视觉系统成熟，控件层与反馈层缺失

6 套对话框、2 套确认（22 处原生 confirm）、4 套表格、8 套列表行、2 套成功提示；间距 token 使用次数为 0；图标按英文名而不是用户动作定义。 style.css:35 · LinearIcon.vue

04 / 方案

八条决策，已确认

以下八条在 2026-11-13 已由你拍板。其中"家庭/小团队并列"把协作升为一等公民，因此多了成员管理、两种角色层级与真实的管理员面（P4）。

1 · 题库与题目收紧为 1:1

联表允许一题多库，但产品语义是"复制=新题、移动=换家"，真实数据 0 跨库。收紧后，"本库归档"才有意义，跨库状态歧义消失。复制入口保留，但明确提示学习记录不会复制。

已确认

2 · 归档是库内"已归档"视图，不是回收站

新增 archived_at，归档与删除分离；工作区用 ?archived=1 查看与恢复。不再回答"题目回收站在哪"——因为归档不删除，删除只发生在空库或明确确认时。

已确认

3 · 模考错题默认进入复习队列

现在交卷只写错题事实、不写 FSRS 卡，考试错题永远没有到期日。按 SPEC"由考试配置决定"补上开关，默认开启。

已确认

4 · 斩杀题库是队列的一个来源，不是独立页面

SPEC 要求"独立斩杀题库"，但独立成一级页面会再复制一套列表与筛选。方案：复习队列的 ?source=killed 视图 + 档案里的数量，保留"查漏补缺"启动入口。

已确认

5 · 删除 /banks/:id/manage，合并两页

保留成熟的管理页 tab 骨架作为唯一题库工作区，吸收浏览能力；题目从右侧抽屉升级为 /banks/:id/q/:qid 页面。这是本方案最大的结构变动，也是"查看题库意义何在"的唯一答案。

已确认

6 · 家庭 / 小团队并列

协作升为一等公民：题库列表分「我的 / 共享给我」，成员管理（搜索添加、改角色、移除、自助离开、转移所有权）进入主流程，成员 tab 不再只是一串用户名。

已确认

7 · 建真实的管理员面

users.is_admin；实例管理提供用户列表、启用/禁用、重置密码、注册开关与会话管理；界面上的「管理员 / 成员」不再是假标签。

已确认

8 · 允许迁移，先本地验证

归档 archived_at、会话 status / result_json、is_admin 与 instance_settings 都以 v19 迁移落地；先在本地库与 E2E 验证，生产备份后再升级。

已确认

06 / 边界

这一版没有做什么

没有修改任何生产代码，没有运行构建或测试，没有对生产库执行写操作。视觉方向（Editorial Precision、四套配色、字体与 1px 排版）整体保留；只收敛"同一个东西有六种实现"的控件层，不重绘。

完整诊断（含七个域的逐条证据、数据模型成本地图、移动端缺口、接口异常清单）在仓库 docs/UX_CORE_REDESIGN_2026-11-13.md。
