# 双语完整性规则与执行门禁实施计划

> **For agentic workers:** Use the approved subagent execution method. Independent repositories have separate writers; changes in the same repository are sequential. Steps use checkbox syntax.

**Goal:** 让 Starter 的双语规则有真实执行入口，并让 EasyExam 的系统文案、错误与浏览器验收遵守该规则。

**Architecture:** 文档镜像检查与产品本地化检查分离。Starter 提供可配置的检查调度器；EasyExam 以实际运行字典、源码扫描和真实浏览器测试实现项目适配，不能靠运行期翻译 DOM 或语言按钮状态冒充覆盖。

**Tech Stack:** Python、Vue 3、JavaScript、Node test runner、FastAPI、Playwright。

**Spec:** 用户已确认的双语完整性交付规则；EasyExam SPEC.md 国际化条目；Starter standards/LOCALIZATION.md。

## Global Constraints

- 所有系统文案覆盖页面、菜单、弹窗、错误、空/加载状态、属性、无障碍标签、动态状态和系统生成导出内容。
- 用户原始题目、标准答案、官方解析、用户名、资料内容及品牌名不得自动改写。豁免必须限定内容与理由。
- 原中文系统文案保持兼容，不能改变已有领域行为和旧测试预期。
- 新文案同批提供中英翻译；缺键、空值、占位符错误、未知引用和新增裸文案阻断交付。
- 每道新门禁有违规与合规实证；无法执行或缺适配器不能按通过处理。
- 保留现有工作树改动和配置；不提交、不推送、不部署、不修改用户数据库。
- 双语支持与翻译自然程度区分；AI 历史内容属于原始内容，生成语言约束与模型实际输出证据分开报告。
- 浏览器使用临时数据库和临时账号；不删除旧测试、不放宽断言，不注入预翻译的假页面。

## Review Focus

1. 切换语言后已创建的错误、提示、派生标签是否仍保留旧语言。
2. 模板属性、三元表达式、alert/confirm 和 JavaScript 动态状态是否绕过字典。
3. 接口未知错误、校验错误和离线故障是否泄露单语言详情或使对象直接显示为字符串。
4. 多语言布局是否隐藏核心按钮；英文界面不得把用户原文误判为漏译。
5. 扫描器是否只检查现有文件列表而忽略新文件、动态键或未配置检查。
