# EasyExam P2 完整 UI/UX 设计源码

本目录是 **P2「完整 UI/UX 设计收敛」轮的最终设计源码**，与 OpenDesign 工作区逐字节一致。
P1 冻结产品规格见 `../product-spec/`，那是产品语义的唯一权威；本目录是它的视觉与交互落地。

## 这是什么

一套可直接在浏览器中打开的完整产品原型：**16 个产品屏幕 + 5 个流程页 + 1 个完整产品壳**，
共 38 个源文件（含本导览）、约 2.1 MB，全部为纯文本（HTML / CSS / JS / Markdown），无构建步骤、无二进制资源。

打开方式：任选一个 `.html` 文件用浏览器直接打开即可，所有资源引用都是相对路径。
URL 参数：`?theme=light|dark` 切明暗，`?palette=editorial|gruvbox|everforest|catppuccin` 切配色，
`?spec=1` 显示设计规格区（默认产品模式只呈现最终用户内容）。

## 九条全局设计规则（独立审查请重点核对）

1. **统一纸面构图**——全产品普通页面共用同一张纸：宽 1120px（`--d-max`）、同一左边界、同一外边距、
   同一套基础内容网格。页面之间的功能差异只在纸面**内部**用排版解决（分栏、密度、宽表自滚、次要信息下沉），
   不改纸张规格。例外仅登录页与全屏练习/模考 runner（`.focus-shell`）。`.content.wide` 是纯语义标记，不改变宽度。
2. **权限两向规则（CR-12）**——判据是「这个入口说的事，对这个用户有意义吗」：
   有意义但不能做 → **禁用并解释**；没意义 → **不出现**。普通用户看不到实例管理入口，普通成员看不到
   题库设置/归档/删除。实现分工在 `assets/store.js`：`can(action)` 答能不能做，`relevant(action)` 答有没有关系。
3. **本期不提供的功能不进产品界面**——FN-113 历史作答重判、FN-509 AI 建议标签与蓝图等已裁定本期不做的能力，
   不在最终产品界面出现占位入口或说明文字；规格记录留在 `docs/product-spec/`。
   判据看产品模式渲染后的可见文本（`data-spec` 包裹的内容在产品模式不可见，不算违规）。
   规格编号（`FN-xxx / CR-xx / BR-xxx`）同样属于设计阶段解释文字，流程页脚注与规则标签里出现的已全部改写为产品语言；
   核对时须**逐步驱动流程每一步**再取可见文本，只加载首页会漏掉后段步骤。
4. **报告只有一套逐题明细**——练习交卷态、模考交卷态、模考归档回看三处共用 `assets/report.js` 的同一套
   `.rep-*` 渲染与展开交互；归档报告不得只给汇总计数，且必须显式区分「交卷时保存的题目版本」与「题目当前版本」。
   交卷时把 `total` 与 `items` 一并写进报告，归档才有东西可展开。
5. **文字层级六维，不只靠加粗**——页面标题 / 章节标题 / 次级标题 / 正文 / 辅助信息五级，每级在
   字号 × 字重 × 字体 × 颜色 × 行高 × 留白 至少三维不同。衬线只给长文阅读位（页面标题、章节标题、题干、解析、资料正文），
   控件与界面 chrome 用无衬线，等宽只给数字与编号。字号阶梯 v4 整体上移一档
   （辅助 12.5 / 控件与表格 13.5 / 正文 14.5 / 阅读正文 16.5 / 小节标题 18.5 / 题干 21 / 区块标题 25 / 页面标题 30）。
6. **细分隔线承担结构意义**——能靠留白、对齐、字重替代的线一律不加。已删：面板外框、表格外框、
   统计带下边线、通知四边框、报告列表上沿线。保留：页签基线、章节标题下沿线、表头下沿线、列表行间线、列间竖线、列分线。
7. **纸内布局用既定模式**——`.lay-stack` / `.lay-main-side` / `.lay-side-main` / `.lay-two` / `.lay-three` /
   `.lay-four` / `.lay-read` / `.lay-toolbar` 八种，按任务选，不各写网格。不得用统一 CSS 数值代替真正的视觉设计。
8. **桌面与手机各为自己的输入方式设计**——手机不是桌面缩窄：底导五个主入口、移动顶栏不与正文重复标题、
   专用移动列表、筛选用底部弹层、软键盘不遮主操作（`--kb-inset` / `data-kb`）。桌面：快捷键按题型动态适配且不拦截
   系统快捷键与输入法组合、浮层按可用空间展开。平板只做响应式过渡，不建第三套界面。
9. **文案是产品语言**——界面能表达的不重复、短句能表达的不长段、只在要决策时才给规则说明。
   不解释功能为何没做，不暴露规格编号与实现细节。按钮命名、状态名、反馈文案全产品统一。

## 给独立审查者的入口

1. **先读** `CONTRACT.md`（设计契约与九条全局规则）与 `IA-AND-OWNERSHIP.md`（信息架构与 120 条功能项落点表）。
2. **再看** `index.html` 的屏幕索引，按域逐个打开 `pages/screens/*.html`。
3. **重点核对**：
   - 八态是否在真实产品界面中落地（每个屏幕内均实渲染空 / 加载 / 错误 / 禁用 / 无权限 / 冲突 / 未配置 / 离线）；
   - 普通页面纸面规格是否真正统一（同宽、同左边界、同外边距）；
   - 普通成员/普通用户视角下，无关管理入口是否真的不出现；
   - 历史报告（练习与模考）是否给出完整逐题明细，并与交卷当次报告内容一致；
   - 报告是否显式区分「交卷时保存的题目版本」与「题目当前版本」；
   - 标题层级是否只用加粗区分（应六维至少三维不同）；细分隔线是否各有结构理由；
   - 答题 / 下一题 / 解析 / 评级四步是否明显比同屏其他操作成本低；
   - 手机端是否为触屏重新组织（而非桌面缩窄）；快捷键是否与系统快捷键、输入法组合冲突；
   - 产品模式可见文本里是否残留「本期不提供 / 未实现 / FN 编号 / CR 编号 / P3」之类。
4. **跨端判定** 以 768px 为唯一切分点：>768 出侧栏，≤768 侧栏收起、底栏接管，二者永不并存（CR-28）。
