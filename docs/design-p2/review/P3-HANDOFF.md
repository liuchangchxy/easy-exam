# P2 → P3 归属清单

本清单记录本轮已处理、设计已定待接线、以及**尚未解决**的三类边界。判定原则来自用户 brief 第九节：

- **P2 必须修正**：产品设计与 P1 冻结定义的冲突；界面必须表达的状态、操作路径、视觉与交互质量。
- **P3 负责**：把冻结设计完整接线——共享模拟数据、状态持久化、真实可操作的业务流程。
- 纯数据与交互实现缺陷明确留给 P3，**不提前进行全量原型工程化**。

分类口径（收口时新增，避免"归 P2"被读成"已修完"）：

| 类别 | 含义 |
|---|---|
| **A 已完成并验证** | 本轮改完，且在原型的真实数据 / 真实交互路径上验过 |
| **B 设计已完成，具体实现待 P3** | 界面该说的都说了、该给的入口都给了；接线（持久化、真实读写、幂等）归 P3 |
| **C 尚未解决的设计缺陷** | 本轮发现但**没有修**，且不是"实现细节"能一言带过的——需要在 P3 开工前先裁定额 |

## 三、尚未解决的设计缺陷（C 类）

> 这些不是"实现细节"，是**本轮发现但没有修**的问题。每一条都给了代码位置，
> P3 开工前需要先裁定额，否则会以"已经归过类了"的形式被跳过。
> C-2 是同类问题中最容易就地修的一条，第七轮已解决，保留在此作为记录与验收对照。

### C-1 CR-05 的「访问权」这一腿只有注释，没有判定

- 位置：`assets/store.js:192-194`（`bankReachable`）、`assets/store.js:447`（CR-05 注释）
- 事实：注释写的可执行集合是「到期 ∧ 未斩杀 ∧ 题库未归档 ∧ **我对该题库仍有访问权**」，
  但 `bankReachable()` 实际只判了 `!b.archived`。题库对象上明明有 `role: 'OWNER' | 'VIEWER'`
  与 `shared` / `readonly` 字段（store.js:40-44），判定里没用。
- 后果：把 `b_sh`（共享题库 · 只读 VIEWER）的卡片改成到期，`executableReview()` 会把它算进
  可执行集合，侧栏角标、复习页待复习视图、题库页侧栏计数会一起虚高。界面文案说的是四条腿，
  实际只有三条。
- 归属：**C**。修法有两种，需要产品裁定，不能由实现侧默认选一种：
  (a)  VIEWER 的共享题库不进可执行复习集合（共享题库只读，不参与我的调度）；
  (b)  进集合但不能斩杀 / 不能改评级（只读影响的是操作，不是集合）。
- 本轮不修的理由：这是集合口径的产品裁定，不是界面表达问题；且改它会同时改动角标、三个页面
  的计数与 diagnosis 的说明文案，超出本轮收口范围。

### C-2 ~~home.html 与 diagnosis.html 仍在本地重写到期 / 可执行口径~~ — 已在第七轮解决

- 原状：`diagnosis.html:605-625` 自写 `dueTime / isDueNow / bankReachable / executableRows /
  scheduledRows`，注释写着「与复习页同一把尺子」，实际是第二把尺子，store 改了它不会跟着改；
  `home.html` 的七日计划自己解析 `due_at` 分桶，`dueRows()` 还按 `reasons` 里的 `'due'` 标签判到期
  （答完一次评级后 `due_at` 已被推到未来，标签却还留着）。
- 本轮处置：diagnosis 改调 `S.reviewDueAt / S.reviewDue / S.executableReview / S.scheduledReview /
  S.reviewReachable`；home 的 `dueRows()` 改为 `S.executableReview()`，七日计划保留自己的分桶
  （它要的是「按天分组」，不是「哪些可执行」，两者不是同一个问题）。
- 尚未收敛的同类口径（本轮一并修）：`workspace.html` 与 `import.html` 的侧栏角标原用
  `S.reviewQueue().length`，把已斩杀、未到期、归档题库的行都算进「今日待复习」，
  同一标签在题库页显示的数与它们不同。已改为 `S.executableReview().length`。
  基线文件 `banks.html:941` 的注释描述的正是这个 bug。

### C-3 账户切换后个人学习数据不隔离（原 #6）

- 位置：`assets/store.js:223-225`
- 事实：原型只有一份共享 `state`，`login` 只替换 `session.user`；会话、复习队列、错题、报告
  都不按账户过滤。切换账户后看到的是上一个人的学习数据。
- 后果：「同一份数据」的设计承诺在产品里是假的——这一条当初归 P2 的理由（原表第 6 行）
  并没有因为归类而消失。
- 归属：**C**（设计口径已写进注释，界面未表达，实现未做）。P3 接线时随状态拆分一起解决。

## 四、本轮收口新增：深链定位的实测覆盖

#8 的修复不能只靠"加了参数"，跨页定位必须在原型的真实数据上跑通。以下 9 种输入全部实测：

| 输入 | 落到 |
|---|---|
| `?tab=mistakes&stem=<题干>` | 正确行（仅题干，编号对不上时仍成立） |
| `?tab=mistakes&qid=<错编号>&bank=<题库>&stem=<题干>` | 正确行（题干在两套编号之间架桥） |
| `?tab=mistakes&stem=<带折行/全角空格的题干>` | 正确行（`S.normStem` 去空白归一化） |
| `?tab=mistakes&stem=<osi 小写题干>` | 正确行（忽略大小写） |
| `?tab=mistakes&qid=<真题目 id>&bank=<与行不符的题库>` | 正确行（题库范围自动纠正） |
| `?tab=mistakes&qid=<队列行 id>&bank=<题库>` | 正确行（行 id 直跳） |
| `?tab=mistakes&qid=<不存在>&bank=<题库>`（无题干） | 准确提示「这道题当前不在错题里」，不停在列表顶部 |
| `?tab=mistakes&stem=<只在「薄弱」的题干>` | 准确提示「这道题现在不在错题里」+ 一键去「薄弱」 |
| `?tab=mistakes&stem=<已斩杀题干的>` | 准确提示「这道题现在不在错题里」+ 一键去「斩杀」 |

高亮与展开同时验过：目标行有品牌色底 + 2px 描边、滚动进视口、详情抽屉打开。
归一化函数只有一份实现（`store.js` 的 `S.normStem`），报告端与复习端共用——两端各写一份
是这类跨页定位最容易坏的地方。

## 五、本轮主动裁定（不来自原清单，收口时记录）

- **命令面板定位为「快速跳转」**：顶栏搜索实际只索引页面路由。与其留一个暗示能搜题目的输入框，
  不如把占位、aria-label 与页脚写成它在页面间跳转。检索能力不进本期。
- **表格 ≤640 不再机械转卡片**：逐字段竖排在手机上比原表更难扫。改为页面显式选择
  `.dtable-cards`，否则宽表留可发现滚动，由页面为移动端设计专用列表。
  本轮按此处置的三个页面：`exams.html`（8 列，原 375 宽横滚 234px）、
  `diagnosis.html`（7 列，横滚 9px）、`instance.html`（7 列，横滚 198px）。
  其中 `instance.html` 由 JS 从同一张表构建手机专用卡片
  （用户名 → 角色/状态/元信息一行 → 操作 → 锁定原因），桌面仍看表，单一数据源不会分叉。
- **`product.html` 的演示脚手架改用 `data-spec` 包裹**：角色切换、覆盖范围清单、重置数据、
  规范入口属设计阶段工具，产品模式下不出现；`?spec=1` 仍可查看。
- **底部导航五入口，设置进账户菜单**（第六轮做法，**已被第七轮推翻**）：第六轮把设置等低频
  功能从底导主位移到「更多」；第七轮确认「更多」是一颗死按钮，且侧栏在手机端整块隐藏、
  账户菜单里又没有设置，导致设置在手机端实际不可达。现方案：底导保持
  今天 / 题库 / 复习 / 模考 / 资料 五入口，设置作为账户菜单第一项（spec-boot.js），
  同时删掉已失效的 `shell.nav.more` 文案键（i18n.js）。
- **细分隔线按结构意义取舍**：面板与表格外框、统计带下边线、通知四边框、报告列表上沿线属
  重复线条，已删；保留页签基线、章节标题下沿线、表头下沿线、列表行间线、列间竖线、列分线。
- **`.panel.rule-top` 与 `.panel-label` 提升为共享修饰类**：题目编辑、题库工作区、导入向导
  三处原本各自把 `.panel` 覆盖成「仅上沿线」、把 `.panel-title` 覆盖成小号大写眉题——同类不同形，
  且违反「屏幕 `<style>` 里不得再写一遍」的契约。提升后三处重复定义删除，
  `.panel-title` 在全产品恢复一个意思。
- **撤消了自己新加的 `.picker` 可搜索选择器**：构建后发现 `workspace.html` 已有 `.combo`、
  `notes.html` 已有 `.qpick`，且小选项量（题型 6 / 难度 6 / 排序 4）用原生 select 是对的。
  三份实现比两份更糟，故撤消，改为把既有两份的合并记入 §二 第 8 项。
