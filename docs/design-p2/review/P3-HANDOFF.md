# P2 → P3 归属清单

本清单记录「本轮已处理」与「明确留给 P3」的边界。判定原则来自用户 brief 第九节：

- **P2 必须修正**：产品设计与 P1 冻结定义的冲突；界面必须表达的状态、操作路径、视觉与交互质量。
- **P3 负责**：把冻结设计完整接线——共享模拟数据、状态持久化、真实可操作的业务流程。
- 纯数据与交互实现缺陷明确留给 P3，**不提前进行全量原型工程化**。

## 二、本轮明确不做、留 P3 的事项

1. **共享模拟数据源统一**：各页面目前各自内联演示数据。统一成单一数据源属接线工作。
2. **跨页面状态持久化**：设置、角色、会话 currently 走 localStorage 的局部同步；完整的状态机持久化属 P3。
3. **真实可操作的业务流程**：导入真正读文件、题目编辑真正落库、批量操作真正写store——本轮只保证界面与状态表达完整。
4. **滚动恢复的进入路径区分**（#7）。
5. **草稿恢复的幂等保护**（#14 的实现部分）。
6. **题目内容检索**：命令面板本轮定位为页面间快速跳转；题面/解析检索不在本期产品范围。
7. **后端联调**：403 `detail` 的中文可读呈现、保存冲突的服务端判定，本轮只设计界面表达。

## 三、本轮主动裁定（不来自原清单，收口时记录）

- **命令面板定位为「快速跳转」**：顶栏搜索实际只索引页面路由。与其留一个暗示能搜题目的输入框，不如把占位与页脚写成它在页面间跳转。检索能力不进本期。
- **表格 ≤640 不再机械转卡片**：逐字段竖排在手机上比原表更难扫。改为页面显式选择 `.dtable-cards`，否则宽表留可发现滚动，由页面为移动端设计专用列表。
  本轮按此处置的三个页面：`exams.html`（8 列，原 375 宽横滚 234px）、`diagnosis.html`（7 列，横滚 9px）、
  `instance.html`（7 列，横滚 198px）。其中 `instance.html` 由 JS 从同一张表构建手机专用卡片
  （用户名 → 角色/状态/元信息一行 → 操作 → 锁定原因），桌面仍看表，单一数据源不会分叉。
- **`product.html` 的演示脚手架改用 `data-spec` 包裹**：角色切换、覆盖范围清单、重置数据、规范入口属设计阶段工具，产品模式下不出现；`?spec=1` 仍可查看。
- **底部导航收敛为 5 + 「更多」**：设置等低频功能从底导主位移到「更多」，主位移给高频学习入口。
- **细分隔线按结构意义取舍**：面板与表格外框、统计带下边线、通知四边框、报告列表上沿线属重复线条，已删；保留页签基线、章节标题下沿线、表头下沿线、列表行间线、列间竖线、列分线。
- **`.panel.rule-top` 与 `.panel-label` 提升为共享修饰类**：题目编辑、题库工作区、导入向导三处原本各自把
  `.panel` 覆盖成「仅上沿线」、把 `.panel-title` 覆盖成小号大写眉题——同类不同形，且违反「屏幕 `<style>` 里
  不得再写一遍」的契约。提升后三处重复定义删除，`.panel-title` 在全产品恢复一个意思。
- **撤消了自己新加的 `.picker` 可搜索选择器**：构建后发现 `workspace.html` 已有 `.combo`、
  `notes.html` 已有 `.qpick`，且小选项量（题型 6 / 难度 6 / 排序 4）用原生 select 是对的。
  三份实现比两份更糟，故撤消，改为把既有两份的合并记入下方 P3 事项。

## 四、新增：明确留给 P3 的实现层合并

8. **可搜索选择器合并为一份**：`workspace.html` 的 `.combo` 与 `notes.html` 的 `.qpick` 是同一组件的
   两份实现（都能搜、都限量渲染、键盘行为各写一遍）。设计语义已定且都可用，合并属接线重构，归 P3。
   本轮不合并的理由：两份都在工作、都在被各自页面依赖，为合并而合并会在打磨轮引入回归风险。
9. **早期报告分支无逐题明细**：这是 CR-25 的数据来源事实，不是设计缺失。界面已明说「这一场没有逐题明细可回看」，
   汇总计数给当时记录下来的部分，不用演示数据冒充。P3 若补历史数据回算，入口已留好。
