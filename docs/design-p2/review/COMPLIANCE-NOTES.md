# P2 合规核实记录（人工逐条）

静态脚本 `review/staticcheck.py` 的 CR-27 正则对「跳过」一词有误报。
已对全项目每一处「跳过」逐条人工核实，结论如下。

## 两类合法出现

### A. CR-27 的禁令表述（不是违规）
出现在：`index.html`、`pages/states.html`、`pages/screens/banks.html`、
`pages/screens/review.html`、`pages/screens/workspace.html`、`pages/components.html`

原文形态：「**不存在「跳过 Z」这一项**」「清除一切「跳过 Z」残留表述」。
这是把规则写进设计文档，属于要求而非违反。

### B. 导入重复题处理策略（FN-127，另一个域）
出现在：`pages/screens/import.html`、`pages/flows/import.html`、
`pages/components.html`（导入策略下拉的控件示例）

原文形态：重复题处理策略的三个选项 `跳过重复 / 新建为新题 / 合并`，
以及导入作业结果的「跳过（重复）」计数列。

**这不属于 CR-27 管辖范围。** CR-27 管的是「题库 / 题目的批量操作结果」，
即归档、恢复这类动作的成败计数；FN-127 管的是「导入时遇到重复题怎么办」，
是规格明确承诺的去重策略，删掉它等于删减已承诺能力。

### 待办的表述澄清（不改变语义，只消除误读）
导入作业结果的列头由裸「跳过」改为「跳过重复」，作业汇总由「跳过 N」
改为「跳过重复 N」。语义不变，只是让读者不会误以为是 CR-27 的批量结果。
执行时机：题库域代理交付后由主 Agent 统一改（避免与代理写同一文件冲突）。

# 第六轮 · P2「全产品成品级 UI/UX 打磨」

本轮目标：把已有设计从「规范文档感」提升到「可发布成品感」。不重新定风格、不扩产品范围。

## 第 1 层 · 共享设计系统（主 Agent）

### 1.1 字号阶梯 v4：整体上移一档

原 v3 把正文压到 13.5px、按钮与表格 12.5px。长时间读题干、解析、资料时字偏小、层级糊——
这是「整体偏小」的直接来源。v4 各级 +1～3px，并把「辅助信息」与「正文」拉开到可感知差距：

| 层级 | v3 | v4 |
|---|---|---|
| 辅助信息 | 12 | 12.5 |
| 控件 / 表格 / 列表标题 | 12.5 | 13.5 |
| 正文 | 13.5 | 14.5 |
| 阅读性正文 | 15.5 | 16.5 |
| 小节标题 | 17 | 18.5 |
| 题干 / 抽屉标题 | 19 | 21 |
| 区块标题 | 22 | 25 |
| 页面标题 | 26 | 30 |
| 首页大标题 | 32 / 38 | 36 / 44 |

### 1.2 层级改为六维组合，不只靠加粗

原实现里 `.page-title` / `.section-title` / `.panel-title` / `.empty-title` 全是「衬线 + font-weight 500」，
只靠字号与加粗区分。v4：

- `.panel-title` 改为**无衬线 600**（与章节标题的衬线 500 在字体维度分开，字号也差一档）；
- 新增 `.sub-title`（无衬线 600 + 墨色）/ `.sub-note` 作为三级小标题；
- `.list-title` 补 `font-weight: 500` 与行高，列表标题不再与正文同重；
- `.notice-title` 500 → 600；
- 衬线收敛到长文阅读位：页面标题、章节标题、题干、解析、资料正文；控件与界面 chrome 一律无衬线；
- 等宽只给数字与编号（`.stat-num` / `.rep-item-n` / `.timer` / `.plan-index` / `.num`）。

实测（1440 宽，22 个页面）：页面标题 30px 衬线 500、章节标题 18.5px 衬线 500、
面板标题 16.5px 无衬线 600、正文 14.5px——全产品一致，无「同级标题只靠字重区分」的页面。

### 1.3 细分隔线治理：删五类重复线

原实现里一个 `.panel` 就有三道线（外框 + head 下边线 + foot 上边线），`.dtable-wrap` 再套一道，
表格内部还有表头线与行线——一个面板里最多叠五层线。v4 删除：

| 删除 | 理由 |
|---|---|
| `.panel` 四周边框 | head 的下边线已分开标题区与内容区；外框是第二道重复线 |
| `.dtable-wrap` 外框 | 表头下边线才是结构线；去框后表格嵌面板不再「盒子套盒子」 |
| `.stat-row` 下边线 | 上沿重线 + 项间竖线已构成数字带；下边线与下一节留白功能重复 |
| `.notice` 四周边框 | 提示的价值在语义色与文字，不在盒子；只留左侧 3px 语义条 |
| `.rep-list` 上沿线 | 与首项自己的上边线重合；同时补 `:last-child` 去线，末行底下不再有悬空线 |

保留的是真的在分结构的线：页签基线、章节标题下沿线、表头下沿线、列表行间线、列间竖线、列分线。
`.dtable th` 的下边线同时加重为 `--line-strong`，补回去掉外框后损失的表头分量。

### 1.4 控件高度三档 + 主操作唯一

新增 `--ctl-h 36`（按钮 / 输入 / 菜单项）、`--ctl-h-sm 32`、`--ctl-h-lg 42`。
按钮 32→36、小按钮 28→32、图标钮 32→36、菜单项 32→36、分段 24→30、chip 28→32、
底导文字 10.5→12.5、步骤字号与序号圈同步放大。`pointer:coarse` 兜底仍为 44。

新增 `.btn-lg` / `.btn-hero`，并立规「一屏至多一颗主操作」。
实测：home 与 product 各 1 颗，其余页面 0 颗（由各域按高频路径补）。

### 1.5 纸内布局模式八种（§15.0）

统一纸面之外，纸**内部**也要有统一词汇，否则每个页面各写一套网格、页面间节奏就散。
新增 `.lay-stack` / `.lay-stack-sm` / `.lay-main-side`(+`.wide-rail`) / `.lay-side-main` /
`.lay-two` / `.lay-three` / `.lay-four` / `.lay-read` / `.lay-toolbar`，
断点：>1024 多栏、769–1024 主辅栏收单栏、≤768 全部单栏；`.lay-toolbar` 在 ≤640 让主操作独占一行并撑满。

### 1.6 跨端三项修正

- **表格 ≤640 不再机械转卡片**：逐字段 `label:value` 竖排在手机上比原表更难扫。改为页面显式选
  `.dtable-cards`，否则宽表留可发现滚动，由页面为移动端设计专用列表。
- **底部操作条不再折成多行**：`.flow-foot` 手机端注记收上一行、操作区固定一行、主操作撑满；
  但操作多于两颗时允许换行，否则第三颗被挤出屏幕（product 入口行实测 375 宽溢出 32px，已修）。
- **`--kb-inset` 有更新机制了**：原来只有声明没有写入方，软键盘弹出后底部操作条仍贴在会被遮住的
  位置。改为 spec-boot.js 用 `visualViewport` 的视口差实时写入，同时给 `<html>` 打 `data-kb`；
  页面用 `.kb-hide`（收起）/ `.kb-shrink`（收缩）响应。地址栏收缩一类 <40px 的抖动不算键盘。

### 1.7 菜单按可用空间展开

## 1. `report.js` 的 `normStem` 未定义（阻塞级）

`itemHtml` 里写了 `stem=' + encodeURIComponent(normStem(it.stem))`，但 `normStem`
在文件里没有定义——任何渲染出带「在错题里打开」的报告都会在这里抛
`ReferenceError`，整块逐题明细随之空白。这不是"差一个函数"，是报告链路断在半路。

修法不是就地补一份实现。报告端与复习端必须用**同一个**归一化函数，两端各写一份是这类
跨页定位最容易坏的地方；而两个文件唯一的共同依赖是 `store.js`，所以：

- `store.js` 新增 `S.normStem(s)`：去全部空白 + 忽略大小写。**不动标点与用词**——
  那会让「哪项不属于」和「哪项属于」撞成同一题。
- `report.js` 改为调用 `window.eeStore.normStem`；`store.js` 缺失时退化成只带
  `qid + bank`（定位能力降级但不报错）。
- `review.html` 的比对同样走 `S.normStem`。

## 2. 对象级定位补上第三重依据（题干架桥）

原契约只有 `?tab=mistakes&qid=<qid>&bank=<bankId>`。问题在于**报告里的题目 id 与复习
队列的行 id 是两套编号**：报告存的是交卷当时的题目快照 id，复习队列有自己的行 id，
两者没有必然关系。只带 `qid` 时，编号对不上就静默退化成"跳到错题列表页顶部"——
正是要消除的行为。

- `rowForQid(qid, bank, stem)` 增加题干兜底：行 id → 题目 id 按题干找回 → 深链自带的
  题干按归一化找回；先题库内、后全局，避免不同题库题干恰好相同而定位错行。
- 队列里有这道题、但不在「错题」视图时（在「薄弱」或「斩杀」），原来**静默返回**，
  用户被丢在列表顶部。改为准确说明它现在在哪，并给一个直达按钮。
- 归一化跨端验过：折行、全角空格、英文大小写差异都不影响落到同一行。
