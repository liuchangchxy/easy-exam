03 / EasyExam UI/UX 设计规范

状态与外壳

八种状态是全产品统一契约：任何屏幕不得只设计「正常那一档」。搜索与跳转面板、快捷键、同步态、URL 状态契约与跨端断点同属全局外壳，由本页定义，各屏直接引用。

01八态矩阵

每个屏幕都必须显式设计下面八种状态，并用同一屏内的不同面板并列呈现。空态必须说明为什么空并给出下一步动作；禁用必须给出可读原因，但只适用于与当前用户相关的控件；完全无关的管理入口不出现；未配置与离线不是错误，是正常的产品状态，要有自己的表达。

03全局快捷键（FN-612）

快捷键只覆盖两类：跨页导航与 runner 内的作答操作。快捷键覆盖的页面入口都能在搜索与跳转面板里用文字搜到，不强迫记忆。

快捷键不得拦截正常输入：焦点在输入框 / 文本域 / 可编辑元素里时，字符类快捷键一律不触发（输入法组合输入同样不触发）；带 Ctrl/⌘ 的组合键让给系统与浏览器。快捷键按题型动态适配——单选题按 A–E 选对应选项，多选题同键切换选中，判断题按 T/F，填空题聚焦输入框时不拦字符键，主观题不启用字符类快捷键。不为了增加高级感堆砌低价值快捷键：帮不上高频路径的一律不加。

宽限期（CR-31）——不是失败

作答窗口已结束，宽限 60 秒

你的答卷已在本地封存，正在等服务端收卷。这 60 秒里网络恢复就会自动补交；超时则由服务端按已封存内容收卷。不会判定你缺考。

「作答窗口结束」不是会话终止。宽限期内界面必须是正常状态（info 级），不能变红、不能报错。只有服务端明确收卷失败才进入错误态，并给出重交入口。

05URL 状态契约与可深链（FN-614）

能被分享、被刷新、被记住的状态必须进 URL。同一语义只允许一种 URL 写法，别名与重复参数一律禁止——否则 P3 会出现两个入口指向同一屏却行为不同。

06跨端断点与软键盘 / 安全区（FN-615）

三档共享同一套 DOM 与同一套语义，只改布局与交互方式，不做机械缩放。判断标准是「这只手现在能做什么」，不是「这块屏有多宽」。

四档断点：1440 / 1024 / 768 / 375

641–768 小平板 侧栏隐藏，底部导航 5 项 单列；表格转卡片（td[data-label]） 触屏 + 拇指可达区优先；底部固定操作区
≤640 手机 侧栏隐藏，底部导航 5 项 + 移动顶栏 单列；长文限宽 .measure 68ch 单手拇指；触摸目标 ≥44px；表单避免被软键盘遮

断点取 768，这是唯一判据。70 册 §6 的跨端行为表把 641–1024 整段归为平板（侧栏图标轨、底部导航不显示），而 CR-28 规定「底部导航与侧栏不得并存」。两处对 641–768 给出相反答案，本设计以侧栏是否可见为唯一判据：>768 侧栏可见（>1024 完整 / 769–768 图标轨），≤768 侧栏隐藏并由底部导航接管。实现见 ee.css（max-width:768 隐藏侧栏、min-width:769 隐藏底栏），文档以它为准。

移动端专项（不为桌面视觉牺牲移动可用性）

单手操作与触摸目标

主要操作落在屏幕下半部的拇指弧内：底部导航、底部固定操作条、抽屉从底部弹出。次级操作（返回、更多）在顶部，但都不应是完成任务的唯一路径。

任何可点元素不小于 44×44（.od-touch）；列表行的整行可点，不只点标题。

作答卡与答题卡

手机端答题卡是从底部拉出的抽屉，不是右侧常驻栏——常驻栏会把题干挤到一行三个字。格子在抽屉里保持 5 列，已答/当前/待复查三种态用形状 + 颜色双编码，不只靠颜色。

表单与软键盘

软键盘弹出时，页面滚动到当前输入框，提交按钮跟随键盘上浮。占位高度由 assets/spec-boot.js 用 visualViewport 实时写进 --kb-inset（键盘收起归零，地址栏收缩一类的小抖动不算键盘），底部操作条的 bottom 直接吃这个变量；需要收起的次要区域加 .kb-hide，需要收缩的加 .kb-shrink。不在软键盘上方再放一层浮层。

对话框 / 抽屉 / 长文

手机端对话框改为底部抽屉式，标题与关闭在顶部，主操作在底部；长文（解析、资料）限宽 68ch 并保留纸面底色，不用纯白背景。

固定操作区 vs 页面滚动

只有「当前这一步的主操作」固定在底部（提交答案、交卷、保存），且固定区不超过一个按钮组。页面内容在固定区下方滚动，不被遮挡（.has-bottomnav 已处理）。

安全区

底部导航与固定操作条用 env(safe-area-inset-bottom) 留出主屏幕指示条的空间；顶部用 viewport-fit=cover 处理刘海。横屏时底部导航保持可见，不因键盘高度抖动。

07全屏 runner 外壳与退出确认（FN-616）

练习与考试是全产品唯一进入全屏的场景。全屏的意义是排除导航干扰，所以 runner 内不出现一级导航，只保留退出、进度与交卷。退出必须确认，并且要说清楚「退出了会怎样」。

练习 · 退出确认

「退出后这组的作答会存成草稿，你可以从今天页继续。已提交的评级不会撤回。」两个按钮：继续练习（主）/ 退出并存草稿（quiet）。

考试 · 退出确认

danger 对话框。「现在退出会暂存草稿，你可以在宽限期内从同一台或另一台设备续考。超过宽限期服务端将按已暂存内容收卷。」确认按钮写「退出并暂存」，不写「确定」。

runner 内不允许出现的东西

一级导航、面包屑跳转、设置入口、与当前题无关的推荐。它们全部收进退出后的正常外壳。

实现约定：runner 的退出按钮统一加 data-act="exit-task"；页面自己的确认对话框用 data-exit-dialog="<dlg-id>"，没有页面对话框时用 data-exit-kind + data-exit-to 走统一确认框。视觉上它仍是左箭头 +「退出」，但语义与「返回父页面」分开。

08可供性矩阵与四态

一个区域看起来能不能点，必须和它实际能不能点一致。全产品只有四种可供性：可点、只读、禁用、纯展示；视觉、DOM 语义与行为三者必须同时成立，不能只靠颜色或 hover 暗示。

可供性矩阵：四种区域各用什么表达
可供性视觉DOM 约定行为禁止
可点 有 hover 背景、有焦点环；行尾可用箭头表示「有默认动作」 <button> / <a>；整行可点用 data-row-href + role="link" + tabindex="0" 点击 / Enter / Space 执行默认动作 用 <div onclick> 冒充按钮；箭头不在链接里

禁用 置灰；原因常驻可见（行内说明或 aria-describedby 指向的说明），不能只在 hover 里 原生 disabled，或 aria-disabled="true" + data-disabled-reason / aria-describedby 不可执行；点击或聚焦时给出可读原因（toast） 隐藏入口；禁用而不说为什么；只写 title

09导航语义：返回 / 切换 / 退出

三类动作在视觉、文案与 aria-label 上必须分开。用户看到「退出」时，预期是「结束当前任务并确认后果」，不是「回到上一页」；看到「返回」时，预期是「回到父页面」，不是「放弃当前作答」。

返回父页面 沿层级回到上一级（面包屑 / 返回箭头） 左箭头 + 父级名称；无危险色 <a class="page-back" href="…"> + data-nav-kind="back-parent" 返回题库列表 / 返回今天
切换一级页面 在五个主入口之间切换（侧栏 / 底导） 导航项；当前项 is-active + aria-current="page" data-act="nav" + data-route；真实链接 沿用可见标签（今天 / 题库 / 复习 / 模考 / 资料）
退出当前任务 结束练习 / 模考 / 导入，必须确认并说明后果 左箭头 + 「退出」；不写「返回」；点击后先出确认对话框 data-act="exit-task"；可带 data-exit-dialog 或 data-exit-kind + data-exit-to 退出当前任务 / 退出练习 / 退出这场模考
返回父页面（真实链接） 返回题库列表
切换一级页面（真实链接） 复习
退出当前任务（先确认）

退出必须确认：练习写「暂存并退出 / 结束本次」，模考写「退出（暂存）/ 放弃」，导入写「稍后继续（存草稿离开）/ 放弃并离开」。确认按钮写清后果，不写「确定」。runner 内 Esc 只打开退出确认，不直接退出。

不混淆：从列表进入详情再返回，用「返回」；离开当前任务用「退出」。同一个「退出」文案不得既表示返回父页面又表示结束任务；页面不得用 <a href> 直接离开 runner 而不确认。
