# 50 · 资料与设置域

> 本册是 EasyExam 产品定义的资料与设置域分册。权威引用：SPEC.md §2.2 / §2.3 / §2.4 / §6 / §8；UX_CORE_REDESIGN §5.3 / §7.9 / §13.1 / §14.3 / §14.4。
> 编号段：FN-5xx / BR-5xx / OP-5xx / ST-5xx / PR-5xx / GAP-5xx / Q-5xx
>
> **边界**：本册负责「资料」（笔记 / AI 总结 / 口诀 / 上传文件）与「设置」（外观、语言、AI 与联网检索、账户、关于），以及以题目为上下文嵌入的 AI 解释与联网核查能力。刷题、判分、FSRS、斩杀属于 20 册；题库、题目版本、标签章节属于 10 册；实例账号与注册开关属于 40 册；导航、命令面板、快捷键属于 60 册。
>
> **本册的前提**（不重复论证，只作引用）：AI 是可选横向能力，没有 AI 时核心功能完整可用（SPEC §2.3 / §2.4，00 册 P-8）；资料是题目与知识点的辅助材料，不生成独立 FSRS 任务，不改变刷题主线（SPEC §2.3 末条）；标准答案与解释分离，解释版本不可覆盖（SPEC §2.2）。

## 1. 域定位与边界

### 1.1 这个域回答什么问题

| 问题 | 归属 |
|---|---|
| 我把笔记、总结、口诀、PDF 放在哪，怎么找回来 | FN-501 ~ FN-504 |
| AI 怎么帮我理解一道题，生成的解释归谁、能不能改、能不能留底 | FN-505 ~ FN-507 |
| AI 说的依据是真的吗，怎么核查，核查不到怎么办 | FN-506 |
| AI 帮我出的变式题怎么变成正式题 | FN-508 |
| AI 用哪个模型、联网用哪个搜索服务，密钥存在哪 | FN-510 |
| 界面长什么样（明暗/配色/密度）、什么语言 | FN-511 ~ FN-514 |
| 我是谁、我在哪些设备上登录着 | FN-515 |
| 没有 AI 时上面这些变成什么 | FN-518 |

### 1.2 明确的非目标

- 不做无题目上下文的独立聊天主入口（SPEC §2.0 / §2.3；00 册模块树）。AI 解释与追问都以「当前题目 + 当前题目版本」为上下文。
- 不把 AI 生成的解释当作标准答案；AI、联网、用户解释都不能改写标准答案（SPEC §2.3）。
- 不把 AI 资产（总结 / 口诀 / 笔记）做成独立背卡产品或独立 FSRS 队列（SPEC §7；00 册非目标）。
- 不要求配置 AI、联网或资料后才能使用题库导入、刷题、模考、错题、趋势、计划、FSRS、斩杀（SPEC §2.4；00 册 P-8）。
- 本期不做视觉设计；本册只定义「设置项的实际作用范围、是否持久化、是否即时生效、是否需要重启」（00 册 P-3）。

### 1.3 与相邻域的接口

| 相邻域 | 本册给出 | 本册消费 |
|---|---|---|
| 10 题库域 | 资料可关联到题目与知识点标签；AI 变式题草稿转正写入目标题库；题库角色决定能否转正 | 题库列表（关联选择器）、知识点标签列表、题目版本 ID |
| 20 学习域 | 资料按需在复习时展示，不产生调度 | 题目上下文（题干/选项/标准答案/官方解析/错因）用于构造 AI Prompt |
| 30 模考域 | 无（模考不开放 AI） | — |
| 40 协作与实例域 | 实例管理入口、账户与设备会话 | 实例角色（决定「谁配置」分层）、实例级 AI/检索环境配置 |
| 60 全局外壳域 | 设置分区的 URL 契约（`?section=`）、主题/语言的全局生效机制 | 外壳主题/语言写回、命令面板入口 |

## 2. 功能定义

### FN-501 资料库

- **存在目的与场景**：用户把自己积累的笔记、错题小结、知识口诀和上传的参考资料集中在一处，刷题和复习时能按类型、按关键词找回来。真实使用画像中资料页为 0 条（UX §3），因此本功能必须是「低门槛、可空着」的状态，而不是占据主航道的管理台（00 册 P-1 / P-5）。
- **入口与适用条件**：一级导航「资料」（侧栏与移动端底栏均有，`00 册 §4.2`）。任何已登录用户可进入；无需 AI、无需题库权限。题库成员（只读）同样可进入，个人资料与题库权限无关。
- **可执行操作**：
  1. 查看资料列表（按更新时间倒序）。
  2. 按类型筛选：全部 / 笔记 / 错题小结 / 知识口诀（`OP-501`）。**「文件」不是独立类型**——上传的文件以上述三种类型之一存在，在阅读器内可预览/下载（见 `BR-503`）。
  3. 关键词搜索（匹配正文与文件名）。
  4. 收藏 / 取消收藏（行内星标）。
  5. 点击列表行展开阅读器；阅读器内编辑、保存、删除、预览与下载原始文件。
  6. 通过链接带 `?type=` 与 `?q=` 进入时恢复同一筛选与搜索词（`OP-502`）。
- **操作结果**（含数据与状态变化）：
  - 列表数据来自 `GET /api/v1/assets`（当前实现为当前用户全量返回，见 `GAP-513`）。
  - 筛选与搜索是纯前端计算 + URL 双向同步；不产生服务端写操作。
  - 收藏在理想态写入 `personal_assets` 的收藏字段并即时反映在行内星标与「收藏」筛选；当前实现无此字段（`GAP-507`）。
  - 阅读器展开：桌面为右侧常驻抽屉（列表仍可点选切换），≤768px 为全屏抽屉 + 遮罩；展开后页头与列表让出抽屉宽度。
- **与其他功能的关系**：资料是 FN-505（AI 解释）的检索源；是 FN-508（变式题）的上下文来源之一；与 20 册复习的关系是「复习时按需展示」，不进入调度。
- **当前缺失与不合理之处**：
  - ① 无标题字段，列表标题由正文前 56 字截断生成（`frontend/src/views/NotesView.vue:537-541`），长笔记在列表里不可辨认。
  - ① 无收藏字段（`backend/app/infrastructure/db/connection.py:209-218`），原型已有收藏星标与「已收藏」标签（原型 `pages/screens/notes.html:587, 590`）。
  - ① 无所属题库字段，原型阅读器有「在题库里打开」（原型 `notes.html:269-275`）。
  - ① 全量拉取 + 前端过滤，无分页（`backend/app/infrastructure/db/repositories/asset_repository.py:72-80`）。
  - ① 删除仍用原生 `window.confirm`（`NotesView.vue:519-520`；UX §14.3 明确列为残留）。
  - ① 上传不能选类型，沿用「新建笔记」对话框残留的 `newAssetType`（`NotesView.vue:407-415, 436-451`）。
- **理想完成态**：资料有「标题 / 类型 / 正文 / 收藏 / 所属题库（可选）/ 关联题目（可选）/ 关联知识点（可选）/ 原始文件」九个属性；列表一行一条，行内只有星标与展开；筛选、搜索、收藏进 URL；空态给两个动作（新建第一条笔记、上传文件）；搜索无结果时给「清除搜索」而不是空白。

### FN-502 资料创建与编辑

- **存在目的与场景**：把一条要点、一个易错处、一段口诀快速记下来，归入某一类型，之后在阅读器里改。
- **入口与适用条件**：资料库页头「新建笔记」；空态「新建第一条笔记」。无需任何配置。
- **可执行操作**：选类型（笔记 / 错题小结 / 知识口诀）→ 填标题与正文 → 保存；在阅读器点「编辑」→ 改正文 → 「保存」或「取消」；关闭阅读器或切换资料时有未保存修改则先询问（保存并继续 / 放弃 / 取消）。
- **操作结果**：`POST /api/v1/assets`（`backend/app/api/routes/assets.py:22-27`）创建；`PUT /api/v1/assets/{id}`（同文件 `:79-86`）更新。正文 trim 后为空返回 422（`backend/app/application/asset_service.py:28-29, 51-53`）。保存成功后列表与阅读器同步刷新，并给出「已保存」反馈。
- **与其他功能的关系**：创建后的资料立即成为 FN-505 的潜在检索源；类型决定它归入哪个筛选（`OP-501`）。
- **当前缺失与不合理之处**：
  - ① 无标题输入，标题靠正文截断（同 FN-501）。
  - ① 保存成功后走 `showNotice` 页内提示，而设置等同类瞬态成功已走全局 toast（UX §13.1 / §14.1），反馈通道不统一（`NotesView.vue:475`）。
  - ① 未保存对话框内「保存并继续」失败时只在对话框内显示一行错误，且错误文案复用 `ep.library.saving`（`NotesView.vue:340-348, 144`）。
- **理想完成态**：标题必填（为空时行内报错且不关闭对话框）、正文必填；类型三选一；保存走全局 toast；未保存守卫的三选一都可用且「保存并继续」失败时明确说「保存失败：原因」并留在对话框。

### FN-503 资料上传与本地资料检索

- **存在目的与场景**：把外部的 PDF / Markdown / 纯文本资料收进来，既保留原文件可预览下载，又提取文本供 AI 检索引用（SPEC §2.3「可选本地资料检索首期支持 PDF、文本/Markdown 和题库解析」）。
- **入口与适用条件**：资料库页头「上传」。无需 AI。检索（被 AI 引用）需要 AI 已配置；未配置时上传与预览下载照常可用。
- **可执行操作**：选择 `.txt` / `.md` / `.pdf` 单个文件 → 上传 → 成功后出现在列表；阅读器内「预览文件」（新标签 inline 打开）与「下载文件」（attachment 下载，保留原文件名）。
- **操作结果**：
  - `POST /api/v1/assets/upload`（`backend/app/api/routes/assets.py:30-50`）→ `AssetService.create_from_file`（`backend/app/application/asset_service.py:86-157`）。
  - 文本类按 UTF-8 解码，空内容 / 非 UTF-8 直接 422；PDF 用 pypdf 抽取全文，损坏 / 纯图片 / 扫描版直接 422 且**不自动 OCR**（SPEC §5 同规则）。
  - 原文件落盘到 `asset_files/<uuid>.<ext>`，路径做目录穿越防护（`asset_service.py:159-167`）；数据库只存 `file_name / mime_type / storage_key`。
  - 删除资料时同步删除落盘文件（`asset_service.py:61-68, 169-176`）。
- **与其他功能的关系**：上传成功即产生一条 `content` 为提取文本的资料，是 FN-505 的检索源；原始文件只服务于人的预览与下载。
- **当前缺失与不合理之处**：
  - ① 上传时不能选类型（`GAP-508`）。
  - ① 无文件大小上限，且 `await file.read()` 整体读入内存（`backend/app/api/routes/assets.py:39`；`asset_service.py:95`）。
  - ① 预览用 `window.open` + Blob URL，被浏览器拦截时降级为再 `window.open` 一次，用户可能看到两个空白标签（`NotesView.vue:485-499`）。
  - ② 原型提示「单个文件上限由实例设置决定」，但不存在该实例设置（原型 `notes.html:209`）。
- **理想完成态**：上传对话框先选类型再选文件；上传中禁用上传按钮并显示进度文案；超限 / 格式不符 / 抽取失败都在对话框内给出可读原因与「重试」；预览失败时关闭预开标签并在阅读器内给「重试」。

### FN-504 资料关联（题目 / 知识点）与 AI 引用可追溯

- **存在目的与场景**：让「这道题该参考哪几份资料」是显式的，而不是靠正文里碰巧出现标签名。SPEC §2.3 要求「所有资料和网页依据必须可追溯」。
- **入口与适用条件**：资料创建 / 编辑时可关联到题目与知识点标签；AI 生成的解释下展示本次引用了哪些资料。关联是可选操作，不关联不影响任何主流程。
- **可执行操作**：关联 / 取消关联题目；关联 / 取消关联知识点标签；在 AI 解释版本下查看「本次引用的资料」列表并可跳转到该资料。
- **操作结果**：`personal_assets.question_id / knowledge_tag_id` 写入；AI 生成时 `_inject_assets_context` 返回 `referenced_assets` ID 列表（`backend/app/application/ai_tutor_service.py:128-149, 175-176, 247`）。
- **与其他功能的关系**：是 FN-505 的输入；关联到知识点时与 10 册标签体系同源。
- **当前缺失与不合理之处**：
  - ① 前端 `uploadAssetFile` / `createAsset` 都支持 `question_id / knowledge_tag_id`，但界面从不传（`frontend/src/api/assets.js:7-21`；`NotesView.vue:422-425, 442`）——API 有能力、UI 没有入口。
  - ① 检索只按 `question_id = ?` 或 `content LIKE %标签名%`，**完全不使用 `knowledge_tag_id`**（`backend/app/infrastructure/db/repositories/asset_repository.py:82-101`）：显式关联到标签的资料，只有在该标签名恰好出现在正文里时才被检索到。
  - ① `referenced_assets` 返回但界面不渲染（`frontend/src/views/PracticeViewV1.vue:420-453` 无任何引用展示），「依据可追溯」只兑现了一半。
  - ① 检索固定 `LIMIT 5` 且按 `created_at DESC`，无相关度排序（`asset_repository.py:99`）。
- **理想完成态**：资料可显式关联题目与知识点；AI 检索按「题目直连 → 题目标签直连 → 题库解析」顺序取用并限制条数；每次 AI 解释版本下方列出本次引用的资料标题，点击可跳转；没有可用资料时明说「未使用个人资料」。

### FN-505 AI 解释

- **存在目的与场景**：在做题过程中对当前这道题生成讲解、重新生成、继续追问，并把每一版都留档。AI 是可选能力：未配置时入口仍在，但给出可读原因且不产生垃圾数据（SPEC §2.3 / §2.4）。
- **入口与适用条件**：
  - 练习页反馈区「AI 解释」入口（当前实现见「缺失」：只在提交作答后出现）。
  - 理想态：练习页（含未作答时）与题目页都有入口；模考页不开放（交卷前不得泄露对错，SPEC §3.2）。
  - 需要登录；不需要题库编辑权（用户解释私有，SPEC §2.1）。
- **可执行操作**：
  1. 生成解释（带可选提问）。
  2. 重新生成（再产生一版，不覆盖旧版）。
  3. 追问（多轮，绑定同一题目版本的活跃会话）。
  4. 编辑任一 AI / 联网版本并「另存为用户解释」。
  5. 采纳某一版为当前主解释（`FN-507`）。
- **操作结果**（含数据与状态变化）：
  - 每次生成写入一条 `explanation_versions`（`source='AI'`，`question_version_id` 绑定当前题目版本，`is_candidate=1`）（`backend/app/infrastructure/db/repositories/ai_answer_repository.py:11-20`）。
  - 追问写入 `ai_messages`（user + assistant 两条，`sequence` 单调递增，`parent_message_id` 形成分支）（`backend/app/infrastructure/db/repositories/ai_conversation_repository.py:84-131`）。
  - 「另存为用户解释」写入**新的** `source='PERSONAL'` 版本，原版本一字不改（`backend/app/api/routes/ai.py:96-103`；`ai_tutor_service.py:151-157`）。
  - 页面按 `created_at DESC` 展示全部版本，标记来源与时间； adopted 版本打「已采纳」。
- **与其他功能的关系**：消费 FN-501 ~ FN-504 的资料作为上下文；产出供 FN-507 选择；供 20 册在复习时按需展示。
- **当前缺失与不合理之处**：
  - ① **P0**：AI 未配置时 `chat_complete` 返回离线兜底文案（`backend/legacy/services/ai_service.py:15-18`），而 `generate_answer` 不检查该文案，直接落库为一条 `source='AI'` 的解释版本（`ai_tutor_service.py:173-174`）；`send_chat_message` 同样把兜底文案存成 assistant 消息（同文件 `:237-246`）。变式题路径有检查（`ai_tutor_service.py:318-320`），解释路径没有——结果是「点一次 AI 解释，永久多一条垃圾版本，且能被采纳为主解释」。
  - ① `is_configured()` 只要 `base_url` 非空就为真，而 `base_url` 永远有默认值（`ai_service.py:155-160`），所以「未配置」在 provider 层永远不成立，只能靠连接失败兜底。
  - ① 入口被 `v-if="result"` 包着，未作答时不可调用（`frontend/src/views/PracticeViewV1.vue:354, 386-392`），与 SPEC §2.3「做对、做错和未作答的题都可以调用 AI」不符；题目页（`frontend/src/views/QuestionPageView.vue`）完全没有 AI 入口。
  - ① 官方解析不是 `explanation_versions` 行（`source` CHECK 允许 `OFFICIAL` 但无任何写入路径，`backend/app/infrastructure/db/connection.py:148-160`），所以「官方 / AI / 联网 / 用户四类同列、可选主解释」缺一类。
  - ① 生成失败时前端用 `alert()` 弹原生对话框（`PracticeViewV1.vue:1553`）。
  - ① 重新生成没有「重试」语义区分：失败与成功都往列表头插一项或显示一行提示，用户看不出哪次失败。
- **理想完成态**：入口在未作答时也可用；未配置 AI 时点击后明确提示「AI 尚未配置，去设置」且**不写入任何版本**；生成中按钮禁用并显示「生成中」；失败在面板内给出原因与「重试」；版本列表稳定显示来源（官方 / AI / 联网 / 个人）、时间、提供方、是否已采纳；编辑另存永远新起一版；追问记录可在同一题目下回看。

### FN-506 联网核查

- **存在目的与场景**：对当前题目的解释补充外部证据。核查必须新增解释版本，不能覆盖原回答；未配置搜索服务时保存 `UNAVAILABLE` 与空证据，不得伪造网页来源（SPEC §2.3 / §5）。
- **入口与适用条件**：练习页 AI 面板「联网核查」。需要登录；不需要题库编辑权。搜索服务可在 FN-510 配置，也可完全关闭。
- **可执行操作**：对当前题目发起联网核查；展开某一 WEB 版本下的证据列表（标题 / 摘要 / 链接 / 检索时间）。
- **操作结果**：
  - `POST /api/v1/questions/{id}/verify-web`（`backend/app/api/routes/ai.py:121-127`）→ `request_web_verification`（`ai_tutor_service.py:178-191`）。

## 4. 数据关系与状态变化

### 4.1 资料实体族

```text
users ──< personal_assets >── questions            (question_id，可选，ON DELETE CASCADE)
   │                    └──── knowledge_tags        (knowledge_tag_id，可选，ON DELETE CASCADE)
   │
   └── 落盘文件：<DATA_DIR>/asset_files/<uuid>.<ext>（DB 只存 file_name / mime_type / storage_key）
```

- 列集合（`backend/app/infrastructure/db/connection.py:209-218` + 迁移 18 追加 `file_name/mime_type/storage_key`，`:385-387`）：`id, user_id, question_id, knowledge_tag_id, asset_type, content, created_at, updated_at, file_name, mime_type, storage_key`。
- **缺**：标题、收藏、所属题库、体积上限。因此 FN-501 的「标题」只能由正文截断，收藏只能在客户端内存里（原型做法）。
- 删除路径：`AssetService.delete` 先读后删，删行成功再删文件；文件删除失败不影响行删除结果（`asset_service.py:61-68`）。
- 检索路径（`asset_repository.py:82-101`）：`user_id = ? AND (question_id = ? OR content LIKE %tag%)`，`ORDER BY created_at DESC LIMIT 5`。**不使用 `knowledge_tag_id`**。

### 4.2 解释版本族

```text
users ──< explanation_versions >── question_versions      (question_version_id，ON DELETE RESTRICT)
   │                        └──── explanation_evidence    (explanation_id，ON DELETE CASCADE)
   │                        └──── parent_version_id → 自身
   └──< ai_conversations >── ai_messages                  (question_version_id，ON DELETE RESTRICT)
```

- `explanation_versions`（`connection.py:148-160`）：`source CHECK IN ('OFFICIAL','AI','WEB','PERSONAL')`、`is_candidate DEFAULT 1`、`is_adopted DEFAULT 0`、`parent_version_id`、索引 `(user_id, question_id, created_at)`。
- `explanation_evidence`：`title / url / summary / retrieved_at`，无「检索是否成功」列——成功与否只能从所属版本推断，而版本本身没有状态列（`GAP-503`）。
- `ai_messages`：`UNIQUE(conversation_id, sequence)`，`message_status CHECK IN ('sending','success','error')`——`error` 状态在现有写入路径中从未使用（追问失败时前端只显示一行提示，不落 error 消息）。
- 状态流转：`is_candidate=1`（新建）→ `is_adopted=1, is_candidate=0`（采纳，同题旧 adopted 全部归 0）。**没有「已删除」状态**：解释版本不可删（SPEC §2.1「历史版本默认永久保留，只能由用户主动删除」——用户解释的主动删除本期未定义）。

### 4.3 AI 配置与密钥生命周期

```text
users ── user_ai_configs (user_id PK，一行七列)
           ai_provider / ai_api_base / ai_model / ai_api_key
           search_provider / search_api_key / search_api_base
实例级：环境变量 LLM_BASE_URL / LLM_API_KEY / LLM_MODEL
        WEB_SEARCH_PROVIDER / OPEN_WEBSEARCH_URL
        EASYEXAM_SECRET_KEY（Fernet 种子，DATA_DIR/.env 为持久来源）
```

密钥生命周期：

| 阶段 | 行为 | 证据 |
|---|---|---|
| 写入 | `encrypt_secret()` → `enc:<fernet token>`；空值存 `''`；掩码值跳过不写 | `ai_config_repository.py:55-62, 226-230` |
| 种子缺失 | `_get_fernet()` 抛 `RuntimeError`，拒绝加解密 | `ai_config_repository.py:47-53` |
| 读取（脱敏） | `decrypt` → `mask_secret()` → `前3 + ****** + 后4`（≤8 位全掩码） | `ai_config_repository.py:80-85, 154-159` |
| 读取（原始） | `get_raw_config()` 返回解密明文，仅供 provider 与测试探针使用，**不出 API** | `ai_config_repository.py:162-180` |
| 历史明文升级 | 读取时检测非 `enc:` 前缀即原地升级为密文 | `ai_config_repository.py:130-141` |
| 密钥不匹配 | `InvalidToken` → `ValueError` 带诊断信息，不静默置空 | `ai_config_repository.py:74-77` |
| 退役键清理 | 启动时删除旧自定义强调色存储键 | `themePreference.py:212-218` |

配置分层语义：`get_config()` 在用户行存在时对空列填「文档默认值」用于展示，`is_configured` 由密钥或 `localhost` 判定；`get_raw_config()` 返回**用户真实保存值**（空列就是空），provider 与探针在其上用环境默认补齐。这正是「默认值不被自定义值覆盖」的机制，但界面无法呈现第三态「正在使用实例默认值」。

### 4.5 状态定义（ST-5xx）

| 编号 | 对象 | 状态 | 进入条件 / 退出条件 |
|---|---|---|---|
| ST-501 | 资料 | `正常` / `上传中` / `删除确认中` | 创建或上传成功即 `正常`；上传请求在途即 `上传中`（按钮禁用）；点删除即 `删除确认中`（取消回 `正常`，确认后实体消失） |
| ST-502 | 资料阅读器 | `收起` / `展开` / `编辑中` / `有未保存修改` | 默认 `收起`；点行 → `展开`；点编辑 → `编辑中`；`编辑中` 且正文与原值不同 → `有未保存修改`（关闭 / 切换触发守卫） |
| ST-503 | 解释版本 | `候选` / `已采纳` | 新建一律 `候选`（`is_candidate=1`）；采纳后 `已采纳`（`is_adopted=1, is_candidate=0`），同题旧 `已采纳` 回落 `候选`。**无删除态**：历史版本永久保留 |
| ST-504 | 联网状态 | `VERIFIED` / `UNAVAILABLE` / `FAILED` | 取到 ≥1 条证据 → `VERIFIED`；搜索服务未配置或离线 → `UNAVAILABLE`（空证据）；探测到服务但调用异常 → `FAILED`。理想态三者都落库（`GAP-503`） |
| ST-505 | AI 配置 | `未配置` / `继承实例默认` / `已配置` | 无用户行 → `未配置`（`is_configured=false`）；有用户行但密钥为空且 base 不含 localhost → `未配置`；有用户行且填了非密钥字段 → `继承实例默认`（界面需可辨，`Q-501`）；有密钥或 base 含 localhost → `已配置` |
| ST-506 | 联网检索开关 | `联网` / `离线` | `search_provider='open-webSearch'` → `联网`；`='offline'` → `离线`（接口与密钥字段隐藏，核查直接返回 UNAVAILABLE） |
| ST-507 | 变式题草稿 | `DRAFT` / `ACCEPTED` / `DISCARDED` | 生成即 `DRAFT`；转正成功 → `ACCEPTED`（行保留，可对账）；丢弃 → `DISCARDED`。状态抢占在同一事务内完成，重复转正不改变状态 |
| ST-508 | 上传文件 | `已存` / `文件缺失` | 落盘成功即 `已存`；`storage_key` 指向的文件不存在时预览 / 下载返回「资料文件不存在或已被删除」 |
| ST-509 | 设备会话 | `本机` / `其他设备` / `已吊销` | 当前令牌对应会话为 `本机`；其余为 `其他设备`（可批量吊销）；吊销后该设备下次请求 401 |
| ST-510 | 账号 | `正常` / `待改密` / `已禁用` | `must_change_password=1` → `待改密`（服务端拦截非豁免 API）；`is_active=0` → `已禁用`（所有请求 401，含未过期令牌） |

## 5. 权限规则（PR-5xx）

| 编号 | 主体 | 允许 | 拒绝 |
|---|---|---|---|

## 9. 未决问题（Q-5xx）

**Q-501 用户级 AI 配置与实例级默认值的「关闭继承」**
- 问题：用户留空 = 继承实例默认；但用户若想「这个字段我不要继承，就用不到」时无法表达。
- 分歧：SPEC §2.3 只说「允许用户配置自己的 API 或代理」，没说能否显式关闭继承。
- 候选方案：A 保持现状（留空即继承）；B 增加一档「不使用实例默认」开关；C 用「显式空串」表达关闭。
- 推荐与理由：A。家庭/小团队场景下实例默认就是运维者自己配的，多一档开关只会增加困惑；需要关闭继承的真实用例（如某用户想强制离线）可由「关闭联网」这一独立开关覆盖。
- 未裁定时的默认行为：按 A 执行（当前实现）。

**Q-502 已保存密钥能否清除**
- 问题：掩码值与空值都被视为「保留旧密文」（`ai_config_repository.py:227-230`），用户无法删除一个存错的密钥。
- 分歧：安全上应可清除；实现上掩码回显会与「用户没改」混淆。
- 候选方案：A 增加独立「清除密钥」按钮；B 输入特定哨兵值；C 保持不可清除。
- 推荐与理由：A。哨兵值容易被误触，不可清除则存错密钥后只能改值不能清空。
- 未裁定时的默认行为：按 A 设计按钮，未实现前保持现状并在密钥框旁说明「输入新值即替换，暂不支持清除」。

**Q-503 外观与语言偏好是否跨设备同步**
- 问题：主题 / 配色 / 密度 / 语言只写 localStorage；SPEC §2.1 要求多设备实时同步。
- 分歧：同步则每次换设备要重设；不同步则与「实时同步」字面冲突。
- 候选方案：A 明确为设备级偏好（原型已这么说）；B 入服务端并随事件同步。
- 推荐与理由：A。外观是「这台屏幕看起来怎样」的问题，与学习记录不同类；且服务端同步会在无网启动时拖累首屏。
- 未裁定时的默认行为：按 A 执行，并在关于页写明「外观与语言保存在本设备」。

**Q-504 自定义强调色是否恢复**
- 问题：SPEC §8 明列「用户可以自定义强调色 + AA 4.5:1」，生产已退役，原型也没有。
- 分歧：SPEC 是已确认真理源；退役是工程决策（强调色归配色家族所有）。
- 候选方案：A 恢复（带对比度校验与焦点环同步）；B 修订 SPEC §8 删除该条并登记 80 册。
- 推荐与理由：A。四套配色已覆盖绝大多数偏好，但「自定义强调色」是 SPEC 验收基线里唯一未兑现的条目，恢复成本低于改真理源的信誉成本。
- 未裁定时的默认行为：按 B 处理（保持退役），直到用户裁定；本轮不因未裁定而阻塞其他条目。

**Q-505 主解释的呈现位置**
- 问题：采纳后在哪儿显示？
- 分歧：反馈区顶部（强）vs 版本列表内标记（弱）。
- 候选方案：A 反馈区顶部渲染「当前主解释」并把官方解析降为一行；B 仅在版本列表打「已采纳」。
- 推荐与理由：A。用户改主解释的目的就是「接下来我看这版」，只改标记看不出效果。
- 未裁定时的默认行为：按 A 定义，实现可分两步（先标记后提升）。

**Q-506 AI 建议标签 / 蓝图是否纳入本期**
- 问题：SPEC §2.3 允许，但无任何实现与原型。
- 分歧：纳入则范围扩大到 10 / 30 册；不纳入则 SPEC 有一条长期未兑现。
- 候选方案：A 本期不做，修订 SPEC §2.3 为「变式题先行，标签与蓝图建议后续」；B 本期做最小版（仅标签建议）。
- 推荐与理由：A。真实使用画像中章节为 0、蓝图为 0（UX §3），标签才是真实组织维度——先做标签建议有意义，蓝图建议没有数据基础。
- 未裁定时的默认行为：按 A 执行，本条在 80 册登记为 SPEC 待修订项。

**Q-507 未作答时是否开放 AI 入口**
- 问题：SPEC §2.3 说做对、做错、未作答都能调用；生产与原型都只在作答后开放。
- 分歧：未作答就调 AI 有「提前看讲解」的泄题风险，但这只在模考语境下成立。
- 候选方案：A 练习页与题目页未作答即可调，模考不开放；B 只在作答后开放。
- 推荐与理由：A。练习不是模考，用户「先问一下思路再答」是正当用法；模考侧已有交卷前不泄题的硬约束（SPEC §3.2）。
- 未裁定时的默认行为：按 A 定义（对应 `GAP-502`）。

**Q-508 「账号与安全」归入「协作与实例」组是否合理**
- 问题：生产与原型都把账号安全放在「协作与实例」组下。
- 分歧：账号是个人主体；协作与实例是他人与实例主体。
- 候选方案：A 移到「个人」组；B 保持。
- 推荐与理由：A。「谁配置」分层的第一刀应是「只影响我 / 影响他人或整个实例」，账号安全只影响我。
- 未裁定时的默认行为：按 B 保持（避免为分组顺序改动索引测试与键盘序）。

**Q-509 资料是否需要文件夹 / 标签 / 批量管理**
- 问题：资料量上来后只有类型筛选与搜索是否够。
- 分歧：加组织结构接近「第二题库」，有悖 P-5；不加则量大了难找。
- 候选方案：A 只做类型 + 搜索 + 收藏；B 增加用户自定义标签；C 增加文件夹。
- 推荐与理由：A。资料是辅助材料，不是主档案；收藏 + 搜索 + 关联到题目已覆盖「刷题时找回」的真实路径。
- 未裁定时的默认行为：按 A 执行。

**Q-510 变式题草稿是否允许改选项**
- 问题：生产草稿箱可编辑选项键与文本，原型草稿卡不渲染选项。
- 分歧：可改则转正质量高；不可改则契约简单。
- 候选方案：A 可改（生产现状）；B 只改题干 / 答案 / 解析。
- 推荐与理由：A。模型给的选项键时常错位，不允许改会让转正后的题不可用。
- 未裁定时的默认行为：按 A 执行，原型下轮补上选项编辑。

**Q-511 联网核查的超时与重试**
- 问题：固定 2.0s 超时、无重试（`web_search.py:34`）。
- 分歧：长超时拖慢刷题反馈；短超时把慢服务误判为不可用。
- 候选方案：A 2s + 一次重试；B 可配置；C 保持 2s 不重试。
- 推荐与理由：A。重试成本低，且能把「偶发抖动」与「真的没配」区分开。
- 未裁定时的默认行为：按 A 设计，未实现前保持 C。

**Q-512 变式题草稿的目标题库默认值**
- 问题：`target_bank_id` 缺省取原题题库（`ai_tutor_service.py:285`）。
- 分歧：默认原题库符合直觉；但用户可能想放到「变式练习库」。
- 候选方案：A 默认原题库且生成前可见可改；B 强制显式选择。
- 推荐与理由：A。默认值 + 可改比强制选择少一步（00 册 P-6）。
- 未裁定时的默认行为：按 A 执行（当前实现已是 A，但界面上没有「可改」的入口，需补）。

### 10.4 生产实例（可选增强，已执行）

- 实例：`http://127.0.0.1:3000`，`/api/v1/health` 返回 200、`version: v1`、`commit_sha: "unknown"`。
- 注册了一个一次性测试账号（名称从略；仅此一次写操作），随后只读浏览：`/auth/me`、`/ai/config`、`/assets`、`/ai/drafts`。
- `/ai/config` 对新用户返回文档默认值 + `is_configured: false` + `has_custom_config: false`，与 BR-513 / BR-514 的分层语义一致；`/assets` 与 `/ai/drafts` 均为空数组。
- **偏差（登记为 `GAP-525`）**：该实例 `/auth/me` 不返回 `is_admin`，且 `/api/v1/admin/users`、`/api/v1/admin/settings`、`/api/v1/sessions` 均 404——说明线上运行的构建早于本地仓库 HEAD（`ae40fd1`，v1.0.24）。本册的「现状」判断以本地源码为准，实例仅用于确认接口契约。
