## 1. 域定位与边界

模考域负责「按一份可复用的组卷配置，生成一次可限时、闭卷、终结后一次性结算的考试」，并产出可回看的成绩报告。它与刷题域共用会话与作答内核（草稿同步、冲突合并、计时、判分），差异只在四处：**判分时机**（交卷后才结算）、**信息可见性**（交卷前不透题，`BR-301`）、**组卷来源**（蓝图版本而非即时抽题）、**是否纳入学习记录**（由会话配置决定，`CR-08`）。

域内实体四类：

| 实体 | 说明 | 落点 |
|---|---|---|
| 考试档案（exam_profile） | 一份可复用的考试目标（名称/说明），本身不承载规则 | `exam_profiles` 表 |
| 蓝图版本（exam_blueprint） | 档案下的不可变组卷规则快照，`version_number` 自增 | `exam_blueprints` 表 |
| 模考会话（practice_sessions, mode=EXAM） | 一次具体考试，绑定 `blueprint_id` 与题目快照 | `practice_sessions` 表 |
| 成绩报告（result_json） | 交卷时一次性计算并落库的终局结果，**落库后永久不可变、不重算、不覆盖**（`CR-25`） | `practice_sessions.result_json` |

边界划分：

- **属于本域**：档案与蓝图的增改查、组卷、开始前确认、会话内计时/作答/标记/交卷、报告生成与回看、退出与草稿、重考。
- **不属于本域但强耦合**：判分算法本体（刷题域 `domain/learning/scoring.py`）、错题与 FSRS 写入（刷题域，本域只通过「纳入学习记录」开关触发，`CR-08`）、题库内容的编辑（题库域；**进行中的模考不锁定、不脱敏、不阻断任何题库编辑**，`CR-26`）。
- **不属于本域**：AI 解释、笔记、导入向导、趋势看板。模考报告中的知识点统计只消费题目版本上的标签快照，不新增标签体系。

## 2. 功能定义

### FN-301 模考中心

- **存在目的与场景**：模考的唯一工作台。用户在这里看「有没有没考完的」「有哪些考试档案可复用」「能直接从哪些题库开考」「以前考得怎么样」，并由此进入考试会话或蓝图编辑。
- **入口与适用条件**：主导航「模考」→ `/exams`。任何已登录用户可进入；页面内的可用动作依赖「至少一个可访问且题量 > 0 的题库」（`ExamCenterView.vue:349` `examBanks` 过滤 `question_count > 0`）。
- **可执行操作**：
  1. 查看并恢复/放弃未完成模考（OP-301）。
  2. 查看考试档案列表，进入蓝图编辑（FN-303）或开始（FN-305）。
  3. 从题库直接开始（不使用蓝图，FN-311 降级路径）。
  4. 新建考试档案——创建后立即打开该档案的蓝图编辑（OP-302）。
  5. 回看历史成绩报告（FN-308）。
  6. 无题库时跳转导入向导。
- **操作结果**（含数据与状态变化）：
  - 页面加载并行拉取题库、档案、`mode=EXAM` 的活跃会话（`ExamCenterView.vue:411-426`，`Promise.allSettled`）。
  - 新建档案：`POST /exams/profiles` 返回后 `profiles.unshift(profile)` 并打开蓝图抽屉（`ExamCenterView.vue:438-444`）。
  - 放弃会话：`POST /practice/sessions/{id}/abandon`，本地从 `activeSessions` 移除（`ExamCenterView.vue:513-515`）。
  - 任一区块请求失败：**只替换自己那一块**为失败态 + 「重试」按钮，档案、题库、进行中、历史报告四块互不影响，其余仍可点。
- **与其他功能的关系**：向上承接题库域的题库与题目；向下进入 FN-305 开始会话；向右联动 FN-303 蓝图编辑；历史报告入口联动 FN-308。
- **当前缺失与不合理之处**：
  1. **没有历史报告列表**。右栏「成绩报告」只有一句说明文案，没有任何列表与回看入口（`ExamCenterView.vue:148-151`）；`exams.py` 也没有「列出已完成会话/报告」的端点（仅 `/profiles`、`/sessions` POST、`/sessions/{id}/complete`）。已交卷会话只能靠手输 `/exam/{sessionId}` 打开。原型 `pages/screens/exams.html:780-797` 已有完整报告表格 + 回看对话框。
  2. **没有「重新考试」动作**。原型报告页顶栏有「再考一次」（`pages/screens/exam.html` 报告态顶栏），生产 `ExamCenterView.vue` 与 `ExamView.vue:172-174` 的报告操作只有「返回模考中心」。
  3. **开始入口未走统一活跃会话决策**。`beginExam` 直接 `startExam(...)`（`ExamCenterView.vue:493`），没有像今天页/题库工作区那样先查同模式活跃会话再弹「继续 / 结束并新建」（`CR-14`：所有「开始练习 / 开始复习 / 开始模考」入口必须调用同一个开始决策，冲突门只比较同 `mode`，跨模式允许并存）。用户可以在已有一场未交卷模考时再开一场，造成会话堆积（UX §5.2「会话可无限增殖」在 EXAM 模式下仍未消除）。**本期修复**（`GAP-312`）。
  4. **加载失败是整页报废而非局部降级**。三个请求中任意一个 rejected 就连考试档案列表、题库列表一起隐藏（`ExamCenterView.vue:421,56-60`）。失败态与重试已具备（`REQUIREMENTS_TRACEABILITY.md:510`），但降级粒度仍是全有或全无。
  5. 空态出口不完整：`ExamView.vue:265-269` 的「这个考试档案没有题目」只有「返回模考中心」，没有原型的「去编辑蓝图」直达（原型 `pages/screens/exam.html` 空态）。
- **理想完成态**：
  1. 页面四块内容各自独立加载与失败：档案、题库、进行中、历史报告任一失败只替换自己那一块，其余可点。
  2. 历史报告成为正式区块（表格：交卷时间 / 考试档案 / 总分 / 正确率 / 状态 / 回看），点击打开 FN-308 的报告回看。
  3. 点「开始模考」时若已有 `mode=EXAM` 的活跃会话，先弹「继续 / 结束并新建 / 取消」；取消不产生新会话（`CR-14`，同模式才算冲突，跨模式允许并存）。
  4. 每份档案行提供「重新考试」快捷动作（用该档案当前蓝图版本开新会话，FN-310）。
  5. 无题库时「开始模考」禁用并附原因，与原型一致显示「先导入题目」；空态另给「去导入题目」出口，不留死路（P-7）。

### FN-302 考试档案管理

- **存在目的与场景**：把「我要考的那场试」固化成可复用模板，避免每次开考重配。
- **入口与适用条件**：模考中心「新建考试档案」按钮 / 空态「新建考试档案」。仅需登录，不要求题库存在（档案可以先于题库创建）。
- **可执行操作**：新建（名称必填、说明选填）、查看列表（含蓝图摘要：配额段数、总题数、负分）、重命名、编辑说明、复制（复制时连带最新蓝图版本）、删除（删除保护集 = 无进行中会话引用 ∧ 无历史报告引用，见 FN-302 理想完成态）。
- **操作结果**：`POST /exams/profiles` → `exam_profiles` 新行 → `list_profiles` 按 `created_at DESC` 返回并附带 `latest_blueprint`（`exam_repository.py:22-31`）。档案本身不含规则；无蓝图的档案在列表中显示「不使用蓝图」（`ExamCenterView.vue:75-78` `blueprintOf` 返回 null 时）。
- **与其他功能的关系**：档案是蓝图的容器；FN-305 开考时可选定档案；档案与蓝图是一对多（多版本）。
- **当前缺失与不合理之处**：
  1. 档案不可重命名、不可删除、不可复制（`exams.py` 只有 `GET /profiles`、`GET /profiles/{id}`、`POST /profiles`）。模板一旦建错只能废弃。
  2. 档案列表不显示「这份档案被几场进行中的模考、几份历史报告引用」，用户无法判断能否安全改蓝图或删除。
  3. 档案不记录适用考试体系/科目（SPEC §2.0.1 的「考试体系 + 科目」在模考侧无落点），跨考试体系的档案只能靠名称区分。
- **理想完成态**：档案支持重命名、编辑说明、复制（复制时连带最新蓝图版本）、删除。**删除不因被引用而拒绝**（与 `CR-26` 同一取向：不阻断），但必须保证**被它引用的会话与历史报告不坏**——这是删除的**约束**，不是删除的**前置条件**：被引用时提示「有 N 场进行中的模考 / N 份历史报告引用本档案；这些考试仍按快照进行、历史报告仍可回看，新考试将不再使用本档案」，用户确认后执行；执行时**不删除**被引用的蓝图版本本身，进行中的考试继续按会话快照与已绑定的 `blueprint_id` 判分，历史报告继续可回看。档案可挂到一个考试体系/科目上，用于模考中心按体系分组。

### FN-303 蓝图可视化编辑与版本绑定

- **存在目的与场景**：让用户按「题型 × 难度 × 章节/标签 × 数量」描述一份卷子的结构，并设定负分、0 分下限与是否纳入学习记录。蓝图是组卷的唯一规则来源。
- **入口与适用条件**：档案行「蓝图编辑」按钮 / 右栏蓝图链接。每次打开按需拉取 `GET /exams/profiles/{id}/blueprint`，404 视为「尚无蓝图，从空开始」（`ExamCenterView.vue:533-538`）。
- **可执行操作**：
  1. 设负分（0–5，步长 0.5）。
  2. 设 0 分下限（蓝图级开关 `floor_at_zero`，默认关；关时总分可为负，规则摘要须说明「负分无下限」——`Q-302` 裁定 C）。
  3. 设「是否纳入学习记录」的蓝图级默认值（默认开；会话级可覆盖——`Q-303` 裁定 B、`CR-08`）。
  4. 增删配额段；每段设题型（单选/多选/判断/主观）、题数、难度（不限/1–5）。
  5. 保存 → `POST /exams/profiles/{id}/blueprint`，服务端 `version_number = MAX + 1`（`exam_repository.py:38`）。
  6. 带未保存修改关闭 → 二次确认「取消 / 放弃 / 保存」（`ExamCenterView.vue:287-303`、`385-390`）。
- **操作结果**：新蓝图版本写入 `exam_blueprints`，`latest_blueprint` 变为新版本；保存后 `profiles` 重新拉取，抽屉标题显示 `v{version_number}`（`ExamCenterView.vue:600-603`、`231`）。总题数为各段 count 之和（`ExamCenterView.vue:367`），≤ 0 时拒绝保存（`ExamCenterView.vue:580-583`）。
- **与其他功能的关系**：蓝图版本在开考时被会话绑定（BR-309）；组卷算法消费蓝图（FN-305）；「纳入学习记录」作为会话配置的回退值（BR-305、`Q-303` 裁定 B）。
- **当前缺失与不合理之处**：
  1. **章节与标签在 UI 中不可配**。数据结构完整支持 `chapter_id` / `tags`（`blueprint.py:42-65`），`ExamCenterView.vue` 的 `blueprintSnapshot`/`blueprintSections` 也带着这两个字段，但渲染的配额行只有题型、数量、难度三个控件（`ExamCenterView.vue:247-262`），`chapter_id` / `tags` 永远是空串。EE-001 声称「蓝图根据章节按需筛选」已闭环（`REQUIREMENTS_TRACEABILITY.md:41`），但用户侧无法输入章节条件——能力存在而不可达。
  2. **没有分值配比**。SPEC §6 要求蓝图覆盖「题型和分值配比」；现行判分是每题 `score_ratio` 1.0/0.5/0.0 直接求和（`domain/learning/scoring.py:47-53`、`grading.py:7`），蓝图无法给某一段加权。报告也只能给出原始分，无法给出「按配比折算的百分制」。
  3. **「纳入学习记录」不在蓝图里配**。生产只在开考对话框提供一次性勾选（`ExamCenterView.vue:206-209`），蓝图层没有该字段；`record_mistakes_for_session` 的「蓝图回退」分支因此几乎不会命中（见 `practice_repository.py:691-726` 的配置优先、蓝图回退逻辑与 SPEC §4.1 的对应关系）。`Q-303` 裁定 B 要求蓝图级可配 + 会话级覆盖，本条随 `GAP-305` 一并补齐。
  4. **蓝图没有导入模板入口**（见 FN-304）。
  5. **保存后没有版本历史视图**：`latest_blueprint` 只返回最新版（`exam_repository.py:43-56`），`get_blueprint(id)` 虽在仓储层存在，但 `exams.py` 没有暴露按 id 读历史版本的路由。用户改坏了无法回看上一版长什么样。
- **理想完成态**：
  1. 配额段可视化配置五维：题型、难度、章节（下拉，来自题库章节树）、标签（多选，来自题库标签）、题数；每段可设单题分值。
  2. 蓝图头部显示「总题数 / 客观题总分 / 主观题题数 / 负分与 0 分下限 / 是否纳入学习记录」五项实时汇总，保存前校验：总题数 > 0、各段题数之和与目标题量的关系明确、分值之和 > 0。
  3. 蓝图版本列表可查（版本号、保存时间、与该版本的差异摘要、被几场会话绑定），可「以此为基线新建版本」。
  4. 保存采用「新版本」语义，永不覆盖旧版本；旧版本仍可被已绑定它的历史会话读取。
  5. 编辑进行中时，若该档案已被某场未交卷模考绑定，页面顶部提示「已有 N 场进行中的模考使用 v{k}；保存会生成 v{k+1}，不影响进行中的考试」。

### FN-304 蓝图导入模板（低频）

- **存在目的与场景**：降低首次配置成本——从一份标准考试模板（如「单项选择题 50 + 多项选择题 20 + 判断 10 + 问答 2，负分 0.5」）出发改，而不是从零拖配额段。对应 SPEC §2.0.1「考试蓝图由用户可视化配置，也支持导入模板后修改」。
- **入口与适用条件**：蓝图编辑抽屉内的「从模板导入」；仅在档案尚无蓝图或用户主动触发时出现。**模板来源只有两种：内置模板、用户上传的 JSON**——与 AI 建议无关（`CR-19`）。
- **可执行操作**：选择模板 → 预览将生成的配额段与负分 → 确认导入为一份新蓝图版本 → 继续手工修改。
- **操作结果**：写入一条新的 `exam_blueprints` 版本；导入不直接开考。
- **与其他功能的关系**：是 FN-303 的另一种写入路径；与 FN-311 的区别是导入后仍走蓝图组卷。
- **当前缺失与不合理之处**：**完全未实现**。`frontend/src/api/exams.js` 只有 `listProfiles / createProfile / saveBlueprint / getBlueprint` 四个方法，没有任何模板端点；`exams.py` 同样没有。SPEC §2.0.1 承诺的能力在生产与原型中均无入口。
- **理想完成态**：内置 3–5 个常见考试结构模板 + 支持上传 JSON 模板；导入前展示「将创建 v{k+1}，包含 N 个配额段、负分 X」的预览；模板校验失败（缺 sections、count 非正数、题型非法）时逐条列出原因且不写库。**本期不提供 AI 建议蓝图**（`CR-19`；另见 `50` 册 `FN-509`）；蓝图导入模板与 AI 建议无关，走的是用户上传/内置 JSON 这一条确认路径。

### FN-305 组卷与开始前确认

- **存在目的与场景**：把蓝图（或题库）变成一份具体考试档案，并在开考前把「考什么、考多久、学习记录算不算」讲清楚。
- **入口与适用条件**：档案行「开始」/ 题库行「开始模考」/ 页头「开始模考」。前置条件：至少一个题量 > 0 的可访问题库（`ExamCenterView.vue:349,85,121`）；题库无题时按钮禁用并给原因。所有「开始模考」入口必须走同一个开始决策（`CR-14`）：已有同模式活跃会话时先弹「继续 / 结束并新建 / 取消」。
- **可执行操作**：选择题库、选择蓝图（含「不使用蓝图」）、设题目数量、设时长（正整数分钟）或明确选「不限时」、设「是否纳入学习记录」，确认开始。
- **操作结果**：
  - 前端把数量钳制在 `min(题库题量, 蓝图总题数)`（`ExamCenterView.vue:353-358`），非法时禁用提交并给出原因（`ExamCenterView.vue:359-365,482-489`）。
  - `POST /exams/sessions`（`exams.py:63-79`）→ 若带 `profile_id`，先取 `latest_blueprint` 解析出 `blueprint_id`，无蓝图则 404；随后走 `practice.start_session(...)`。
  - 组卷：有 `blueprint_id` 时 `select_questions_by_blueprint(candidates, blueprint, total_questions)`（`practice_service.py:95-100`），否则 `questions[:total_questions]`（`practice_service.py:108`）。
  - 会话落库：`total_questions = len(selected)`、`time_limit`、`exam_profile_id`、`blueprint_id`、题目快照 `questions_json`（含 `question_id/version_id/bank_id`）、`config_json`（含 `bank_ids`、`record_mistakes`）（`practice_service.py:119-132`）。
  - 空题库或无匹配时拒绝建会话，报「当前题库没有符合条件的题目」（`practice_service.py:109-118`）。
  - 成功后跳转 `/exam/{sessionId}`。
  - **不锁定任何题库内容**：会话只持有自己的题目与版本快照（`CR-26`、`FN-312`）。
- **与其他功能的关系**：消费 FN-303 的蓝图版本；产出 FN-306 的会话；「纳入学习记录」决定 FN-308 报告后是否写复习队列（`BR-305`、`CR-08`）。
- **当前缺失与不合理之处**：
  1. **开始前确认信息不完整**。对话框不显示「本场将考哪些题型各几题」「客观题总分多少」「负分如何计」，只显示题库题量与上限（`ExamCenterView.vue:188-211`）。用户无法在开考前核对蓝图是否被正确组卷。
  2. **蓝图组卷结果不可预览**。降级补齐（BR-310）静默发生：蓝图要 40 题而题库只匹配到 12 题时，`select_questions_by_blueprint` 直接补满到目标数（`blueprint.py:77-87`），开考对话框中没有任何「实际组出 N 题，其中 M 题为降级补入」的提示。
  3. **「纳入学习记录」不落蓝图**：该值只进本次会话 `config_json`（`practice_service.py:126-127`），没有蓝图级默认值；下次从同一档案开考又回到默认 true。`Q-303` 裁定 B：蓝图级可配 + 会话级覆盖，默认 true。
  4. **时长口径分裂**：上限 600 分钟是硬编码前端约束（`ExamCenterView.vue:204`），后端 `time_limit` 无校验；`time_limit = 0` 时前端按「已用时长」显示（`ExamView.vue:18-19`），但 `start_exam` 允许 0。产品规则：时长要么是正整数分钟，要么明确「不限时」，**不允许 0 这种既非限时又非不限时的歧义值**。
  5. **没有「继续 / 结束并新建」决策**（同 FN-301 第 3 条，`GAP-312`，本期修复）。
- **理想完成态**：
  1. 开始前确认区固定展示七项：题库与可组卷题量、蓝图版本号、按题型/难度的实际配额结果（含降级补入的题数与原因）、客观题总分与折算百分制、负分规则（含是否设 0 分下限）、**时长（正整数分钟，或明确写「不限时」；不接受 0，`CR-31`/`BR-311`）**、是否纳入学习记录。任一项与蓝图声明不一致时高亮并说明差异来源。
  2. 提供「预览考试档案」：开考前可看组出的题目清单（只显题号与题型，不显答案解析），确认后再开考。
  3. 「纳入学习记录」存为蓝图级默认值，会话级可覆盖；开始前确认信息显式显示本场取值，关闭时必须写明「本场不纳入学习记录：错题、FSRS、统计均不更新」（`CR-08`、`Q-303` 裁定 B）。
  4. 已有同模式活跃会话时，先弹「继续 / 结束并新建 / 取消」（`CR-14`）。

### FN-306 考试会话（倒计时 / 答题卡 / 待复查标记 / 跳题）

- **存在目的与场景**：闭卷作答的单一页面（可限时，也可不限时）。所有考试内交互都收敛在这一页，且这一页在交卷前绝不透露对错。
- **入口与适用条件**：`/exam/{sessionId}`。进入时服务端返回会话；若 `mode !== 'EXAM'` 重定向到刷题页；若已交卷直接渲染报告；若 `is_expired` 进入只读态——**「作答窗口结束」不是会话终结态**，会话本身仍是 `active`，仍必须能交卷与生成报告（`CR-31`）。
- **可执行操作**：作答（选项点选 / 键盘 A–H 或 1–8 / 文本题输入）、上一题/下一题、答题卡跳题、标记待复查（`B`）、左右滑动手势切题（移动端）、交卷、退出。
- **操作结果**：
  - 倒计时：顶栏常显剩余时间，≤ 300s 时计时器进入低时态（`ExamView.vue:17`）；**不限时会话没有硬截止、没有宽限、没有自动交卷**，只显「不限时」与已用时长，结束只能由用户主动「交卷」或「放弃」（`CR-31`、`FN-306` 理想第 4 项）。剩余时间以服务端为准，客户端只做展示（`BR-311`）。
  - 作答：改 `answers` → 立即写 localStorage → 400ms 防抖 `syncDraft`（`ExamView.vue:769-786,707-710`）。
  - 标记：`POST /sessions/{id}/toggle-flag`，返回后覆盖 `flags`（`ExamView.vue:794-805`）。
  - 答题卡：桌面为右侧常驻栏（`ExamView.vue:218-241`），移动档收起为底部「移动作答卡」抽屉（`ExamView.vue:272-302`，scoped 768 旧断点见 §7 注）；格子状态 = 当前 / 已答 / 未答 / 已标记。
  - 按固定节流周期强制同步一次草稿（周期取值是实现载体，P-12；默认量级为十秒）（`ExamView.vue:879-881`）。
- **与其他功能的关系**：与刷题会话共用内核；差异由 `answersLocked`（`ExamView.vue:505`）与 `mode` 决定；交卷与超时后的收卷见 FN-307，报告见 FN-308。
- **当前缺失与不合理之处**：
  1. **术语与 SPEC 不一致**：SPEC §3.2 写「待复查标记」，产品实现叫「标记 / flagged」。功能等价，但文档与界面不同词，跨册引用会错位。
  2. **`submitAttempt` 是死导入**（`ExamView.vue:376` 导入但从未调用）。单题提交路径（`POST /sessions/{id}/attempts`）在模考中不可达，意味着模考的全部判分依赖交卷时从 `answers_json` 反推（`practice_service.py:387-404`），任何未同步成功的作答都要靠这条兜底路径。
  3. **低时无提示音/无系统通知**：只剩 5 分钟、1 分钟时只有颜色变化（`ExamView.vue:17`），切到其他标签页时用户不会察觉。
  4. **倒计时是客户端时钟**：`elapsedSeconds` 只在 `onMounted` 用 `created_at` 校准一次（`ExamView.vue:1017-1018`），之后纯本地累加。设备休眠、时钟漂移、跨设备续考都会让客户端剩余时间与服务端 `_exam_expired` 判定（`practice_service.py:167-188`）偏离。
  5. **不限时模考没有明确定义**：界面显示「已用」但没有任何地方说明这场不会自动收卷，用户既不知道要主动交卷，也看不到「还有一场没交」的常驻提示，只能默认静默失效（`Q-206` 裁定 A+B；产品规则见本条理想完成态第 4 项、`ST-302`、`OP-307`、§4.5 方式 3）。
- **理想完成态**：
  1. 统一术语为「待复查」，界面文案与 SPEC 对齐；`B` 键与练习 runner 的「标记薄弱（`W`）」明确区分——同一按键在两个 runner 里必须是同一个动作（`Q-603` 裁定 B）。
  2. 剩余 5 分钟 / 1 分钟给出页面内强提示（不限仅变色），并可选一声轻提示；配置项可关。
  3. 剩余时间以服务端为准：每次草稿同步时服务端回带服务端时间与剩余秒数，客户端据此校正，而不是只信本地累加（禁止把「客户端累加」当产品规则，P-12）。
  4. **不限时模考**（`Q-206` 裁定 A+B）：不限时是单独定义的一类，不与限时考试混用——没有硬截止、没有宽限、没有自动交卷；
     - 顶栏明确写「不限时」，不显示倒计时，只显示已用时长；
     - 结束只能由用户主动「交卷」或「放弃」，会话内两个入口都必须在场；
     - 只要存在未交卷模考，产品内常驻「有未交卷模考」提示，一键「去交卷」或「放弃」，不依赖用户记住 URL；
     - 连续 N 天（默认 30 天，可配）无任何作答活动后，会话明确失效并告知用户，失效后仍由用户显式选择交卷或放弃，不静默、不自动判成绩。

### FN-307 交卷确认与自动交卷

- **存在目的与场景**：交卷是不可逆的终结动作，必须有二段确认；到点则必须自动收卷，且自动收卷也要让用户知道发生了什么。
- **入口与适用条件**：顶栏「交卷」按钮（`ExamView.vue:28-30`）；或到点后由**服务端**在宽限结束时自动收卷——不要求用户保持页面打开（`CR-31`）。
- **可执行操作**：打开交卷确认 → 查看已答/未答/待复查统计 → 「跳到首个未答」→ 取消或确认交卷。**打开交卷确认不冻结答案**：用户可随时关掉对话框回去改答案（`Q-304` 裁定 A）。`is_expired` 态下「交卷」仍然可用——超时禁止的只是继续作答，不禁止交卷（`CR-31`）。
- **操作结果**：
  - 交卷确认对话框展示三项统计与未答警告，未答 > 0 时不阻断、只警告，并提供「跳到第 N 题（首个未答）」（`ExamView.vue:325-347,884-890`）。
  - 确认交卷：`persistDraft(true)` → `completeSession` → 报告落入 `report`、清本地草稿、`switchTab` 到报告态（`ExamView.vue:812-870`）。
  - 到点（限时考试）：硬截止 → 宽限（默认 60s）→ 服务端收卷三段，宽限**只同步截止前已经产生的答案，不用于继续答题**；界面明确告知「已到交卷时间，答案已停止收录」（`CR-31`）。
  - 宽限结束：**由服务端完成交卷并生成报告，不要求用户保持页面打开**；客户端再次打开该会话时直接看到已生成的报告。宽限内不接受新的作答、改答案、标记。
  - 未成功同步的答案必须明确告知处理结果：报告页与终结横幅列出「本机有 N 题未同步成功，未计入本场成绩」，并说明这些答案仍保留在本机、不计入。
  - 客户端进入 `syncExpired` 只读态：停所有自动重试、保留本机副本、提供「以服务器已保存的答案交卷」的显式动作与二次确认（`ExamView.vue:630-667,304-323`）；该态下 `complete` 与报告读取必须放行。
- **与其他功能的关系**：交卷成功即触发 FN-308 的报告计算（落库后永久不可变，`CR-25`）与 `BR-305` 的学习域结算（「纳入学习记录」关闭时学习域零写入）。
- **当前缺失与不合理之处**：
  1. **二段确认不完整**。取消交卷的确认只有一层（`showSubmitConfirm` → `submitExam`），没有「交卷后不可撤销」的强确认副本；原型同样只有一层对话框，但生产在「过期后以服务器答案交卷」路径上才有真正的二段（`ExamView.vue:304-323`）。两条路径的确认强度不一致。
  2. **自动交卷的报告不带来源标记**。报告结构（`practice_service.py:474-495`）没有 `auto` / `submitted_at` / `deadline` 字段，用户事后无法区分「我手动交的」和「时间到被收的」。原型本有 `auto` 字段意图（`pages/screens/exam.html` `buildReport` 的 `auto: R.autoAt`），但 `R.autoAt` 从未被赋值，所以原型里这个区分也失效——回看时报告备注与考试档案回看理由都显示成手动交卷的版本。
  3. **自动交卷依赖客户端且离线不可见**：现状是客户端倒计时归零即 `submitExam(true)`（`ExamView.vue:874-878`），失败会 `markPendingSubmit()`（`ExamView.vue:838`），只在重连/手动重试时恢复。若用户不再打开这个页面，这次自动交卷可能长时间停留在「本机待交卷」状态，而服务端其实已因超时拒绝写入。`CR-31` 要求改为**服务端在宽限结束后完成交卷并生成报告，不要求用户保持页面打开**。
  4. **60 秒宽限是硬编码**（`practice_service.py:188`、`question_repository.py:518`），既不可配置也无产品说明；用户看到的是「到点后还能再答一分钟」这种无解释行为。产品规则：宽限时长是显式产品参数（默认 60s），在会话详情中可见（`GAP-320`）；宽限只用于同步截止前已产生的答案，不用于继续答题。
  5. **超时把该放行的也禁了**：现状超时后服务端对草稿同步、标记、单题提交一律拒绝（`practice_service.py:167-192`），`is_expired` 态下**连 `complete` 与报告读取也一并被拒**，导致会话既不能继续作答、也不能被服务端收卷出报告。`CR-31`：超时禁止的只是「继续作答」这类写入操作，不得同时禁止必要的终结与报告生成。
- **理想完成态**：
  1. 交卷确认固定包含四行：已答 / 未答 / 待复查 / 本场规则摘要（负分、是否纳入学习记录），以及一句「交卷后不能再修改答案」。**未答 > 0 或存在待复查标记时都给警告**（仅计数不够，`Q-308` 裁定 B）；警告不阻断交卷。
  2. 有未答题时，「跳到首个未答」与「仍要交卷」并列为同级主动作，不把交卷按钮降级；从确认对话框返回后答案仍可修改（`Q-304` 裁定 A）。
  3. 到点后按三段走：**作答窗口 → 宽限（只同步截止前已产生的答案，不用于继续答题）→ 服务端收卷**。宽限结束**由服务端完成交卷并生成报告，不要求用户保持页面打开**；客户端再打开直接看到报告（`CR-31`）。若用户此刻仍在页面上，先给一条不可忽略的只读原因条（说明「题目已只读、答案以已保存版本为准、正在自动交卷」），原因条在报告生成前不得消失。
  4. 报告必须记录交卷时间、服务端截止时间与交卷来源三项，交卷来源取值 `manual` / `auto_deadline` / `expired_server_answers`（`ST-303`）；报告页与考试档案回看都据此显示「本场为到点自动交卷」。
  5. 未成功同步的答案必须在报告页与终结横幅明确告知：「本机有 N 题未同步成功，未计入本场成绩」，并说明这些答案仍保留在本机、不计入本场成绩（`ST-303`）。
  6. 宽限时长成为显式产品参数（默认 60s），在会话详情中可见；宽限只用于同步截止前已产生的答案，不用于继续答题。

### FN-308 成绩报告与历史回看

- **存在目的与场景**：交卷后的一次性结算，也是唯一允许展示对错的时刻；报告要能跨天回看且不随后续改题变化。
- **入口与适用条件**：交卷成功后的报告态；或从模考中心历史报告列表点「回看」（当前该列表不存在，只能直链 `/exam/{sessionId}`）。
- **可执行操作**：查看总分·满分·折算百分制/正确率/已答/未答/**未判分**/用时（双口径）/对错分布；按题型统计；按知识点（标签）统计；查看错题与未答列表（含你的答案、正确答案、解析）；查看整卷回看；查看「本报告按题目版本 vN 判分」与「查看该题当前版本」；查看交卷来源（手动 / 到点自动 / 超时后以服务器答案交卷）；返回模考中心；重新考试。
- **操作结果**：
  - `complete_session` 在 active→completed 跃迁时：补算未提交的草稿答案 → `practices.complete` → 按绑定的蓝图版本 `grade_report` 算总分（负分在此生效）→ 统计 correct/partial/incorrect、`type_stats`、`tag_stats`、逐题 `answers` → `save_result` 落库（`practice_service.py:371-499`）。
  - **报告的「已答 / 未答」按作答状态计数，不按 `correctness`**：用户保存了答案即「已答」（含主观题这类「已作答·未判分」的题）；没有保存答案才是「未答」。**未判分是独立计数项**，不并进「未答」（`CR-06`）。
  - **`score_ratio` 对未判分题不参与得分计算，不按 0 分计入**；客观题得分与客观题满分只含已判分的客观题；卷面总分与满分里的主观题部分标注「未判分，不计入」（`CR-06`、`BR-313`）。
  - 报告记录交卷时间、服务端截止时间与交卷来源三项（`ST-303`）；**本机未成功同步的答案不计入本场成绩，并在报告页与终结横幅明确告知**（`CR-31`）。
  - 已交卷会话再次 `complete`：逐字返回已存报告，不重算（`practice_service.py:379-380`、`practice_repository.py:667-689` 的 `result_json IS NULL` 条件保证只写一次）。
  - 重新打开会话：`GET /sessions/{id}` 返回 `report`（`practice_repository.get_session` 解析 `result_json`），前端直接渲染报告而非答题器（`ExamView.vue:990-999`）。
  - 报告加载失败：可重试（`ExamView.vue:962-979`）。
- **与其他功能的关系**：报告的错题列表是复习域的入口；「纳入学习记录」决定这些错题是否写入学习域（`BR-305`、`CR-08`）——关闭时报告内的错题列表是这些错题的**唯一可见出口**，用户可从中跳去普通练习。
- **当前缺失与不合理之处**：
  1. **没有历史报告列表与导航入口**（同 FN-301 第 1 条）。这是 SPEC §3.2「成绩报告」与 UX §7.1「模考增加历史报告」之间最大的落地缺口：报告能算、能存、能直链回看，但用户在产品里找不到它。
  2. **没有整卷回看**。报告的错题区只列 `isExamReviewItem` 过滤出的题（`ExamView.vue:156-170,518`），答对的题不在报告里，用户无法复盘「我是怎么选对的」。原型有「查看考试档案」整卷只读回看（含正确项标记与逐题解析）。
  3. **总分口径未定义且不可配**。现行总分 = 各题 `score_ratio` 之和 − 答错题数 × 负分（`grading.py:4-9`），即「每题 1 分」的原始分；原型用百分制。报告既不说满分是多少，也不给配比折算。`Q-301` 裁定 C：原始分、满分与折算百分制三者同时给出。
  4. **负分可把总分压成负数**，报告直接显示负分，没有产品规则说明是否设 0 分下限。`Q-302` 裁定 C：蓝图级开关 `floor_at_zero`，默认不设下限，规则摘要说明「负分无下限」。
  5. **`unanswered_count` 把主观题误算成「已答」**：`unanswered_count = total_questions - len(attempts)`（`practice_service.py:426`），主观题只要填了字就会生成一条 `correctness=UNANSWERED` 的 attempt（`scoring.py:25-31`），于是主观题既进了「已答」又没有判分结果，与正确率分母 `objective_total` 不是一套口径；用户写了字却可能在界面上被理解成「未作答」。**已裁定（`CR-06`）**：改用独立的作答状态与判分状态，「未判分」单独计数。
  6. **知识点统计只有标签**：`tag_stats` 来自 attempt 上的 `tags`（`practice_service.py:435-439`），没有章节维度；真实生产中章节树基本为空（UX §3），但产品定义上「知识点统计」应同时支持章节与标签。
  7. **已放弃会话再次进入时显示「报告不可用」**：`onMounted` 对 `is_completed` 且无 `report` 的会话一律走 `reportLoadFailed`（`ExamView.vue:990-999`），而放弃会话正是 `is_completed=1, report=NULL`（`practice_repository.py:139-148`）。用户看到的是「加载失败 + 重试」，而重试永远不可能成功——放弃态被伪装成故障态。
- **理想完成态**：
  1. 模考中心常驻「历史报告」表格（交卷时间 / 考试档案 / 总分·满分 / 正确率 / 用时 / 交卷来源 / 状态 / 回看），支持按考试档案与时间筛选；点「回看」进入只读报告页。
  2. 报告页固定七区：总分头（总分、满分、折算百分制——`Q-301` 裁定 C）、**五项计数（已答 / 未答 / 未判分 / 对 / 部分得分 / 错，口径见 `CR-06`）**、正确率与用时（服务端在线作答时长与墙钟时长双口径，`Q-307` 裁定 C；正确率分母只含已判分的客观题）、题型统计、知识点统计（章节 + 标签双维）、错题与未答列表、整卷回看。当客观题已答数为 0 时，正确率显示「暂无数据」，不显示误导性的 0% 或 100%（R20/R21）。
  3. 整卷回看为只读纸面：逐题显示你的作答、正确答案、对错标记与解析；主观题明确标「已作答·未判分」；明确标注「答案与解析按交卷时保存的结果展示，不会因为重新组卷或后续改题而改变」；报告页展示「本报告按题目版本 vN 判分」并提供「查看该题当前版本」入口，由用户自行判断差异，**本期不提供历史重判**（`CR-25`）。
  4. 总分口径写进报告：同时给出原始分、满分与百分制折算（`Q-301` 裁定 C）；总分可为负时显示负分并说明规则，是否设 0 分下限由蓝图级开关 `floor_at_zero` 决定，默认不设下限（`Q-302` 裁定 C）。
  5. 报告区分「手动交卷 / 到点自动交卷 / 超时后以服务器答案交卷」三种来源，并在考试档案回看理由里复述；本机未同步成功的答案单独列出「未计入本场成绩」并说明仍保留在本机（`CR-31`）。
  6. 已放弃会话再次进入时显示「本场已放弃，未计入成绩」，提供「重新考试」，绝不显示重试按钮。

### FN-309 退出、暂存草稿与多设备续考

- **存在目的与场景**：考试可以被安全打断——刷新、关机、换设备都不丢已答内容，也不产生第二份互相覆盖的真相。
- **入口与适用条件**：顶栏「退出」、浏览器刷新/关闭、`onBeforeUnmount`；会话内「放弃这场考试」。
- **可执行操作**：请求退出 → 退出确认给出三个后果明确的动作：「继续」（关闭对话框回到当前题）、「退出（暂存）」（保留草稿）、「放弃」（结束本场，不计成绩，需再确认一次）；直接关闭对话框等同「继续」。刷新或换设备后从「未完成的模考」/「继续上次」回来。
- **操作结果**：
  - 退出：先弹确认，确认后 `persistDraft(true)` 再离页（`ExamView.vue:402-406,1046-1055`）。
  - 本地草稿：浏览器本地草稿存储（具体键名是实现载体，P-12），存 answers/flags/currentIndex/timeSpent/pendingSubmit（`ExamView.vue:593-607`、`domain/exam.js:124-148`）；旧的无用户作用域键在下次写入时迁移删除（`ExamView.vue:586-591,605`）。
  - 断点恢复：合并服务端 answers 与本地草稿，`draftBase` 取服务端最后观察值，使跨设备差异能被识别为冲突而非静默覆盖（`ExamView.vue:1002-1015`）。
  - 恢复后：若本机有未同步修改且在线，立即 `persistDraft()`（`ExamView.vue:1032-1035`）；若上次有 pendingSubmit 且在线，恢复交卷（`ExamView.vue:1028-1031`）。
  - 冲突：合并策略按 `CR-23` 三分类执行——**未提交的答案内容属用户创作类**（用户花力气做出来的），本机与服务端不一致时**保留两个版本并提示选择**，禁止静默覆盖；题目光标、旗标、计时等低价值临时状态走后写覆盖，且覆盖时明确告知「已被另一设备更新，已用较新版本替换」。前端对创作类冲突显示「保留服务器 / 使用本机」两个后果可分辨的按钮（`ExamView.vue:55-70,546-567`）。
  - 离线：显示离线横幅 + 手动重试，计时不暂停（`ExamView.vue:51-54,669-673`）。
- **与其他功能的关系**：与刷题会话共用同一套草稿内核；差异在模考不允许交卷前泄露反馈。
- **当前缺失与不合理之处**：
  1. **退出确认的文案与行为相反，且只有一个出口**。对话框标题用「放弃」、正文用「放弃这场模考」（`ep.exam.abandon*`），按钮只有「取消（实为继续）」和「退出」；而「退出」的实际行为是保留进度（`handleConfirmExit` → `persistDraft(true)` + `doExit`）。UX §5.2 明确点名过这条（「退出文案与行为相反」），§9–§14 的实施记录未涉及，原型已改为三出口（继续 / 退出（保留进度）/ 退出（放弃））。**本期修复**：文案必须与行为一致——标题写「退出」的对话框不得执行放弃，写「放弃」的必须真的结束本场。
  2. **「放弃」只能从模考中心发起**。会话内没有「放弃这场考试」的动作；用户若在会话内想作废重来，只能退出后去模考中心点「放弃考试」。**本期修复**（`GAP-308`）。
  3. **本地草稿无过期与无跨设备清理**：`pendingSubmit` 标记会一直留着直到某次重试成功；本地草稿在会话终结后由 `clearLocalExamDraft` 清理（`ExamView.vue:609-617`），但若用户清理了站点数据，服务端 answers 仍是唯一真相，`draftBase` 归零，历史跨设备差异不再可检测。
  4. **多设备同时续考没有互斥**：两台设备可以同时打开同一会话并交替提交，靠冲突检测兜底；没有「这场考试正在另一台设备上进行」的提示。`Q-305` 裁定 B：后开者只读并提示。
- **理想完成态**：
  1. 退出确认三个后果明确的动作：继续（关闭对话框回到当前题）、退出（暂存，保留草稿，会话留在「未完成的模考」）、放弃（结束本场，不计成绩，需再确认一次）。**三个动作的文案必须与行为一致**（`GAP-308`）。
  2. 会话内提供「放弃这场考试」入口，与模考中心的放弃走同一接口、同一确认、同一文案。
  3. 换设备/新标签页打开同一进行中会话时，后开者进入只读并提示「这场模考正在另一台设备上进行」，并给出「只看不动」的只读选项；用户显式选择在本机继续作答时，才进入 `BR-314` 的冲突合并流程（`Q-305` 裁定 B）。
  4. 本地草稿在会话进入 completed/abandoned 后立即清除；`pendingSubmit` 在服务端返回报告或明确超时后清除，不得无限残留。

### FN-310 重新考试（低频）

- **存在目的与场景**：考完一场后立刻用同一配置再考一遍，是模考的高频复访动作。
- **入口与适用条件**：报告页顶栏；或模考中心档案行。
- **可执行操作**：点击「重新考试」→ 用该档案当前最新蓝图版本开新会话 → 进入新考试会话。
- **操作结果**：新 `practice_sessions` 行，新 `blueprint_id`，全新题目快照；旧报告原样保留。
- **与其他功能的关系**：等价于 FN-305 的快捷路径，跳过设置对话框。
- **当前缺失与不合理之处**：生产未实现（`ExamView.vue:172-174` 报告操作只有「返回模考中心」；`ExamCenterView.vue:81-88` 档案行只有「蓝图编辑/开始」）。原型已有「再考一次」，但其实现是「用同一题库、同一题量、同一时长重开」，且 `pages/screens/exam.html` 的 `again()` 直接以 `R.paper.length` 为总量，不看蓝图当前总题数——蓝图改版后重考的题量不会跟着变。
- **理想完成态**：报告页与档案行都提供「重新考试」；重考前用 FN-305 的开始前确认信息做一次轻量确认（题库、蓝图版本、题量、时长、是否纳入学习记录），确认后开新会话；旧会话与旧报告不受影响。

### FN-311 无蓝图时的降级：基础题库模式（低频）

- **存在目的与场景**：没配蓝图也要能模考。SPEC §2.4 明确「未配置考试蓝图时使用基础题库模式」。
- **入口与适用条件**：档案无蓝图（`blueprintOf` 返回 null，`ExamCenterView.vue:392-397`）或在设置对话框选「不使用蓝图」。
- **可执行操作**：不使用蓝图，按题库既有顺序抽取前 N 题开考（`Q-306` 裁定 A：默认顺序、不承诺随机；随机抽题若提供，必须是用户在设置里显式选择的选项）。
- **操作结果**：`blueprint_id` 为空 → 按题库既有顺序顺序抽取前 N 题；报告仍完整，只是没有配比约束。设置对话框在该模式下提示「不使用蓝图时按题库顺序抽取前 N 题」。
- **与其他功能的关系**：是 FN-305 的退化分支；不应报错。
- **当前缺失与不合理之处**：
  1. 生产在档案列表把无蓝图显示为「不使用蓝图」、在设置里作为选项，行为已可用；但**没有任何地方说明基础题库模式的抽题规则**（是否随机、是否按题型均衡、难度如何分布），用户无法预期会抽到什么。
  2. `select_questions_by_blueprint` 在 `sections` 为空时走 `candidate_questions[:total_questions]`（`blueprint.py:32-33`），是顺序切片而非抽样；同一蓝图两次开考抽到同一批题。SPEC 未规定随机性（`REQUIREMENTS_TRACEABILITY.md:76` 明确「不把随机新增成产品承诺」），但产品定义上应给出确定且可说明的规则。
- **理想完成态**：基础题库模式的组卷规则显式写清（`Q-306` 裁定 A：默认按题库既有顺序**顺序**抽取前 N 题，不承诺随机；随机抽题若提供，必须是用户在设置里显式选择的选项，不作为默认）；设置对话框在该模式下提示「不使用蓝图时按题库顺序抽取前 N 题」。

### FN-312 模考进行中的题库内容不锁定（低频，跨域）

- **存在目的与场景**：考试进行中，被考到的题目**不**被锁定。隔离靠「会话快照 + 题目版本」：开考时会话持有题目与版本快照（`BR-309`），编辑题库内容不会污染进行中的考试。锁定的协作阻塞（他人的模考阻断你编辑共享题库，`GAP-309`）远大于防护价值，故本期取消整套锁定机制（`CR-26`）。
- **入口与适用条件**：任何用户存在 `mode=EXAM` 且未终结的会话时，本规则生效——生效的结果是「什么都不做」：不锁定、不脱敏、不阻断、也不存在「解锁」。**遮蔽只作用于模考 runner 自身**（交卷前不透对错与解析，`BR-301`）；题库与普通练习侧的旧脱敏规则**彻底清除，不是留着不用**（`CR-26`）。
- **可执行操作**：编辑者对被进行中模考引用的题目可正常编辑、改章节/标签、移动、复制、生成新版本。**归档或删除**已被进行中模考引用的题目时**不阻断**，但必须提示「有 N 场进行中的模考引用本题；这些考试仍按快照进行，新考试将不再包含本题」，用户确认后执行。
- **操作结果**：
  - 题库内容列表、题目页、版本列表的可见性**不因模考改变**；`locked_by_active_exam` 一类标记与「活动模考题目集合」计算**彻底清除，不是留着不用**。
  - 编辑生成新的题目版本；进行中的会话继续按自己快照里的 `version_id` 读取，新考试才用到新版本（`BR-302`、`BR-309`）。
  - 进行中的模考本身仍遵守「交卷前不透题」（`BR-301`、R19）——该约束只作用于模考会话，不外溢为题库域的读侧脱敏。
- **与其他功能的关系**：本域不向题库域发送任何锁定信号；题库内容的编辑权归题库域（`PR-4xx`），与模考是否进行、与实例角色均无关（`CR-11`）。
- **当前缺失与不合理之处**：
  1. 生产仍保留整套锁定机制（读侧脱敏、写侧全局拦截、列表锁定标记），并有三套互不一致的锁定口径（读模型多按 `user_id`，写拦截与部分标记用全局集合），导致他人的模考可阻断你编辑共享题库（`GAP-309`）——按 `CR-26` 整条作废，实现方向是**彻底删除**，不是把三套统一成一套。要清除的东西：`question_repository` 读侧脱敏、`locked_by_active_exam` 标记、错题/普通练习侧各自计算的「活动模考题目集合」，以及随之而来的 60s 宽限脱敏判定。
  2. 随本条一并**彻底清除**的还有「题库读模型在模考进行中清空答案/解析」：遮蔽只作用于模考 runner 自身（`BR-301`、R19），题库内容管理、题目页、版本历史、普通练习、错题视图在任何情况下都不因「有未交卷模考」而隐藏答案或解析。若未来要保留「模考进行中本用户在题库内看不到答案」这类防作弊口径，须作为独立规则在题库域定义，不得复用已取消的锁定机制。
- **理想完成态**：一条规则——「进行中的模考不锁定任何题库内容」。编辑者维护题库不受他人考试影响；归档/删除被引用题目时给出上述提示后执行；题库工作区不出现任何与模考相关的锁定徽标或 tooltip。旧脱敏规则**彻底清除，不是留着不用**：`question_repository` 读侧脱敏、`locked_by_active_exam` 标记、错题/普通练习侧各自计算的「活动模考题目集合」与 60s 宽限脱敏判定全部删除；保留的只有模考 runner 自身「交卷前不展示对错与解析」（`BR-301`）。

### 操作与交互（OP-3xx）

**OP-301 恢复或放弃未完成模考。** 模考中心「未完成的模考」区列出所有 `mode=EXAM` 且 `is_completed=0` 的会话，每行显示考试档案名、已答/总数、剩余时长（不限时会话显示「不限时」与已用时长）、「纳入学习记录」标记，以及「继续答题」与「放弃考试」两个动作。
- 「继续答题」→ 跳 `/exam/{sessionId}`，服务端 answers 与本地草稿合并后恢复（FN-309）。
- 「放弃考试」→ 弹确认（显示考试档案名与已答进度）→ 确认后 `POST /sessions/{id}/abandon`，该行从列表消失；取消则不动。放弃是终态：不计成绩、不生成报告、拒绝一切后续写入（§4.5 方式 2）。
- 该区在无未完成会话时整区隐藏（`ExamCenterView.vue:26` `v-if="activeSessions.length"`）；但**不限时会话不得靠「用户记得回来」收口**——只要存在未交卷模考，产品内有常驻的「有未交卷模考」提示，一键「去交卷」或「放弃」（`Q-206` 裁定 A+B）。
- 异常出口：abandon 失败时错误信息进入页内 notice，行不消失，可重试。

**OP-302 新建档案并立即配置蓝图。** 模考中心「新建考试档案」→ 填名称（必填）与说明（选填）→ 「创建考试档案」。
- 成功：对话框关闭，档案进入列表首位，蓝图编辑抽屉自动打开并加载该档案（404 视为空蓝图）。
- 失败：错误信息显示在对话框内，档案不创建，可重试。
- 带未保存修改关闭蓝图抽屉：弹「取消 / 放弃 / 保存」三选一（`ExamCenterView.vue:287-303`）。

**OP-303 打开与保存蓝图。** 「蓝图编辑」入口（档案行或右栏链接）→ 拉取该档案最新蓝图版本 → 抽屉内编辑 → 「保存蓝图」或「取消」。
- 保存：总题数 ≤ 0 时拒绝并提示；成功后 `version_number + 1`，抽屉标题版本号刷新，档案列表摘要刷新。
- 取消/关闭（Escape/遮罩）：有未保存修改时先弹丢弃确认；无修改直接关。
- 保存中禁用保存与关闭按钮，避免重复提交产生多个版本。

**OP-304 开始一场模考。** 「开始」→ 模考设置对话框 → 选题库/蓝图/题量/时长（正整数分钟或「不限时」）/是否纳入学习记录 → 「开始模考」。
- 已有同模式活跃会话时，先弹「继续 / 结束并新建 / 取消」，取消不新建会话（`CR-14`、`GAP-312`）。
- 题量超出 `min(题库题量, 蓝图总题数)` 时提交按钮禁用，并在输入框旁给出「上限为题库题量 N」或「这个题库只有 N 题，请把题目数量改到 1 到 N 之间」。
- 时长必须是 1–600 的整数，或显式选择「不限时」；不接受 0。
- 成功：对话框关闭，跳考试会话页；失败：错误显示在对话框内，可重试。
- 异常出口：所选蓝图已被删除（404「exam blueprint not found」）时提示重新选择蓝图，不静默退化为无蓝图。

**OP-305 考试会话内的作答与导航。** 选项点选 / 键盘 A–H 或 1–8（选项题）/ 文本框输入（主观题）；「上一题 / 下一题」；答题卡格子跳题；移动端左右滑动手势；`B` 切换待复查。
- 每次作答立即写本机草稿，400ms 防抖后同步服务端；每 10 秒强制同步一次。
- 顶栏常显倒计时（或已用时长），`≤ 300s` 进入低时态；不限时会话不显示倒计时，只显「不限时」与已用时长，且没有硬截止、没有宽限、没有自动交卷（`CR-31`）。
- 对话框或作答卡抽屉打开时，除 Escape 外所有快捷键挂起（`ExamView.vue:902-904`）。
- 异常出口：同步失败（网络）→ 离线横幅 + 手动重试，作答不丢；同步失败（已超过交卷时间）→ 进入只读态（OP-307）——该态**拒绝继续作答，放行交卷与报告**（`CR-31`）。

**OP-306 交卷。** 顶栏「交卷」→ 交卷确认对话框 → 「跳到首个未答」或「交卷」。
- 对话框展示已答/未答/待复查三项统计与本场规则摘要（负分、是否纳入学习记录）；**未答 > 0 或存在待复查标记时都给警告**，但不阻断（`Q-308` 裁定 B）。
- 打开交卷确认不冻结答案：关掉对话框可回去继续修改（`Q-304` 裁定 A）。
- 「交卷」→ 先同步草稿，成功后调 complete；成功后清本机草稿并切到报告态；报告落库时记录交卷来源（`ST-303`）。
- `is_expired`（超时）态下「交卷」**仍然放行**：超时禁止的只是继续作答这类写入操作，不禁止交卷与报告生成（`CR-31`）。
- 异常出口：草稿同步失败 → 保留本机副本并标记待交卷，不拿服务端旧草稿交卷；有未解决的跨设备冲突时拒绝交卷并要求用户先选择保留哪一版。

**OP-307 到点与超时后的收卷。** 限时考试到点后按三段走（`CR-31`）：**作答窗口 → 宽限（只同步截止前已产生的答案，不用于继续答题）→ 服务端收卷**。
- 宽限内：不接受新的作答、不接受改答案、不接受标记；界面明确告知「已到交卷时间，答案已停止收录」。
- 宽限结束：**由服务端完成交卷并生成报告，不要求用户保持页面打开**；客户端再次打开该会话时直接看到已生成的报告。
- 超时禁止的只是「继续作答」这类写入操作：`is_expired` 态下**拒绝继续作答（新的作答、改答案、标记、单题提交），放行交卷（`complete`）与报告读取**——不得同时禁止必要的终结与报告生成。
- 客户端收到超时拒绝：停掉所有自动重试，显示只读横幅（含未能提交的题号清单）与「本机有 N 题未同步成功，未计入本场成绩」的明确告知（这些答案仍保留在本机、不计入），并保留一个显式动作「以服务器已保存的答案交卷」，该动作需二次确认。
- 交卷成功后：横幅消失，进入报告态；报告与考试档案回看显示交卷来源（`ST-303`）。
- 重新打开一个已超时会话：直接进入只读态并可看到已生成的报告，不重放本机草稿。
- **不限时会话单独定义，不与限时考试混用**：没有硬截止、没有宽限、没有自动交卷，不收卷、不拒绝写入，只能由用户主动交卷或放弃；连续无活动达到阈值（默认 30 天，可配）后明确失效并告知，失效后仍由用户显式选择交卷或放弃，不静默、不自动判成绩（`Q-206` 裁定 A+B、`ST-302`）。

**OP-308 回看历史报告。** 模考中心「历史报告」表格 → 「回看」→ 只读报告页（当前该表格不存在，见 GAP-301）。
- 报告页可看总分头（总分/满分/折算百分制）、四计数、正确率与用时（在线作答时长与墙钟时长双口径）、题型统计、知识点统计、错题与未答列表、整卷回看，以及「本报告按题目版本 vN 判分」与「查看该题当前版本」。
- 「返回模考中心」回到列表；「重新考试」开新会话（FN-310）。
- 异常出口：报告缺失或读取失败时可重试；若会话状态为 `abandoned`，显示「本场已放弃，未计入成绩」而非重试（GAP-302）。

## 3. 业务规则（BR-3xx）

**BR-301 交卷前不透题。** 模考会话未交卷时，任何接口都不得返回标准答案、官方解析或对错判定。
证据：`practice_service.py:307-318`（`get_session` 对 EXAM 未完成会话删除题目级 `answer`/`explanation`，并把 answers 收敛到 `answer`/`user_answer` 两个键）、`practice_service.py:253-261`（`submit_attempt` 对 EXAM 返回 `feedback_available: False`）。引用：SPEC §3.2「模考交卷前不透露对错和标准答案」。
> 注：本条只约束**模考会话本身**——遮蔽只作用于模考 runner。题库侧读模型在模考进行中清空答案/解析的旧行为已按 `CR-26` **彻底清除，不是留着不用**（`FN-312`）；若未来要保留该防作弊口径，须作为独立规则在题库域定义。

**BR-302 交卷后答案与解析可见，且绑定交卷时快照；报告永久不可变。** 交卷后报告中的正确答案与解析取交卷时刻会话快照解析出的题目版本，不随后续改题变化。报告一旦落库即不可修改、不可重新计算、不可覆盖（`CR-25`）。
- 报告页必须展示「本报告按题目版本 vN 判分」，并提供「查看该题当前版本」入口——由用户自行判断差异，系统不替他改历史。
- **本期不提供历史重判**：修改标准答案只影响之后开始的会话；未来若要做，必须生成新报告版本并保留旧版可查，本期不排入。
证据：`practice_service.py:379-380`（已交卷会话逐字返回已存报告）、`practice_repository.py:667-689`（`save_result` 只在 `result_json` 为空时写入）、`practice_service.py:194-213`（会话按 `questions_json` 的 `version_id` 解析题目，题目被移动/归档不影响已开始会话）。引用：SPEC §3.3「历史作答绑定原版本」、`CR-25`。

**BR-303 判分规则由考试配置决定。** 支持标准得分、部分得分与负分三种规则，可按场次配置。
证据：`domain/learning/scoring.py:47-53`（MULTI 漏选 `PARTIAL` / `score_ratio=0.5`，`grading.py:4-9`（负分）。引用：SPEC §3.2「判分规则可按考试配置：标准得分、部分得分、负分」。

**BR-304 负分只罚答错，不罚未答与主观题；0 分下限由蓝图级开关决定。** `grade_report` 只对 `correctness == "INCORRECT"` 的作答计负分；**未答（没有保存答案）与主观题（已作答但未判分）都不计负分**——主观题不是「答错」，只是「还没判」。
- 是否设 0 分下限由蓝图级开关 `floor_at_zero` 决定，**默认不设下限**；未开启时总分可为负，报告的规则摘要必须说明「负分无下限」（`Q-302` 裁定 C）。
证据：`grading.py:8`。引用：SPEC §5.1（主观题不自动判分）、SPEC §3.2、`CR-06`。

**BR-305 「纳入学习记录」是本场是否写入学习域的总开关。** 会话 `config_json.record_mistakes` 优先，缺省时回退蓝图上的同名字段（保留此优先级）。
- 为真（默认）时：交卷判分写错题表，并同样写 FSRS 卡（与 SPEC §4.1「由考试配置决定」一致）。
- 为假时：本场**完全不写入学习域**——不写 `mistake_records`、不写也不推进 FSRS 卡、不计入任何学习统计与趋势。**禁止半写入**（写了错题却不调度 = 无法复习的孤儿错题，违反 P-7）。
- 会话快照与作答记录仍然保存；报告仍可正常生成与回看（报告属模考域产物，不是学习记录）；**报告内的错题列表是这些错题的唯一可见出口**，用户可从中跳去普通练习。
- 开始前确认信息必须显式写明「本场不纳入学习记录：错题、FSRS、统计均不更新」，避免用户误以为关了开关只是「这些错题不进错题队列」。
- 默认值与存放层级见 `Q-303` 裁定 B：蓝图级可配 + 会话级覆盖，默认 true，开始前确认信息显式显示本场取值。
- **普通练习不暴露此开关**（`CR-08`）：普通练习默认记录学习过程。
证据：`practice_service.py:347-369`（`_schedule_exam_reviews`，仅在 active→completed 跃迁执行一次，天然幂等）、`practice_service.py:356`（`record_mistakes_for_session` 门禁）、`practice_repository.py:691-726`（配置优先、蓝图回退的解析）。引用：SPEC §4.1「模考是否进入错题由考试配置决定」、`CR-08`。

**BR-306 模考进行中不推进 FSRS，交卷时一次性结算。** 单题作答路径在 EXAM 模式下禁止 FSRS 调度；复习排队只在交卷跃迁时按「纳入学习记录」开关做一次。开关关闭时本场学习域零写入（不写错题、不写也不推进 FSRS 卡、不计入统计），见 `BR-305` 与 `CR-08`。
证据：`practice_service.py:347-369` 与 ADV-002（`REQUIREMENTS_TRACEABILITY.md:123`）、UX §11.2「没有在单题提交时给模考排 FSRS」。

**BR-307 提交与交卷必须幂等。** 网络重试不得重复插入作答、重复计入错题或重复推进 FSRS；已交卷会话的任何后续作答提交必须被拒绝。
证据：`practice_service.py:231-232`（`submit_attempt` 对已完成会话抛错）、`practice_repository.py:545`（`update_draft` 对已完成会话抛错）、`practice_repository.py:667-689`（报告只写一次）、`practice_service.py:379-380`（重复 complete 返回原报告）、`ExamView.vue:675-693`（客户端优先取服务端终局报告而非重放草稿）。引用：SPEC §3.2 末句、GUARDRAILS「作答、会话与数据一致性」。

**BR-308 终结态会话拒绝一切作答。** `completed` 与 `abandoned` 都必须是终局：拒绝草稿同步、拒绝标记、拒绝单题提交、拒绝再次交卷改判。
证据：`practice_repository.py:139-148`（abandon 置 `is_completed=1, status='abandoned'`）、`practice_repository.py:545,630`（草稿与标记按 `is_completed` 拒绝）。引用：GUARDRAILS「已交卷、已取消或其他终结状态的会话必须拒绝后续作答」。
> 已知违背：`complete_session` 未按 `status='abandoned'` 拒绝，见 GAP-303。

**BR-309 模考会话绑定启动时的蓝图版本。** 会话落库时记 `blueprint_id`；判分时按该 id 取回同一版本的蓝图，而非当前最新版。
证据：`exams.py:66-71`（开考时解析 `blueprint_id`）、`practice_service.py:129-131`（写入会话）、`practice_service.py:414-420`（交卷时按 `blueprint_id` 重读）。引用：SPEC §6 实现约束「模考会话必须绑定启动时选定的考试蓝图版本」。

**BR-310 蓝图组卷不足时降级补齐，且补齐必须可说明。** 章节/题型/难度筛选匹配不足时，按 `allow_fallback`（默认真）从剩余候选中补齐到目标题数；显式关闭时才报错。
证据：`blueprint.py:75-89`。引用：`REQUIREMENTS_TRACEABILITY.md:31`（EE-001）。
> 产品约束：降级补齐的题数与原因必须在开始前确认信息中可见（FN-305），不得静默。

**BR-311 倒计时只是展示，服务端持有硬截止；到点 ≠ 会话终结。** 客户端倒计时只做展示；**服务端持有一个硬截止时间**。限时考试的时间线固定为三段（`CR-31`）：① **作答窗口**（开考 → 硬截止）正常作答、同步草稿、标记；② **宽限**（硬截止 → 硬截止 + 宽限时长）**只用于把截止前已经产生的答案同步上服务端，不用于继续答题**；③ **收卷**（宽限结束）**由服务端完成交卷并生成报告，不要求用户保持页面打开**，客户端再次打开该会话时直接看到已生成的报告。
- 超时禁止的是「继续作答」这类写入操作（新作答、改答案、标记、单题提交），**不得同时禁止必要的终结与报告生成**：`is_expired` 态下 `complete`（交卷）与报告读取**必须放行**；历史上「`is_expired` 后全部拒绝」的口径废止。
- 未成功同步的答案必须明确告知处理结果：报告页与终结横幅列出「本机有 N 题未同步成功，未计入本场成绩」，并说明这些答案仍保留在本机、不计入本场成绩（`ST-303`）。
- 时长由开始前确认设置：**正整数分钟，或明确「不限时」；不接受 0** 这种既非限时又非不限时的歧义值（`GAP-329`）。
- 硬截止之后的宽限时长是**显式产品参数**（默认 60s），在会话详情中可见，不得以「到点后还能再答一分钟」这种无解释行为出现（`GAP-320`）。
- **不限时会话单独定义，不与限时考试混用**：没有硬截止、没有宽限、没有自动交卷，只能由用户主动交卷或放弃；连续无活动达到阈值（默认 30 天，可配）后明确失效并告知，失效后仍由用户显式选择交卷或放弃，不静默、不自动判成绩（`ST-302`、`Q-206` 裁定 A+B）。
- 禁止把 `created_at + time_limit + 60s` 一类实现公式当产品规则（P-12）；产品只保证「服务端有硬截止、宽限只同步截止前已产生的答案、宽限结束由服务端收卷出报告、客户端只做展示」。
证据：`practice_service.py:167-192`、`practice.py:102-122`、`ExamView.vue:630-667,751-755`。引用：ADV-005（`REQUIREMENTS_TRACEABILITY.md:125`）。

**BR-312 成绩与用时必须落库，且用时给两个口径。** 交卷时把 `score` 与 `time_spent` 写入会话行；报告可从 `result_json` 重复读取。
- 用时同时记录并展示两个口径：服务端 `time_spent`（在线作答时长，草稿同步时取 max 累加）与墙钟时长（交卷时间 − 开考时间）。两者都对用户有意义，报告都给并标注各自含义（`Q-307` 裁定 C）。
证据：`practice_repository.py:667-689`、`practice_service.py:491,496`。这是 UX §5.2「成绩与用时从未落值」的修正结果（§11.1），已落地。

**BR-313 主观题保存作答与参考解析，不计入客观正确率。** 主观题不自动判分：**作答状态是「已作答」，判分状态恒为「未判分」**，`score_ratio` 不参与得分计算、不按 0 分计入；正确率分母只算已判分的客观题。
- **不得因为不能自动评分就把主观题显示成「未作答」**（`CR-06`）；报告的「未判分」是独立计数项。
- 当客观题已答数为 0 时，报告的正确率显示「暂无数据」，不显示误导性的 0% 或 100%（R20/R21）。
证据：`scoring.py:25-31`、`practice_service.py:467-473`。引用：SPEC §5.1。

**BR-314 跨设备草稿合并按数据可否重建分流；后开者默认只读。** 客户端上报它最后观察到的服务端值（`base_answers`）；服务端发现已被别的设备改过时的处理策略按 `CR-23` 三分类执行，**判据是「这份内容是不是用户花力气做出来的」**：
- **未提交的答案内容属用户创作类**：用户花力气做出来的，不可重建。本机值与服务端值不一致时**保留两个版本并提示用户选择**（前端「保留服务器 / 使用本机」），禁止静默覆盖。
- **题目光标、旗标、计时等低价值临时状态属临时状态类**：可重建/低价值，**后写覆盖**，且覆盖时必须明确告知「已被另一设备更新，已用较新版本替换」——覆盖本身允许，静默是禁止项。
- 后打开同一进行中会话的设备**默认进入只读**，并提示「这场模考正在另一台设备上进行」（`Q-305` 裁定 B）；用户显式选择在本机继续作答时，才进入本条的冲突合并流程。
证据：`practice_repository.py:547-575`、`ExamView.vue:737-748,546-567`、`domain/exam.js:59-122`。引用：SPEC §6「同一用户的多设备修改按服务端事件顺序合并；无法自动合并时保留两个版本并提示用户选择」、`CR-23`。

## 4. 数据关系与状态变化

### 4.0 状态定义（ST-3xx）

**ST-301 会话状态 `status`。** `practice_sessions.status ∈ {active, completed, abandoned}`；`is_completed` 是派生列（`active → 0`，其余 `→ 1`）。迁移 20 引入，历史 `is_completed=1` 行回填为 `completed`（UX §11.1）。
- `active`：可读可写，是唯一允许作答的状态。
- `completed`：终局。有 `completed_at` 与 `result_json`；一切写入被拒（BR-308）。
- `abandoned`：终局。无报告；一切写入被拒；**不得再被 complete 改写**（GAP-303）。
- 查询口径：`list_active_sessions` 只返回 `is_completed = 0` 的行，因此 `abandoned` 不出现在「未完成的模考」里。
- 三种状态各自的进入方式见 §4.5「五种退出方式」——同一句话里的「退出」「放弃」「超时」「交卷」在产品里是四件不同的事，不得混用。

**ST-302 派生状态 `is_expired`。** 非持久字段，由服务端在返回会话时判定。为真时：客户端进入只读态，服务端**拒绝继续作答**（新的作答、改答案、标记、单题提交），但**放行 `complete`（交卷）与报告读取**。它**不改变 `status`**——「作答窗口结束」不是会话终结态，会话仍是 `active`，仍必须能交卷与生成报告（`CR-31`）。两种成因，必须分开写、分开处理：
- **限时会话**：到达服务端硬截止（含宽限）即 `is_expired`；宽限只同步截止前已产生的答案，宽限结束**由服务端完成交卷并生成报告，不要求用户保持页面打开**，客户端再打开直接看到报告。
- **不限时会话**：连续无活动达到阈值（默认 30 天，可配）后 `is_expired`。不限时会话**没有硬截止、没有宽限、没有自动交卷**，失效只告知用户并要求其显式选择交卷或放弃，**不自动判成绩**（`Q-206` 裁定 A+B）。
- 超时**不解除任何锁定，因为本来就没有锁定**（`CR-26`、`FN-312`）；超时只结束作答窗口（限时会话并在宽限结束后驱动服务端收卷）。
- 禁止把 `created_at + time_limit*60 + 60s` 一类实现公式当产品规则（P-12）。
证据：`practice_service.py:298,167-188`。

**ST-303 交卷来源 `submitted_via`。** 取值 `manual` / `auto_deadline` / `expired_server_answers`，对应「手动交卷 / 到点自动交卷 / 超时后以服务器答案交卷」三种用户可理解的来源。当前报告不记录该字段（GAP-315）；理想态由 `complete_session` 在写入 `result_json` 时一并落库，报告页与考试档案回看据此显示「本场为到点自动交卷」（FN-307 理想第 4 条）。报告同时记录交卷时间与服务端截止时间；**未成功同步的答案不计入本场成绩**，报告页与终结横幅须明确告知「本机有 N 题未同步成功，未计入本场成绩」，并说明这些答案仍保留在本机（`CR-31`）。

**ST-304 蓝图版本状态。** `version_number` 从 1 起自增，只增不改不删。对用户可见的只有「最新版」；历史版本文档上存在（`exam_blueprints` 行）但无读取入口（GAP-313）。会话按 `blueprint_id` 固定引用某一版，该引用在会话生命周期内不可变。

**ST-305 报告状态。** `result_json` 为空 = 未交卷或已放弃；非空 = 已交卷。`save_result` 的 `WHERE result_json IS NULL OR ''` 保证只写一次，因此「报告已存在」本身就是终态标记（`practice_repository.py:667-689`）。报告一经落库即**永久不可变**：不可修改、不可重算、不可覆盖，并须展示判分所依据的题目版本（`CR-25`、`BR-302`）。

**ST-306 客户端本地态。** `pendingSubmit`（有待交付的交卷）、`syncExpired`（服务端已宣告超时，本机交互终态；会话本身仍是 `active`，交卷与报告读取仍放行，`CR-31`）、`draftConflicts`（有未裁决的跨设备冲突）、`offlineRetryAvailable`。四者都只影响本机交互，不改变服务端状态；刷新后 `pendingSubmit` 由本地草稿恢复，其余重置。

### 4.1 实体关系

```
exam_profiles (1) ──< exam_blueprints (N, version_number 自增)
      │                        │
      │                        └── 被 practice_sessions.blueprint_id 绑定（不可变引用）
      └──< practice_sessions (N, mode='EXAM')
                 │
                 ├── questions_json: [{question_id, version_id, bank_id}]  （开考时快照）
                 ├── answers_json / flags_json / current_index / time_spent （草稿）
                 ├── config_json: {bank_ids, record_mistakes}
                 └── result_json: 成绩报告（交卷时一次性写入）
```

### 4.2 模考会话状态机

```
                 ┌──────────── start_session ────────────┐
                 ▼                                       │
            ┌─────────┐   persistDraft / toggleFlag      │
            │ active  │◀──────────────────────────────────┘
            └────┬────┘
                 │
   ┌─────────────┼──────────────────┬─────────────────────┐
   │ complete    │ 宽限结束 / 失效  │ abandon             │ 服务端硬截止 / 不限时失效
   ▼             ▼                  ▼                     ▼
┌───────────┐ ┌───────────┐    ┌───────────┐        ┌──────────────┐
│ completed │ │ completed │    │ abandoned │        │ expired(派生)│
│ (有报告)  │ │ (有报告)  │    │ (无报告)  │        │ 只读·可交卷  │
└───────────┘ └───────────┘    └───────────┘        │ 可读报告     │
      │              │                  │           └──────────────┘
      └──────────────┴──────────────────┴──▶ 拒绝「继续作答」；交卷与报告读取放行（CR-31）
```

> 「退出（暂存）」不出现在本图：它不产生跃迁，会话留在 `active`。

- `status` 三值：`active` / `completed` / `abandoned`（迁移 20 引入，`is_completed` 为派生列）。
- `is_expired` 不是持久状态，是 `get_session` 时的派生字段（`practice_service.py:298`），成因有两种：服务端硬截止到达、不限时会话长期无活动（`ST-302`）。
- **退出（暂存）不改变 `status`**：会话仍是 `active`，草稿与已答内容保留，可从「未完成的模考」回来。它不是终态，也不产生任何记录——与「放弃」是两件不同的事。
- 允许的跃迁：`active → completed`（手动或自动）、`active → abandoned`、`active → expired(派生) → completed`（宽限结束由服务端自动收卷，或用户显式交卷；该态下 `complete` 与报告读取必须放行，`CR-31`）。
- **「作答窗口结束」不是会话终结态**：`is_expired` 是 `active` 上的派生态，不是第四种 `status`（`CR-07`）。
- **不允许但当前可行的跃迁**：`abandoned → completed`（GAP-303）。
- 五种退出方式的完整定义见 §4.5。

### 4.3 蓝图版本状态

`v1 → v2 → v3 …`，每次 `save_blueprint` 自增；旧版本永不覆盖。会话按 `blueprint_id` 固定引用某一版；`latest_blueprint` 只影响「下一次开考」。

### 4.4 关键状态变化明细

| 动作 | 写入 |
|---|---|
| 开始模考 | `practice_sessions` 新行（active）、`questions_json` 快照、`config_json` |
| 作答/切题/标记 | `answers_json` / `current_index` / `flags_json` / `time_spent`（取 max）、`updated_at` |
| 退出（暂存） | **无服务端状态变化**（仍是 `active`）；仅本机草稿保留 |
| 交卷 | `is_completed=1`、`status='completed'`、`completed_at`、`result_json`、`score`、`time_spent`；并按「纳入学习记录」开关写错题与 FSRS（关闭时学习域零写入，`CR-08`） |
| 放弃 | `is_completed=1`、`status='abandoned'`、`updated_at`（不写报告） |
| 保存蓝图 | `exam_blueprints` 新行（`version_number+1`） |

### 4.5 模考会话的五种退出方式（必须分开定义，不得混为一谈）

「退出」「放弃」「超时」「交卷」在产品里是四件不同的事，加上「会话内放弃入口」这个第二入口，共五项。每项都有明确入口、结果与出口；任何一项都不得用另一项的文案或行为实现。

| # | 方式 | 入口 | 会话状态 | 是否计成绩 | 结果与出口 |
|---|---|---|---|---|---|
| 1 | **退出（暂存）** | 会话内「退出」→ 退出确认 →「退出（暂存）」 | 仍 `active` | 不计（尚未交卷） | 保留草稿与已答内容；稍后从「未完成的模考」/「继续上次」回来。文案必须写「保留进度，稍后继续」 |
| 2 | **放弃** | 会话内「放弃这场考试」或模考中心「放弃考试」→ 确认对话框 → 二次确认 | `abandoned` | 不计成绩，不生成报告 | 明确结束本场；拒绝一切后续写入（BR-308）；再次进入显示「本场已放弃，未计入成绩」+「重新考试」，**绝不显示重试**（GAP-302） |
| 3 | **超时** | 服务端硬截止到达（限时）；或不限时会话长期无活动失效 | 仍 `active`，`is_expired=true` 派生 | 交卷前不计 | 作答窗口结束、会话转只读：**拒绝继续作答，放行交卷与报告读取**（`CR-31`）。限时会话：宽限只同步截止前已产生的答案，宽限结束由**服务端**完成交卷并生成报告（不要求页面打开），并标注交卷来源（`ST-303`）；不限时会话无宽限、无自动交卷，只告知并要求用户显式选择。两条出口：服务端自动交卷、显式「以服务器已保存的答案交卷」（OP-307） |
| 4 | **交卷** | 会话内「交卷」→ 交卷确认 | `completed` | 计成绩 | 报告落库且永久不可变（CR-25）；会话终结，拒绝一切后续写入；报告可跨天回看 |
| 5 | **会话内放弃入口** | 会话内「放弃这场考试」 | 同 2 | 同 2 | 与方式 2 同一动作的第二个入口：同一接口、同一确认、同一文案。现状只有模考中心一个入口，会话内想作废重来必须先退出再去找，属操作死路——本期补齐（GAP-308） |

- 五项的共同约束：① 文案必须与行为一致（标题写「退出」不得执行放弃，写「放弃」必须真的结束）；② 每一项都不得静默发生——超时与不限时失效必须明确告知；③ 终结态（completed / abandoned）拒绝一切写入（BR-308）；④ 交卷确认打开后答案仍可回改（`Q-304` 裁定 A），因此「打开交卷确认」本身不是第 6 种退出方式。

## 5. 权限规则（PR-3xx）

**PR-301 只能对有权访问的题库开考。** `start_session` 对每个目标题库走 `banks.get_for_user(bank_id, user_id)`，拿不到即 404「question bank not found」（`practice_service.py:79-84`）。共享题库的成员（只读）可以开考；可访问即资格，与角色高低无关。

**PR-302 只能操作自己的会话。** 所有会话读写都带 `user_id` 条件（`practice_repository.py:521,637,657-666,690`）；他人会话 id 一律按不存在处理（404），不区分「不存在」与「无权限」。

**PR-303 蓝图与档案按用户隔离。** `latest_blueprint` / `get_blueprint` / `save_blueprint` 都 JOIN `exam_profiles` 校验 `p.user_id`（`exam_repository.py:35,44-51,59-66`）。蓝图不跨用户共享——这是与「共享题库」的不对称点：A 共享题库给 B，B 不能直接用 A 的考试档案组卷。

**PR-304 模考开始不要求题库编辑权，与实例角色无关。** 题库角色只有三种：所有者 / 编辑者 / 成员（`Q-401` 裁定 a、`CR-11`）；成员（只读）即可开考、作答、交卷、回看自己的报告。**实例管理员不因实例角色获得任何题库编辑权**（`CR-11`）——他要编辑某个库必须被显式授予所有者或编辑者；模考的开始与进行同样与实例角色无关。权限表达按相关性分流（`CR-12`）：与当前用户相关但此刻不可用的能力禁用并解释，完全无关的入口不显示。

**PR-305 报告只对自己可见。** `result_json` 随会话行返回，受 PR-302 约束；多用户之间无法读取彼此模考成绩（SPEC §8「多用户之间无法读取彼此的学习记录」）。

**PR-306 进行中的模考不产生任何题库编辑阻塞。** 取消「模考进行中锁定题库/题目」的机制（`CR-26`、`FN-312`）：进行中的模考不锁定内容、不脱敏读模型、不拒绝编辑、也不需要「解锁」。因此不存在「按用户过滤还是全局集合」的问题——**他人的模考不影响你编辑共享题库**。会话与题目版本的隔离由开考快照保证（`BR-309`）。题库与普通练习侧的旧脱敏规则**彻底清除，不是留着不用**；遮蔽只作用于模考 runner 自身（`BR-301`）。

## 6. 跨域与跨页联动

| 触发 | 联动 |

| 开始模考 | 走同一个开始决策门：已有同模式活跃会话时先弹「继续 / 结束并新建 / 取消」（`CR-14`、`GAP-312`）；跨模式允许并存 |

| 编辑者归档/删除已被进行中模考引用的题目 | **不阻断**，但必须提示「有 N 场进行中的模考引用本题；这些考试仍按快照进行，新考试将不再包含本题」，确认后执行（`CR-26`） |

| 报告生成 | 报告落库后永久不可变，展示判分所依据的题目版本（`CR-25`）；报告中的错题列表是复习域的入口（UX §7.3「报告 → 看错题」） |
| 蓝图保存 | 不影响任何进行中会话（BR-309）；影响下一次开考 |
| 换设备/新标签页 | 后开者只读并提示该会话正在另一设备进行；显式选择在本机继续时才进入冲突合并（`BR-314`、`Q-305` 裁定 B） |
| 主题/语言 | 考试会话内可切换（`ExamView.vue:25-26`），切换不打断计时 |

**跨页断点**：模考中心 → 考试会话是路由跳转（`/exam/:sessionId`），考试会话 → 模考中心是「返回」。生产用 `emit('back')` + `router.back()`（`ExamView.vue:412-419`），刷新考试会话页不会丢会话（服务端为主），但**刷新后会丢掉报告态**——已交卷会话刷新后由 `onMounted` 重新拉 `report` 恢复（`ExamView.vue:990-999`），这条路是通的；真正的断点在于没有历史列表，用户无法从产品内回到那份报告（GAP-301）。

## 9. 未决问题（Q-3xx）

**Q-301 总分口径：原始分还是百分制？（已裁定 · C）**
- 结论：总分同时给原始分与百分制；报告头部显示「满分 N」与折算百分制。
- 问题：报告应显示「每题 1 分求和（可负）」还是「按蓝图配比折算的百分制」？
- 分歧：生产是原始分（`grading.py:7`），原型是百分制（`pages/screens/exam.html` `score = correct/total*100`）；SPEC §3.2 只说「总分」，§6 说「分值配比」但未定义口径。
- 候选方案：A 只给原始分；B 只给百分制；C 两者都给（原始分 + 满分 + 折算）。
- 裁定 C 及理由：原始分保留负分与部分得分的精度，百分制便于跨考试档案比较；且 C 不需要改判分内核，只改报告呈现。
- 已落入正文：`FN-308` 理想完成态第 2、4 条；`GAP-311`。

**Q-302 负分是否存在 0 分下限？（已裁定 · C）**
- 结论：蓝图级开关 `floor_at_zero`，默认不设下限；未开启时总分可为负，报告的规则摘要说明「负分无下限」。
- 问题：负分把总分压到负数时，报告显示负分还是钳到 0？
- 分歧：现行实现会显示负分（`grading.py:9` 无钳制）；部分考试制度（如高考）不允许负总分。
- 候选方案：A 不设下限；B 全局钳到 0；C 蓝图级开关 `floor_at_zero`。
- 裁定 C 及理由：默认不设下限（保持可解释），需要时按档案开启。
- 已落入正文：`BR-304`、`FN-303` 可执行操作第 2 条、`FN-305`/`FN-308` 理想完成态。

**Q-303 `record_mistakes` 的默认值与存放层级？（已裁定 · B）**
- 结论：蓝图级可配 + 会话级覆盖，默认 true；开始前确认信息显式显示本场取值。
- 问题：模考错题是否进复习，默认是真是假？配置放会话级还是档案/蓝图级？
- 分歧：生产默认 true 且只在会话级（`ExamCenterView.vue:339`、`practice_service.py:126-127`）；蓝图级回退字段存在但 UI 不可配（`practice_repository.py:691-726`）。SPEC §4.1 只说「由考试配置决定」。
- 候选方案：A 保持会话级默认 true；B 蓝图级可配默认值，会话级可覆盖；C 全局实例设置。
- 裁定 B 及理由：与「蓝图是考试配置的载体」一致，且避免每次开考重勾。
- 已落入正文：`BR-305`（含「关闭时学习域零写入、禁止半写入、报告内错题列表是唯一可见出口、开始前确认必须显式说明」）、`FN-303` 可执行操作第 3 条、`FN-305` 理想完成态第 3 条、`GAP-305`；总开关语义见 `CR-08`。

**Q-304 交卷前是否允许查看/修改已作答题目？（已裁定 · A）**
- 结论：交卷确认打开后仍可回改答案；打开确认不冻结作答。
- 问题：交卷确认里「跳到首个未答」之后，能否继续改答案？
- 分歧：现行允许（对话框可关、答案仍可改，`ExamView.vue:884-890`）；严格考试制度一旦进入交卷流程就冻结。
- 候选方案：A 保持可回改；B 打开交卷确认即冻结，只有「继续作答」能解冻。
- 裁定 A 及理由：家用/小团队场景下误点交卷的代价太高，冻结会增加焦虑且不利于自查。
- 已落入正文：`FN-307` 可执行操作与理想完成态第 2 条、`OP-306`、§4.5 共同约束第 4 项。

**Q-305 多设备同时续考是否互斥？（已裁定 · B）**
- 结论：后开者只读，并提示该会话正在另一设备进行；显式选择在本机继续时才进入冲突合并。
- 问题：两台设备同时打开同一进行中会话，应互斥还是并行 + 冲突合并？
- 分歧：现行并行 + 冲突检测（BR-314）；互斥需要设备在线状态与租约。
- 候选方案：A 并行 + 冲突提示（**旧行为，已裁定 B 取代**）；B 后打开者进入只读并提示；C 租约制，先打开者独占。
- 裁定 B 及理由：成本低（只需在返回会话时回带「正在另一设备进行」的提示），能消除大部分「我改的怎么没了」。
- 已落入正文：`BR-314`、`FN-309` 理想完成态第 3 条、§6 联动表；与 `CR-23` 一致。

**Q-306 基础题库模式的抽题规则是否需要随机？（已裁定 · A）**
- 结论：顺序抽题 + 界面说明；随机应由用户显式选，不作为默认。
- 问题：不使用蓝图时，是顺序取前 N 题还是随机抽 N 题？
- 分歧：现行是顺序切片（`blueprint.py:32-33`、`practice_service.py:108`）；`REQUIREMENTS_TRACEABILITY.md:76` 明确「不把随机新增成产品承诺」。
- 候选方案：A 顺序；B 随机；C 按难度/题型均衡的确定性抽样。
- 裁定 A 及理由：家用场景重复抽同一批题反而有利于对比进步；随机应由用户显式选择而非默认。
- 已落入正文：`FN-311` 理想完成态。

**Q-307 「用时」以客户端时钟还是服务端时间为准？（已裁定 · C）**
- 结论：同时记服务端在线作答时长与墙钟时长（交卷时间 − 开考时间），报告两个都给并标注含义。
- 问题：报告里的耗时应来自客户端累加、服务端 `time_spent` 累加，还是 `completed_at - created_at`？
- 分歧：生产用服务端 `time_spent`（草稿同步时取 max 累加，`practice_repository.py:622-623`）；原型用「上限 − 剩余」反推（`pages/screens/exam.html` `buildReport`）。跨设备续考时两者会不一致。
- 候选方案：A 服务端 `time_spent`；B `completed_at - created_at`；C 两者都记，报告显示 B 并在详情里给 A。
- 裁定 C 及理由：墙钟时长反映真实耗时，服务端时长反映实际在线作答时长，两者都对用户有意义。
- 已落入正文：`BR-312`、`FN-308` 理想完成态第 2 条与可执行操作。

**Q-308 待复查标记是否参与交卷门槛？（已裁定 · B）**
- 结论：未答 > 0 **或**有待复查标记时，交卷都给警告；仅计数不够。
- 问题：还有「待复查」题未答时，交卷确认是否应比未答更强的警告？
- 分歧：现行只按未答数量警告（`ExamView.vue:335-340`）；待复查是用户主动标记的，语义上更接近「我没把握」。
- 候选方案：A 仅计数展示；B 未答 > 0 或有待复查时都给警告文案；C 有待复查时需二次确认。
- 裁定 B 及理由：不增加点击成本，但把用户的自我怀疑显式化。
- 已落入正文：`FN-307` 理想完成态第 1 条、`OP-306`。
