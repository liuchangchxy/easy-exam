## 1. 域定位与边界

模考域负责「按一份可复用的组卷配置，生成一次限时、闭卷、终结后一次性结算的考试」，并产出可回看的成绩报告。它与刷题域共用会话与作答内核（草稿同步、冲突合并、计时、判分），差异只在三处：**判分时机**（交卷后才结算）、**信息可见性**（交卷前不透题）、**组卷来源**（蓝图版本而非即时抽题）。

域内实体四类：

| 实体 | 说明 | 落点 |
|---|---|---|
| 考试档案（exam_profile） | 一份可复用的考试目标（名称/说明），本身不承载规则 | `exam_profiles` 表 |
| 蓝图版本（exam_blueprint） | 档案下的不可变组卷规则快照，`version_number` 自增 | `exam_blueprints` 表 |
| 模考会话（practice_sessions, mode=EXAM） | 一次具体考试，绑定 `blueprint_id` 与题目快照 | `practice_sessions` 表 |
| 成绩报告（result_json） | 交卷时一次性计算并落库的终局结果 | `practice_sessions.result_json` |

边界划分：

- **属于本域**：档案与蓝图的增改查、组卷、开始前确认、会话内计时/作答/标记/交卷、报告生成与回看、退出与草稿、重考。
- **不属于本域但强耦合**：判分算法本体（刷题域 `domain/learning/scoring.py`）、错题与 FSRS 写入（刷题域，本域只通过 `record_mistakes` 开关触发）、题库内容的编辑锁定（题库域，本域只产生锁定信号）。
- **不属于本域**：AI 解释、笔记、导入向导、趋势看板。模考报告中的知识点统计只消费题目版本上的标签快照，不新增标签体系。

## 2. 功能定义

### FN-301 模考中心

- **存在目的与场景**：模考的唯一工作台。用户在这里看「有没有没考完的」「有哪些考试档案可复用」「能直接从哪些题库开考」「以前考得怎么样」，并由此进入考试会话或蓝图编辑。
- **入口与适用条件**：主导航「模考」→ `/exams`。任何已登录用户可进入；页面内的可用动作依赖「至少一个可访问且题量 > 0 的题库」（`ExamCenterView.vue:349` `examBanks` 过滤 `question_count > 0`）。
- **可执行操作**：
  1. 查看并恢复/放弃未完成模考（OP-301）。
  2. 查看考试档案列表，进入蓝图编辑（FN-303）或开始（FN-305）。
  3. 从题库直接开始（不使用蓝图，FN-311 降级路径）。
  4. 新建考试档案——创建后立即打开该档案的蓝图编辑（OP-302）。
  5. 回看历史成绩报告（FN-308）。
  6. 无题库时跳转导入向导。
- **操作结果**（含数据与状态变化）：
  - 页面加载并行拉取题库、档案、`mode=EXAM` 的活跃会话（`ExamCenterView.vue:411-426`，`Promise.allSettled`）。
  - 新建档案：`POST /exams/profiles` 返回后 `profiles.unshift(profile)` 并打开蓝图抽屉（`ExamCenterView.vue:438-444`）。
  - 放弃会话：`POST /practice/sessions/{id}/abandon`，本地从 `activeSessions` 移除（`ExamCenterView.vue:513-515`）。
  - 任一请求失败：整页切换为失败态 + 「重试」按钮（`ExamCenterView.vue:56-60`）。
- **与其他功能的关系**：向上承接题库域的题库与题目；向下进入 FN-305 开始会话；向右联动 FN-303 蓝图编辑；历史报告入口联动 FN-308。
- **当前缺失与不合理之处**：
  1. **没有历史报告列表**。右栏「成绩报告」只有一句说明文案，没有任何列表与回看入口（`ExamCenterView.vue:148-151`）；`exams.py` 也没有「列出已完成会话/报告」的端点（仅 `/profiles`、`/sessions` POST、`/sessions/{id}/complete`）。已交卷会话只能靠手输 `/exam/{sessionId}` 打开。原型 `pages/screens/exams.html:780-797` 已有完整报告表格 + 回看对话框。
  2. **没有「重新考试」动作**。原型报告页顶栏有「再考一次」（`pages/screens/exam.html` 报告态顶栏），生产 `ExamCenterView.vue` 与 `ExamView.vue:172-174` 的报告操作只有「返回模考中心」。
  3. **开始入口未走统一活跃会话决策**。`beginExam` 直接 `startExam(...)`（`ExamCenterView.vue:493`），没有像今天页/题库工作区那样先查同模式活跃会话再弹「继续 / 结束并新建」（UX §7.3、§11.1 的统一入口只覆盖 `useStartStudy` 的调用点）。用户可以在已有一场未交卷模考时再开一场，造成会话堆积（UX §5.2「会话可无限增殖」在 EXAM 模式下仍未消除）。
  4. **加载失败是整页报废而非局部降级**。三个请求中任意一个 rejected 就连考试档案列表、题库列表一起隐藏（`ExamCenterView.vue:421,56-60`）。失败态与重试已具备（`REQUIREMENTS_TRACEABILITY.md:510`），但降级粒度仍是全有或全无。
  5. 空态出口不完整：`ExamView.vue:265-269` 的「这个考试档案没有题目」只有「返回模考中心」，没有原型的「去编辑蓝图」直达（原型 `pages/screens/exam.html` 空态）。
- **理想完成态**：
  1. 页面四块内容各自独立加载与失败：档案、题库、进行中、历史报告任一失败只替换自己那一块，其余可点。
  2. 历史报告成为正式区块（表格：交卷时间 / 考试档案 / 总分 / 正确率 / 状态 / 回看），点击打开 FN-308 的报告回看。
  3. 点「开始模考」时若已有 `mode=EXAM` 的活跃会话，先弹「继续 / 结束并新建 / 取消」；取消不产生新会话。
  4. 每份档案行提供「重新考试」快捷动作（用该档案当前蓝图版本开新会话，FN-310）。
  5. 无题库时「开始模考」禁用并附原因，与原型一致显示「先导入题目」。

### FN-302 考试档案管理

- **存在目的与场景**：把「我要考的那场试」固化成可复用模板，避免每次开考重配。
- **入口与适用条件**：模考中心「新建考试档案」按钮 / 空态「新建考试档案」。仅需登录，不要求题库存在（档案可以先于题库创建）。
- **可执行操作**：新建（名称必填、说明选填）、查看列表（含蓝图摘要：配额段数、总题数、负分）、删除/重命名（低频，当前未实现）。
- **操作结果**：`POST /exams/profiles` → `exam_profiles` 新行 → `list_profiles` 按 `created_at DESC` 返回并附带 `latest_blueprint`（`exam_repository.py:22-31`）。档案本身不含规则；无蓝图的档案在列表中显示「不使用蓝图」（`ExamCenterView.vue:75-78` `blueprintOf` 返回 null 时）。
- **与其他功能的关系**：档案是蓝图的容器；FN-305 开考时可选定档案；档案与蓝图是一对多（多版本）。
- **当前缺失与不合理之处**：
  1. 档案不可重命名、不可删除、不可复制（`exams.py` 只有 `GET /profiles`、`GET /profiles/{id}`、`POST /profiles`）。模板一旦建错只能废弃。
  2. 档案列表不显示「这份档案被几场进行中的模考引用」，用户无法判断能否安全改蓝图。
  3. 档案不记录适用考试体系/科目（SPEC §2.0.1 的「考试体系 + 科目」在模考侧无落点），跨考试体系的档案只能靠名称区分。
- **理想完成态**：档案支持重命名、编辑说明、复制（复制时连带最新蓝图版本）、删除（删除前校验无进行中会话引用它；有则拒绝并说明）。档案可挂到一个考试体系/科目上，用于模考中心按体系分组。

### FN-303 蓝图可视化编辑与版本绑定

- **存在目的与场景**：让用户按「题型 × 难度 × 章节/标签 × 数量」描述一份卷子的结构，并设定负分与是否记录错题。蓝图是组卷的唯一规则来源。
- **入口与适用条件**：档案行「蓝图编辑」按钮 / 右栏蓝图链接。每次打开按需拉取 `GET /exams/profiles/{id}/blueprint`，404 视为「尚无蓝图，从空开始」（`ExamCenterView.vue:533-538`）。
- **可执行操作**：
  1. 设负分（0–5，步长 0.5）。
  2. 增删配额段；每段设题型（单选/多选/判断/主观）、题数、难度（不限/1–5）。
  3. 保存 → `POST /exams/profiles/{id}/blueprint`，服务端 `version_number = MAX + 1`（`exam_repository.py:38`）。
  4. 带未保存修改关闭 → 二次确认「取消 / 放弃 / 保存」（`ExamCenterView.vue:287-303`、`385-390`）。
- **操作结果**：新蓝图版本写入 `exam_blueprints`，`latest_blueprint` 变为新版本；保存后 `profiles` 重新拉取，抽屉标题显示 `v{version_number}`（`ExamCenterView.vue:600-603`、`231`）。总题数为各段 count 之和（`ExamCenterView.vue:367`），≤ 0 时拒绝保存（`ExamCenterView.vue:580-583`）。
- **与其他功能的关系**：蓝图版本在开考时被会话绑定（BR-309）；组卷算法消费蓝图（FN-305）；`record_mistakes` 作为会话配置的回退值（BR-305）。
- **当前缺失与不合理之处**：
  1. **章节与标签在 UI 中不可配**。数据结构完整支持 `chapter_id` / `tags`（`blueprint.py:42-65`），`ExamCenterView.vue` 的 `blueprintSnapshot`/`blueprintSections` 也带着这两个字段，但渲染的配额行只有题型、数量、难度三个控件（`ExamCenterView.vue:247-262`），`chapter_id` / `tags` 永远是空串。EE-001 声称「蓝图根据章节按需筛选」已闭环（`REQUIREMENTS_TRACEABILITY.md:41`），但用户侧无法输入章节条件——能力存在而不可达。
  2. **没有分值配比**。SPEC §6 要求蓝图覆盖「题型和分值配比」；现行判分是每题 `score_ratio` 1.0/0.5/0.0 直接求和（`domain/learning/scoring.py:47-53`、`grading.py:7`），蓝图无法给某一段加权。报告也只能给出原始分，无法给出「按配比折算的百分制」。
  3. **`record_mistakes` 不在蓝图里配**。生产只在开考对话框提供一次性勾选（`ExamCenterView.vue:206-209`），蓝图层没有该字段；`record_mistakes_for_session` 的「蓝图回退」分支因此几乎不会命中（见 `practice_repository.py:691-726` 的配置优先、蓝图回退逻辑与 SPEC §4.1 的对应关系）。
  4. **蓝图没有导入模板入口**（见 FN-304）。
  5. **保存后没有版本历史视图**：`latest_blueprint` 只返回最新版（`exam_repository.py:43-56`），`get_blueprint(id)` 虽在仓储层存在，但 `exams.py` 没有暴露按 id 读历史版本的路由。用户改坏了无法回看上一版长什么样。
- **理想完成态**：
  1. 配额段可视化配置五维：题型、难度、章节（下拉，来自题库章节树）、标签（多选，来自题库标签）、题数；每段可设单题分值。
  2. 蓝图头部显示「总题数 / 客观题总分 / 主观题题数 / 负分 / 是否记录错题」五项实时汇总，保存前校验：总题数 > 0、各段题数之和与目标题量的关系明确、分值之和 > 0。
  3. 蓝图版本列表可查（版本号、保存时间、与该版本的差异摘要、被几场会话绑定），可「以此为基线新建版本」。
  4. 保存采用「新版本」语义，永不覆盖旧版本；旧版本仍可被已绑定它的历史会话读取。
  5. 编辑进行中时，若该档案已被某场未交卷模考绑定，页面顶部提示「已有 N 场进行中的模考使用 v{k}；保存会生成 v{k+1}，不影响进行中的考试」。

### FN-304 蓝图导入模板（低频）

- **存在目的与场景**：降低首次配置成本——从一份标准考试模板（如「单项选择题 50 + 多项选择题 20 + 判断 10 + 问答 2，负分 0.5」）出发改，而不是从零拖配额段。对应 SPEC §2.0.1「考试蓝图由用户可视化配置，也支持导入模板后修改」。
- **入口与适用条件**：蓝图编辑抽屉内的「从模板导入」；仅在档案尚无蓝图或用户主动触发时出现。模板来源为内置/用户上传的 JSON，AI 只能建议、必须用户确认（SPEC §2.3）。
- **可执行操作**：选择模板 → 预览将生成的配额段与负分 → 确认导入为一份新蓝图版本 → 继续手工修改。
- **操作结果**：写入一条新的 `exam_blueprints` 版本；导入不直接开考。
- **与其他功能的关系**：是 FN-303 的另一种写入路径；与 FN-311 的区别是导入后仍走蓝图组卷。
- **当前缺失与不合理之处**：**完全未实现**。`frontend/src/api/exams.js` 只有 `listProfiles / createProfile / saveBlueprint / getBlueprint` 四个方法，没有任何模板端点；`exams.py` 同样没有。SPEC §2.0.1 承诺的能力在生产与原型中均无入口。
- **理想完成态**：内置 3–5 个常见考试结构模板 + 支持上传 JSON 模板；导入前展示「将创建 v{k+1}，包含 N 个配额段、负分 X」的预览；模板校验失败（缺 sections、count 非正数、题型非法）时逐条列出原因且不写库。AI 建议蓝图走同一条确认路径，不单独开写入口。

### FN-305 组卷与开始前确认

- **存在目的与场景**：把蓝图（或题库）变成一份具体考试档案，并在开考前把「考什么、考多久、错题算不算」讲清楚。
- **入口与适用条件**：档案行「开始」/ 题库行「开始模考」/ 页头「开始模考」。前置条件：至少一个题量 > 0 的可访问题库（`ExamCenterView.vue:349,85,121`）；题库无题时按钮禁用并给原因。
- **可执行操作**：选择题库、选择蓝图（含「不使用蓝图」）、设题目数量、设时长（分钟）、勾选「记入错题」，确认开始。
- **操作结果**：
  - 前端把数量钳制在 `min(题库题量, 蓝图总题数)`（`ExamCenterView.vue:353-358`），非法时禁用提交并给出原因（`ExamCenterView.vue:359-365,482-489`）。
  - `POST /exams/sessions`（`exams.py:63-79`）→ 若带 `profile_id`，先取 `latest_blueprint` 解析出 `blueprint_id`，无蓝图则 404；随后走 `practice.start_session(...)`。
  - 组卷：有 `blueprint_id` 时 `select_questions_by_blueprint(candidates, blueprint, total_questions)`（`practice_service.py:95-100`），否则 `questions[:total_questions]`（`practice_service.py:108`）。
  - 会话落库：`total_questions = len(selected)`、`time_limit`、`exam_profile_id`、`blueprint_id`、题目快照 `questions_json`（含 `question_id/version_id/bank_id`）、`config_json`（含 `bank_ids`、`record_mistakes`）（`practice_service.py:119-132`）。
  - 空题库或无匹配时拒绝建会话，报「当前题库没有符合条件的题目」（`practice_service.py:109-118`）。
  - 成功后跳转 `/exam/{sessionId}`。
- **与其他功能的关系**：消费 FN-303 的蓝图版本；产出 FN-306 的会话；`record_mistakes` 决定 FN-308 报告后是否写复习队列。
- **当前缺失与不合理之处**：
  1. **开始前确认信息不完整**。对话框不显示「本场将考哪些题型各几题」「客观题总分多少」「负分如何计」，只显示题库题量与上限（`ExamCenterView.vue:188-211`）。用户无法在开考前核对蓝图是否被正确组卷。
  2. **蓝图组卷结果不可预览**。降级补齐（BR-310）静默发生：蓝图要 40 题而题库只匹配到 12 题时，`select_questions_by_blueprint` 直接补满到目标数（`blueprint.py:77-87`），开考对话框中没有任何「实际组出 N 题，其中 M 题为降级补入」的提示。
  3. **`record_mistakes` 勾选不落蓝图**：该值只进本次会话 `config_json`（`practice_service.py:126-127`），不开「记住这份档案的默认值」；下次从同一档案开考又回到默认 true。
  4. **时长上限 600 分钟是硬编码前端约束**（`ExamCenterView.vue:204`），后端 `time_limit` 无校验；`time_limit = 0` 时前端按「已用时长」显示（`ExamView.vue:18-19`），但 `start_exam` 允许 0，语义分裂。
  5. **没有「继续 / 结束并新建」决策**（同 FN-301 第 3 条）。
- **理想完成态**：
  1. 开始前确认区固定展示六项：题库与可组卷题量、蓝图版本号、按题型/难度的实际配额结果（含降级补入的题数与原因）、客观题总分与折算百分制、负分规则、是否记录错题。任一项与蓝图声明不一致时高亮并说明差异来源。
  2. 提供「预览考试档案」：开考前可看组出的题目清单（只显题号与题型，不显答案解析），确认后再开考。
  3. 「记入错题」的勾选可存为档案级默认值，下次开考预填。
  4. 已有同模式活跃会话时，先弹「继续 / 结束并新建 / 取消」。

### FN-306 考试会话（倒计时 / 答题卡 / 待复查标记 / 跳题）

- **存在目的与场景**：限时闭卷作答的单一页面。所有考试内交互都收敛在这一页，且这一页在交卷前绝不透露对错。
- **入口与适用条件**：`/exam/{sessionId}`。进入时服务端返回会话；若 `mode !== 'EXAM'` 重定向到刷题页；若已交卷直接渲染报告；若 `is_expired` 直接进入终结态（`ExamView.vue:986-1038`）。
- **可执行操作**：作答（选项点选 / 键盘 A–H 或 1–8 / 文本题输入）、上一题/下一题、答题卡跳题、标记待复查（F）、左右滑动手势切题（移动端）、交卷、退出。
- **操作结果**：
  - 倒计时：每秒 `elapsedSeconds += 1`，`remainingSeconds = time_limit*60 - elapsed`，与 `created_at` 校准取较大值（`ExamView.vue:1016-1019`）；≤ 300s 时计时器进入低时态（`ExamView.vue:17`）。无 `time_limit` 时改显「已用时长」。
  - 作答：改 `answers` → 立即写 localStorage → 400ms 防抖 `syncDraft`（`ExamView.vue:769-786,707-710`）。
  - 标记：`POST /sessions/{id}/toggle-flag`，返回后覆盖 `flags`（`ExamView.vue:794-805`）。
  - 答题卡：桌面为右侧常驻栏（`ExamView.vue:218-241`），≤768 收起为底部「移动作答卡」抽屉（`ExamView.vue:272-302`）；格子状态 = 当前 / 已答 / 未答 / 已标记。
  - 每 10 秒强制同步一次草稿（`ExamView.vue:879-881`）。
- **与其他功能的关系**：与刷题会话共用内核；差异由 `answersLocked`（`ExamView.vue:505`）与 `mode` 决定。
- **当前缺失与不合理之处**：
  1. **术语与 SPEC 不一致**：SPEC §3.2 写「待复查标记」，产品实现叫「标记 / flagged」。功能等价，但文档与界面不同词，跨册引用会错位。
  2. **`submitAttempt` 是死导入**（`ExamView.vue:376` 导入但从未调用）。单题提交路径（`POST /sessions/{id}/attempts`）在模考中不可达，意味着模考的全部判分依赖交卷时从 `answers_json` 反推（`practice_service.py:387-404`），任何未同步成功的作答都要靠这条兜底路径。
  3. **低时无提示音/无系统通知**：只剩 5 分钟、1 分钟时只有颜色变化（`ExamView.vue:17`），切到其他标签页时用户不会察觉。
  4. **倒计时是客户端时钟**：`elapsedSeconds` 只在 `onMounted` 用 `created_at` 校准一次（`ExamView.vue:1017-1018`），之后纯本地累加。设备休眠、时钟漂移、跨设备续考都会让客户端剩余时间与服务端 `_exam_expired` 判定（`practice_service.py:167-188`）偏离。
  5. **无 `time_limit` 的模考**没有明确的「不限时」表达，界面会显示「已用」但会话仍可被 `_check_exam_timeout` 之外的一切路径终结，语义模糊。
- **理想完成态**：
  1. 统一术语为「待复查」，界面文案与 SPEC 对齐；`F` 键与刷题的「标记薄弱」明确区分（UX §5.2 已指出两个 runner 的 `F` 语义互斥，需在模考侧固定为待复查）。
  2. 剩余 5 分钟 / 1 分钟给出页面内强提示（不限仅变色），并可选一声轻提示；配置项可关。
  3. 剩余时间以服务端为准：每次草稿同步响应回带 `server_now` 与 `remaining_seconds`，客户端据此校正，而不是只信本地累加。
  4. 不限时模考在顶栏明确写「不限时」，且交卷只能由用户主动触发（无自动交卷）。

### FN-307 交卷确认与自动交卷

- **存在目的与场景**：交卷是不可逆的终结动作，必须有二段确认；到点则必须自动收卷，且自动收卷也要让用户知道发生了什么。
- **入口与适用条件**：顶栏「交卷」按钮（`ExamView.vue:28-30`）；或倒计时归零自动触发（`ExamView.vue:874-878`）。
- **可执行操作**：打开交卷确认 → 查看已答/未答/待复查统计 → 「跳到首个未答」→ 取消或确认交卷。
- **操作结果**：
  - 交卷确认对话框展示三项统计与未答警告，未答 > 0 时不阻断、只警告，并提供「跳到第 N 题（首个未答）」（`ExamView.vue:325-347,884-890`）。
  - 确认交卷：`persistDraft(true)` → `completeSession` → 报告落入 `report`、清本地草稿、`switchTab` 到报告态（`ExamView.vue:812-870`）。
  - 倒计时归零：`submitExam(true)` 自动交卷（`ExamView.vue:874-878`）。
  - 服务端超时：`_check_exam_timeout` 在草稿同步、标记、单题提交前拦截，超时（限时 + 60s 宽限）抛 `EXAM_TIME_EXPIRED` → 409（`practice_service.py:190-192`、`practice.py:102-110`）。
  - 客户端进入 `syncExpired` 终结态：停所有自动重试、保留本机副本、只提供「以服务器已保存的答案交卷」的显式动作与二次确认（`ExamView.vue:630-667,304-323`）。
- **与其他功能的关系**：交卷成功即触发 FN-308 的报告计算与 BR-305 的错题结算。
- **当前缺失与不合理之处**：
  1. **二段确认不完整**。取消交卷的确认只有一层（`showSubmitConfirm` → `submitExam`），没有「交卷后不可撤销」的强确认副本；原型同样只有一层对话框，但生产在「过期后以服务器答案交卷」路径上才有真正的二段（`ExamView.vue:304-323`）。两条路径的确认强度不一致。
  2. **自动交卷的报告不带来源标记**。报告结构（`practice_service.py:474-495`）没有 `auto` / `submitted_at` / `deadline` 字段，用户事后无法区分「我手动交的」和「时间到被收的」。原型本有 `auto` 字段意图（`pages/screens/exam.html` `buildReport` 的 `auto: R.autoAt`），但 `R.autoAt` 从未被赋值，所以原型里这个区分也失效——回看时报告备注与考试档案回看理由都显示成手动交卷的版本。
  3. **自动交卷在设备离线时不可见**：`submitExam(true)` 失败会 `markPendingSubmit()`（`ExamView.vue:838`），只在重连/手动重试时恢复。若用户不再打开这个页面，这次自动交卷可能长时间停留在「本机待交卷」状态，而服务端其实已因超时拒绝写入。
  4. **60 秒宽限是硬编码**（`practice_service.py:188`、`question_repository.py:518`），既不可配置也无产品说明；用户看到的是「到点后还能再答一分钟」这种无解释行为。
- **理想完成态**：
  1. 交卷确认固定包含四行：已答 / 未答 / 待复查 / 本场规则摘要（负分、是否记错题），以及一句「交卷后不能再修改答案」。
  2. 有未答题时，「跳到首个未答」与「仍要交卷」并列为同级主动作，不把交卷按钮降级。
  3. 到点自动交卷时，先给一条不可忽略的锁定原因条（说明「题目已只读、答案以已保存版本为准、正在自动交卷」），再执行收卷；原因条在报告生成前不得消失。
  4. 报告必须记录 `submitted_at`、`deadline_at`、`auto_submitted` 三个字段；报告页与考试档案回看都据此显示「本场为到点自动交卷」。
  5. 宽限时长成为显式产品参数（默认 60s），在会话详情中可见。

### FN-308 成绩报告与历史回看

- **存在目的与场景**：交卷后的一次性结算，也是唯一允许展示对错的时刻；报告要能跨天回看且不随后续改题变化。
- **入口与适用条件**：交卷成功后的报告态；或从模考中心历史报告列表点「回看」（当前该列表不存在，只能直链 `/exam/{sessionId}`）。
- **可执行操作**：查看总分/正确率/已答/用时/对错分布；按题型统计；按知识点（标签）统计；查看错题与未答列表（含你的答案、正确答案、解析）；查看整卷回看；返回模考中心；重新考试。
- **操作结果**：
  - `complete_session` 在 active→completed 跃迁时：补算未提交的草稿答案 → `practices.complete` → 按绑定的蓝图版本 `grade_report` 算总分（负分在此生效）→ 统计 correct/partial/incorrect/unanswered、`type_stats`、`tag_stats`、逐题 `answers` → `save_result` 落库（`practice_service.py:371-499`）。
  - 已交卷会话再次 `complete`：逐字返回已存报告，不重算（`practice_service.py:379-380`、`practice_repository.py:667-689` 的 `result_json IS NULL` 条件保证只写一次）。
  - 重新打开会话：`GET /sessions/{id}` 返回 `report`（`practice_repository.get_session` 解析 `result_json`），前端直接渲染报告而非答题器（`ExamView.vue:990-999`）。
  - 报告加载失败：可重试（`ExamView.vue:962-979`）。
- **与其他功能的关系**：报告的错题列表是复习域的入口；`record_mistakes` 决定这些错题是否进入 FSRS 队列（BR-305）。
- **当前缺失与不合理之处**：
  1. **没有历史报告列表与导航入口**（同 FN-301 第 1 条）。这是 SPEC §3.2「成绩报告」与 UX §7.1「模考增加历史报告」之间最大的落地缺口：报告能算、能存、能直链回看，但用户在产品里找不到它。
  2. **没有整卷回看**。报告的错题区只列 `isExamReviewItem` 过滤出的题（`ExamView.vue:156-170,518`），答对的题不在报告里，用户无法复盘「我是怎么选对的」。原型有「查看考试档案」整卷只读回看（含正确项标记与逐题解析）。
  3. **总分口径未定义且不可配**。现行总分 = 各题 `score_ratio` 之和 − 答错题数 × 负分（`grading.py:4-9`），即「每题 1 分」的原始分；原型用百分制。报告既不说满分是多少，也不给配比折算。
  4. **负分可把总分压成负数**，报告直接显示负分，没有「最低 0 分」的产品规则说明。
  5. **`unanswered_count` 与主观题混算**：`unanswered_count = total_questions - len(attempts)`（`practice_service.py:426`），主观题只要填了字就会生成一条 `correctness=UNANSWERED` 的 attempt（`scoring.py:25-31`），于是「已答」包含主观题、「未答」不含，与正确率分母 `objective_total` 不是一套口径；报告页三组数字并列时容易误读。
  6. **知识点统计只有标签**：`tag_stats` 来自 attempt 上的 `tags`（`practice_service.py:435-439`），没有章节维度；真实生产中章节树基本为空（UX §3），但产品定义上「知识点统计」应同时支持章节与标签。
  7. **已放弃会话再次进入时显示「报告不可用」**：`onMounted` 对 `is_completed` 且无 `report` 的会话一律走 `reportLoadFailed`（`ExamView.vue:990-999`），而放弃会话正是 `is_completed=1, report=NULL`（`practice_repository.py:139-148`）。用户看到的是「加载失败 + 重试」，而重试永远不可能成功——放弃态被伪装成故障态。
- **理想完成态**：
  1. 模考中心常驻「历史报告」表格（交卷时间 / 考试档案 / 总分·满分 / 正确率 / 用时 / 状态 / 回看），支持按考试档案与时间筛选；点「回看」进入只读报告页。
  2. 报告页固定七区：总分头（总分、满分、折算百分制）、四计数（对/部分得分/错/未答）、正确率与用时、题型统计、知识点统计（章节 + 标签双维）、错题与未答列表、整卷回看。
  3. 整卷回看为只读纸面：逐题显示你的作答、正确答案、对错标记与解析；明确标注「答案与解析按交卷时保存的结果展示，不会因为重新组卷或后续改题而改变」。
  4. 总分口径写进报告：同时给出原始分、满分与百分制折算；负分导致负分时显示负分并说明规则，是否设 0 分下限由 Q-303 裁定。
  5. 报告区分「手动交卷 / 到点自动交卷 / 超时后以服务器答案交卷」三种来源，并在考试档案回看理由里复述。
  6. 已放弃会话再次进入时显示「本场已放弃，未计入成绩」，提供「重新考试」，绝不显示重试按钮。

### FN-309 退出、暂存草稿与多设备续考

- **存在目的与场景**：考试可以被安全打断——刷新、关机、换设备都不丢已答内容，也不产生第二份互相覆盖的真相。
- **入口与适用条件**：顶栏「退出」、浏览器刷新/关闭、`onBeforeUnmount`。
- **可执行操作**：请求退出 → 选择「继续 / 退出（保留进度）/ 退出（放弃）」；刷新或换设备后从「未完成的模考」继续。
- **操作结果**：
  - 退出：先弹确认，确认后 `persistDraft(true)` 再离页（`ExamView.vue:402-406,1046-1055`）。
  - 本地草稿：`easyexam_exam_draft:{sessionId}:{userKey}` 作用域的 localStorage，存 answers/flags/currentIndex/timeSpent/pendingSubmit（`ExamView.vue:593-607`、`domain/exam.js:124-148`）；旧的无用户作用域键在下次写入时迁移删除（`ExamView.vue:586-591,605`）。
  - 断点恢复：合并服务端 answers 与本地草稿，`draftBase` 取服务端最后观察值，使跨设备差异能被识别为冲突而非静默覆盖（`ExamView.vue:1002-1015`）。
  - 恢复后：若本机有未同步修改且在线，立即 `persistDraft()`（`ExamView.vue:1032-1035`）；若上次有 pendingSubmit 且在线，恢复交卷（`ExamView.vue:1028-1031`）。
  - 冲突：服务端保留已存值并把本机值报为冲突（`practice_repository.py:547-575`），前端显示「保留服务器 / 使用本机」两个后果可分辨的按钮（`ExamView.vue:55-70,546-567`）。
  - 离线：显示离线横幅 + 手动重试，计时不暂停（`ExamView.vue:51-54,669-673`）。
- **与其他功能的关系**：与刷题会话共用同一套草稿内核；差异在模考不允许交卷前泄露反馈。
- **当前缺失与不合理之处**：
  1. **退出确认的文案与行为相反，且只有一个出口**。对话框标题用「放弃」、正文用「放弃这场模考」（`ep.exam.abandon*`），按钮只有「取消（实为继续）」和「退出」；而「退出」的实际行为是保留进度（`handleConfirmExit` → `persistDraft(true)` + `doExit`）。UX §5.2 明确点名过这条（「退出文案与行为相反」），§9–§14 的实施记录未涉及，原型已改为三出口（继续 / 退出（保留进度）/ 退出（放弃））。
  2. **「放弃」只能从模考中心发起**。会话内没有「放弃这场考试」的动作；用户若在会话内想作废重来，只能退出后去模考中心点「放弃考试」。
  3. **本地草稿无过期与无跨设备清理**：`pendingSubmit` 标记会一直留着直到某次重试成功；本地草稿在会话终结后由 `clearLocalExamDraft` 清理（`ExamView.vue:609-617`），但若用户清理了站点数据，服务端 answers 仍是唯一真相，`draftBase` 归零，历史跨设备差异不再可检测。
  4. **多设备同时续考没有互斥**：两台设备可以同时打开同一会话并交替提交，靠冲突检测兜底；没有「这场考试正在另一台设备上进行」的提示。
- **理想完成态**：
  1. 退出确认三个后果明确的动作：继续（关闭对话框回到当前题）、退出（保留进度，会话留在「未完成的模考」）、放弃（结束本场，不计成绩，需再确认一次）。
  2. 会话内提供「放弃这场考试」入口，与模考中心的放弃走同一接口与同一确认。
  3. 换设备/新标签页打开同一进行中会话时，页面顶部提示「这场模考正在另一台设备上进行；继续作答将以本机答案为准」，并给出「只看不动」的只读选项（低频）。
  4. 本地草稿在会话进入 completed/abandoned 后立即清除；`pendingSubmit` 在服务端返回报告或明确超时后清除，不得无限残留。

### FN-310 重新考试（低频）

- **存在目的与场景**：考完一场后立刻用同一配置再考一遍，是模考的高频复访动作。
- **入口与适用条件**：报告页顶栏；或模考中心档案行。
- **可执行操作**：点击「重新考试」→ 用该档案当前最新蓝图版本开新会话 → 进入新考试会话。
- **操作结果**：新 `practice_sessions` 行，新 `blueprint_id`，全新题目快照；旧报告原样保留。
- **与其他功能的关系**：等价于 FN-305 的快捷路径，跳过设置对话框。
- **当前缺失与不合理之处**：生产未实现（`ExamView.vue:172-174` 报告操作只有「返回模考中心」；`ExamCenterView.vue:81-88` 档案行只有「蓝图编辑/开始」）。原型已有「再考一次」，但其实现是「用同一题库、同一题量、同一时长重开」，且 `pages/screens/exam.html` 的 `again()` 直接以 `R.paper.length` 为总量，不看蓝图当前总题数——蓝图改版后重考的题量不会跟着变。
- **理想完成态**：报告页与档案行都提供「重新考试」；重考前用 FN-305 的开始前确认信息做一次轻量确认（题库、蓝图版本、题量、时长、是否记错题），确认后开新会话；旧会话与旧报告不受影响。

### FN-311 无蓝图时的降级：基础题库模式（低频）

- **存在目的与场景**：没配蓝图也要能模考。SPEC §2.4 明确「未配置考试蓝图时使用基础题库模式」。
- **入口与适用条件**：档案无蓝图（`blueprintOf` 返回 null，`ExamCenterView.vue:392-397`）或在设置对话框选「不使用蓝图」。
- **可执行操作**：直接按题型/标签/难度抽题开考。
- **操作结果**：`blueprint_id` 为空 → `questions[:total_questions]`（`practice_service.py:108`）；报告仍完整，只是没有配比约束。
- **与其他功能的关系**：是 FN-305 的退化分支；不应报错。
- **当前缺失与不合理之处**：
  1. 生产在档案列表把无蓝图显示为「不使用蓝图」、在设置里作为选项，行为已可用；但**没有任何地方说明基础题库模式的抽题规则**（是否随机、是否按题型均衡、难度如何分布），用户无法预期会抽到什么。
  2. `select_questions_by_blueprint` 在 `sections` 为空时走 `candidate_questions[:total_questions]`（`blueprint.py:32-33`），是顺序切片而非抽样；同一蓝图两次开考抽到同一批题。SPEC 未规定随机性（`REQUIREMENTS_TRACEABILITY.md:76` 明确「不把随机新增成产品承诺」），但产品定义上应给出确定且可说明的规则。
- **理想完成态**：基础题库模式的组卷规则显式写清（默认按题库既有顺序取前 N 题，不承诺随机；如需随机由后续 Q 裁定并在界面说明）；设置对话框在该模式下提示「不使用蓝图时按题库顺序抽取前 N 题」。

### FN-312 模考进行中的题库内容锁定（低频，跨域）

- **存在目的与场景**：考试进行中，被考到的题目不能改答案/解析，否则这场考试的公平性与报告的可复现性都被破坏。
- **入口与适用条件**：任何用户存在 `mode=EXAM` 且 `is_completed=0` 且未超时的会话时，自动生效。
- **可执行操作**：题库管理员/编辑者对被考到的题目尝试编辑、改章节/标签、移动、复制、归档、删版本——应被拒绝并说明原因。
- **操作结果**：
  - 读侧脱敏：活动模考涉及的题目在 `get_for_user` / `list_for_bank` / `list_versions` 中 `answer`、`explanation` 被清空（`question_repository.py:148-162,410-411,1286-1298,647-660`）；列表行带 `locked_by_active_exam` 标记（`question_repository.py:573,745`）。
  - 写侧拦截：`create_next_version` 对活动模考题目抛 `PermissionError`（`question_repository.py:787`）；批量维护整批拒绝（SPEC §2.0.1）。
  - 锁定集合按「会话 `questions_json` ∩ 未超时」计算，超时（限时 + 60s）后不再锁定（`question_repository.py:510-535`）。
- **与其他功能的关系**：本域只产生信号，锁定执行在题库域。
- **当前缺失与不合理之处**：
  1. **锁定口径三套且读写不一致**：读模型多数调用传 `user_id`（按用户锁定），写拦截（`question_repository.py:787`）与部分列表标记（`:714-715,745`）用不带 `user_id` 的全局集合。结果是：**别人正在进行的一场模考，可以阻断你编辑共享题库里的同一道题**。UX §5.1 已点过「锁定有三套定义」，§9–§14 未收口。
  2. **锁定原因不可见**：编辑被拒时只拿到 `PermissionError` 文案，不说「这道题正在被哪场模考使用、预计何时解除」。
  3. **归档与模考锁定的优先级没有产品规则**：`is_deleted` 题目被拒绝编辑（`question_repository.py:784-786`）与模考锁定拒绝是两条独立分支，错误信息可能误导。
- **理想完成态**：统一为一条规则——「题目被任一会话（不论归属谁）引用即锁定，因为题目版本是共享实体」；编辑被拒时给出结构化原因（题目名、引用会话数、最早可能的解除时间）；题库工作区在题目行与批量条上显示统一的锁定徽标与同一套 tooltip 文案；超时解锁的时间规则（限时 + 60s）在产品文档中写明。

### 操作与交互（OP-3xx）

**OP-301 恢复或放弃未完成模考。** 模考中心「未完成的模考」区列出所有 `mode=EXAM` 且 `is_completed=0` 的会话，每行显示考试档案名、已答/总数、剩余时长、「记入错题」标记，以及「继续答题」与「放弃考试」两个动作。
- 「继续答题」→ 跳 `/exam/{sessionId}`，服务端 answers 与本地草稿合并后恢复（FN-309）。
- 「放弃考试」→ 弹确认（显示考试档案名与已答进度）→ 确认后 `POST /sessions/{id}/abandon`，该行从列表消失；取消则不动。
- 该区在无未完成会话时整区隐藏（`ExamCenterView.vue:26` `v-if="activeSessions.length"`）。
- 异常出口：abandon 失败时错误信息进入页内 notice，行不消失，可重试。

**OP-302 新建档案并立即配置蓝图。** 模考中心「新建考试档案」→ 填名称（必填）与说明（选填）→ 「创建考试档案」。
- 成功：对话框关闭，档案进入列表首位，蓝图编辑抽屉自动打开并加载该档案（404 视为空蓝图）。
- 失败：错误信息显示在对话框内，档案不创建，可重试。
- 带未保存修改关闭蓝图抽屉：弹「取消 / 放弃 / 保存」三选一（`ExamCenterView.vue:287-303`）。

**OP-303 打开与保存蓝图。** 「蓝图编辑」入口（档案行或右栏链接）→ 拉取该档案最新蓝图版本 → 抽屉内编辑 → 「保存蓝图」或「取消」。
- 保存：总题数 ≤ 0 时拒绝并提示；成功后 `version_number + 1`，抽屉标题版本号刷新，档案列表摘要刷新。
- 取消/关闭（Escape/遮罩）：有未保存修改时先弹丢弃确认；无修改直接关。
- 保存中禁用保存与关闭按钮，避免重复提交产生多个版本。

**OP-304 开始一场模考。** 「开始」→ 模考设置对话框 → 选题库/蓝图/题量/时长/是否记错题 → 「开始模考」。
- 题量超出 `min(题库题量, 蓝图总题数)` 时提交按钮禁用，并在输入框旁给出「上限为题库题量 N」或「这个题库只有 N 题，请把题目数量改到 1 到 N 之间」。
- 时长非 1–600 的整数时提交被拒并提示。
- 成功：对话框关闭，跳考试会话页；失败：错误显示在对话框内，可重试。
- 异常出口：所选蓝图已被删除（404「exam blueprint not found」）时提示重新选择蓝图，不静默退化为无蓝图。

**OP-305 考试会话内的作答与导航。** 选项点选 / 键盘 A–H 或 1–8（选项题）/ 文本框输入（主观题）；「上一题 / 下一题」；答题卡格子跳题；移动端左右滑动手势；`F` 切换待复查。
- 每次作答立即写本机草稿，400ms 防抖后同步服务端；每 10 秒强制同步一次。
- 顶栏常显倒计时（或已用时长），`≤ 300s` 进入低时态。
- 对话框或作答卡抽屉打开时，除 Escape 外所有快捷键挂起（`ExamView.vue:902-904`）。
- 异常出口：同步失败（网络）→ 离线横幅 + 手动重试，作答不丢；同步失败（超时 409）→ 进入终结态（OP-307）。

**OP-306 交卷。** 顶栏「交卷」→ 交卷确认对话框 → 「跳到首个未答」或「交卷」。
- 对话框展示已答/未答/待复查三项统计；未答 > 0 时给警告但不阻断。
- 「交卷」→ 先同步草稿，成功后调 complete；成功后清本机草稿并切到报告态。
- 异常出口：草稿同步失败 → 保留本机副本并标记待交卷，不拿服务端旧草稿交卷；有未解决的跨设备冲突时拒绝交卷并要求用户先选择保留哪一版。

**OP-307 到点与超时后的收卷。** 倒计时归零 → 客户端自动交卷；服务端超时（限时 + 60s）后拒绝一切写入并回 `EXAM_TIME_EXPIRED`。
- 客户端收到 `EXAM_TIME_EXPIRED`：停掉所有自动重试，显示终结横幅（含未能提交的题号清单），只保留一个显式动作「以服务器已保存的答案交卷」，且该动作需二次确认。
- 交卷成功后：横幅消失，进入报告态，本机未提交的答案仍留在本机（明确告知不计入成绩）。
- 重新打开一个已超时会话：直接进入终结态，不重放本机草稿。

**OP-308 回看历史报告。** 模考中心「历史报告」表格 → 「回看」→ 只读报告页（当前该表格不存在，见 GAP-301）。
- 报告页可看总分头、四计数、正确率与用时、题型统计、知识点统计、错题与未答列表、整卷回看。
- 「返回模考中心」回到列表；「重新考试」开新会话（FN-310）。
- 异常出口：报告缺失或读取失败时可重试；若会话状态为 `abandoned`，显示「本场已放弃，未计入成绩」而非重试（GAP-302）。

## 3. 业务规则（BR-3xx）

**BR-301 交卷前不透题。** 模考会话未交卷时，任何接口都不得返回标准答案、官方解析或对错判定。
证据：`practice_service.py:307-318`（`get_session` 对 EXAM 未完成会话删除题目级 `answer`/`explanation`，并把 answers 收敛到 `answer`/`user_answer` 两个键）、`practice_service.py:253-261`（`submit_attempt` 对 EXAM 返回 `feedback_available: False`）、`question_repository.py:647-660,1286-1298`（题库侧读模型同步脱敏）。引用：SPEC §3.2「模考交卷前不透露对错和标准答案」。

**BR-302 交卷后答案与解析可见，且绑定交卷时快照。** 交卷后报告中的正确答案与解析取交卷时刻会话快照解析出的题目版本，不随后续改题变化。
证据：`practice_service.py:379-380`（已交卷会话逐字返回已存报告）、`practice_repository.py:667-689`（`save_result` 只在 `result_json` 为空时写入）、`practice_service.py:194-213`（会话按 `questions_json` 的 `version_id` 解析题目，题目被移动/归档不影响已开始会话）。引用：SPEC §3.3「历史作答绑定原版本」。

**BR-303 判分规则由考试配置决定。** 支持标准得分、部分得分与负分三种规则，可按场次配置。
证据：`domain/learning/scoring.py:47-53`（MULTI 漏选 `PARTIAL` / `score_ratio=0.5`，`grading.py:4-9`（负分）。引用：SPEC §3.2「判分规则可按考试配置：标准得分、部分得分、负分」。

**BR-304 负分只罚答错，不罚未答与主观题。** `grade_report` 只对 `correctness == "INCORRECT"` 的作答计负分；未答（UNANSWERED）与主观题（`scoring.py:25-31` 恒为 UNANSWERED）不计负分。

## 4. 数据关系与状态变化

### 4.0 状态定义（ST-3xx）

**ST-301 会话状态 `status`。** `practice_sessions.status ∈ {active, completed, abandoned}`；`is_completed` 是派生列（`active → 0`，其余 `→ 1`）。迁移 20 引入，历史 `is_completed=1` 行回填为 `completed`（UX §11.1）。
- `active`：可读可写，是唯一允许作答的状态。
- `completed`：终局。有 `completed_at` 与 `result_json`；一切写入被拒（BR-308）。
- `abandoned`：终局。无报告；一切写入被拒；**不得再被 complete 改写**（GAP-303）。
- 查询口径：`list_active_sessions` 只返回 `is_completed = 0` 的行，因此 `abandoned` 不出现在「未完成的模考」里。

**ST-302 派生状态 `is_expired`。** 非持久字段，`GET /sessions/{id}` 时按 `created_at + time_limit*60 + 60s` 计算（`practice_service.py:298,167-188`）。为真时：客户端进入只读终结态，服务端拒绝草稿/标记/单题提交。它不改变 `status`，也不解锁题库锁定（FN-312 用同一公式）。

**ST-303 交卷来源 `submitted_via`。** 取值 `manual` / `auto_deadline` / `expired_server_answers`。当前报告不记录该字段（GAP-315）；理想态由 `complete_session` 在写入 `result_json` 时一并落库。

**ST-304 蓝图版本状态。** `version_number` 从 1 起自增，只增不改不删。对用户可见的只有「最新版」；历史版本文档上存在（`exam_blueprints` 行）但无读取入口（GAP-313）。会话按 `blueprint_id` 固定引用某一版，该引用在会话生命周期内不可变。

**ST-305 报告状态。** `result_json` 为空 = 未交卷或已放弃；非空 = 已交卷。`save_result` 的 `WHERE result_json IS NULL OR ''` 保证只写一次，因此「报告已存在」本身就是终态标记（`practice_repository.py:667-689`）。

**ST-306 客户端本地态。** `pendingSubmit`（有待交付的交卷）、`syncExpired`（服务端已宣告超时，终态）、`draftConflicts`（有未裁决的跨设备冲突）、`offlineRetryAvailable`。四者都只影响本机交互，不改变服务端状态；刷新后 `pendingSubmit` 由本地草稿恢复，其余重置。

### 4.1 实体关系

```
exam_profiles (1) ──< exam_blueprints (N, version_number 自增)
      │                        │
      │                        └── 被 practice_sessions.blueprint_id 绑定（不可变引用）
      └──< practice_sessions (N, mode='EXAM')
                 │
                 ├── questions_json: [{question_id, version_id, bank_id}]  （开考时快照）
                 ├── answers_json / flags_json / current_index / time_spent （草稿）
                 ├── config_json: {bank_ids, record_mistakes}
                 └── result_json: 成绩报告（交卷时一次性写入）
```

### 4.2 模考会话状态机

```
                 ┌──────────── start_session ────────────┐
                 ▼                                       │
            ┌─────────┐   persistDraft / toggleFlag      │
            │ active  │◀──────────────────────────────────┘
            └────┬────┘
                 │
   ┌─────────────┼──────────────────┬─────────────────────┐
   │ complete    │ 倒计时归零       │ abandon             │ _exam_expired
   ▼             ▼                  ▼                     ▼
┌───────────┐ ┌───────────┐    ┌───────────┐        ┌──────────────┐
│ completed │ │ completed │    │ abandoned │        │ expired(派生)│
│ (有报告)  │ │ (auto=1)  │    │ (无报告)  │        │ 只读·待显式  │
└───────────┘ └───────────┘    └───────────┘        │ 交卷         │
      │              │                  │           └──────────────┘
      └──────────────┴──────────────────┴──▶ 拒绝一切写入（BR-308）
```

- `status` 三值：`active` / `completed` / `abandoned`（迁移 20 引入，`is_completed` 为派生列）。
- `is_expired` 不是持久状态，是 `get_session` 时的派生字段（`practice_service.py:298`）。
- 允许的跃迁：`active → completed`（手动或自动）、`active → abandoned`、`active → expired(派生) → completed`（仅显式动作）。
- **不允许但当前可行的跃迁**：`abandoned → completed`（GAP-303）。

### 4.3 蓝图版本状态

`v1 → v2 → v3 …`，每次 `save_blueprint` 自增；旧版本永不覆盖。会话按 `blueprint_id` 固定引用某一版；`latest_blueprint` 只影响「下一次开考」。

### 4.4 关键状态变化明细

| 动作 | 写入 |
|---|---|
| 开始模考 | `practice_sessions` 新行（active）、`questions_json` 快照、`config_json` |
| 作答/切题/标记 | `answers_json` / `current_index` / `flags_json` / `time_spent`（取 max）、`updated_at` |
| 交卷 | `is_completed=1`、`status='completed'`、`completed_at`、`result_json`、`score`、`time_spent`；并按 `record_mistakes` 写错题与 FSRS |
| 放弃 | `is_completed=1`、`status='abandoned'`、`updated_at`（不写报告） |
| 保存蓝图 | `exam_blueprints` 新行（`version_number+1`） |

## 5. 权限规则（PR-3xx）

**PR-301 只能对有权访问的题库开考。** `start_session` 对每个目标题库走 `banks.get_for_user(bank_id, user_id)`，拿不到即 404「question bank not found」（`practice_service.py:79-84`）。共享题库的普通成员可以开考（只读成员不阻断考试）。

**PR-302 只能操作自己的会话。** 所有会话读写都带 `user_id` 条件（`practice_repository.py:521,637,657-666,690`）；他人会话 id 一律按不存在处理（404），不区分「不存在」与「无权限」。

**PR-303 蓝图与档案按用户隔离。** `latest_blueprint` / `get_blueprint` / `save_blueprint` 都 JOIN `exam_profiles` 校验 `p.user_id`（`exam_repository.py:35,44-51,59-66`）。蓝图不跨用户共享——这是与「共享题库」的不对称点：A 共享题库给 B，B 不能直接用 A 的考试档案组卷。

**PR-304 模考开始不要求题库编辑权。** 只读成员（VIEWER）可开考、可作答、可交卷；编辑权只影响 FN-312 的题库内容维护。

**PR-305 报告只对自己可见。** `result_json` 随会话行返回，受 PR-302 约束；多用户之间无法读取彼此模考成绩（SPEC §8「多用户之间无法读取彼此的学习记录」）。

**PR-306 题库内容锁定是全局信号，不是个人权限。** 活动模考对题目的锁定不按用户过滤（`question_repository.py:787` 等处），因此它覆盖共享题库的所有编辑者——这是产品取舍（题目版本是共享实体），但必须在界面上说明，否则会被感知为越权（见 GAP-309）。

## 6. 跨域与跨页联动

## 9. 未决问题（Q-3xx）

**Q-301 总分口径：原始分还是百分制？**
- 问题：报告应显示「每题 1 分求和（可负）」还是「按蓝图配比折算的百分制」？
- 分歧：生产是原始分（`grading.py:7`），原型是百分制（`pages/screens/exam.html` `score = correct/total*100`）；SPEC §3.2 只说「总分」，§6 说「分值配比」但未定义口径。
- 候选方案：A 只给原始分；B 只给百分制；C 两者都给（原始分 + 满分 + 折算）。
- 推荐与理由：C。原始分保留负分与部分得分的精度，百分制便于跨考试档案比较；且 C 不需要改判分内核，只改报告呈现。
- 未裁定时的默认行为：继续显示原始分，但在报告头部补一行「满分 N」与折算百分制。

**Q-302 负分是否存在 0 分下限？**
- 问题：负分把总分压到负数时，报告显示负分还是钳到 0？
- 分歧：现行实现会显示负分（`grading.py:9` 无钳制）；部分考试制度（如高考）不允许负总分。
- 候选方案：A 不设下限；B 全局钳到 0；C 蓝图级开关 `floor_at_zero`。
- 推荐与理由：C。默认不设下限（保持可解释），需要时按档案开启。
- 未裁定时的默认行为：不钳制，报告照显负分并在规则摘要里说明「负分无下限」。

**Q-303 `record_mistakes` 的默认值与存放层级？**
- 问题：模考错题是否进复习，默认是真是假？配置放会话级还是档案/蓝图级？
- 分歧：生产默认 true 且只在会话级（`ExamCenterView.vue:339`、`practice_service.py:126-127`）；蓝图级回退字段存在但 UI 不可配（`practice_repository.py:691-726`）。SPEC §4.1 只说「由考试配置决定」。
- 候选方案：A 保持会话级默认 true；B 蓝图级可配默认值，会话级可覆盖；C 全局实例设置。
- 推荐与理由：B。与「蓝图是考试配置的载体」一致，且避免每次开考重勾。
- 未裁定时的默认行为：保持现状（会话级、默认 true），但在开始前确认信息里显式显示本场取值。

**Q-304 交卷前是否允许查看/修改已作答题目？**
- 问题：交卷确认里「跳到首个未答」之后，能否继续改答案？
- 分歧：现行允许（对话框可关、答案仍可改，`ExamView.vue:884-890`）；严格考试制度一旦进入交卷流程就冻结。
- 候选方案：A 保持可回改；B 打开交卷确认即冻结，只有「继续作答」能解冻。
- 推荐与理由：A。家用/小团队场景下误点交卷的代价太高，冻结会增加焦虑且不利于自查。
- 未裁定时的默认行为：保持可回改。

**Q-305 多设备同时续考是否互斥？**
- 问题：两台设备同时打开同一进行中会话，应互斥还是并行 + 冲突合并？
- 分歧：现行并行 + 冲突检测（BR-314）；互斥需要设备在线状态与租约。
- 候选方案：A 并行 + 冲突提示（现状）；B 后打开者进入只读并提示；C 租约制，先打开者独占。
- 推荐与理由：B。成本低（只需在 `get_session` 回带 `active_device` 提示），能消除大部分「我改的怎么没了」。
- 未裁定时的默认行为：保持 A。

**Q-306 基础题库模式的抽题规则是否需要随机？**
- 问题：不使用蓝图时，是顺序取前 N 题还是随机抽 N 题？
- 分歧：现行是顺序切片（`blueprint.py:32-33`、`practice_service.py:108`）；`REQUIREMENTS_TRACEABILITY.md:76` 明确「不把随机新增成产品承诺」。
- 候选方案：A 顺序；B 随机；C 按难度/题型均衡的确定性抽样。
- 推荐与理由：A + 界面说明。家用场景重复抽同一批题反而有利于对比进步；随机应由用户显式选择而非默认。
- 未裁定时的默认行为：顺序抽取，并在设置对话框说明。

**Q-307 「用时」以客户端时钟还是服务端时间为准？**
- 问题：报告里的耗时应来自客户端累加、服务端 `time_spent` 累加，还是 `completed_at - created_at`？
- 分歧：生产用服务端 `time_spent`（草稿同步时取 max 累加，`practice_repository.py:622-623`）；原型用「上限 − 剩余」反推（`pages/screens/exam.html` `buildReport`）。跨设备续考时两者会不一致。
- 候选方案：A 服务端 `time_spent`；B `completed_at - created_at`；C 两者都记，报告显示 B 并在详情里给 A。
- 推荐与理由：C。B 反映真实墙钟时长，A 反映实际在线作答时长，两者都对用户有意义。
- 未裁定时的默认行为：以服务端 `time_spent` 为准（现状）。

**Q-308 待复查标记是否参与交卷门槛？**
- 问题：还有「待复查」题未答时，交卷确认是否应比未答更强的警告？
- 分歧：现行只按未答数量警告（`ExamView.vue:335-340`）；待复查是用户主动标记的，语义上更接近「我没把握」。
- 候选方案：A 仅计数展示；B 未答 > 0 或有待复查时都给警告文案；C 有待复查时需二次确认。
- 推荐与理由：B。不增加点击成本，但把用户的自我怀疑显式化。
- 未裁定时的默认行为：保持 A。
