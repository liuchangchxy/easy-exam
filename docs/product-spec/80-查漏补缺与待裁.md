### 1.2 六类处置的含义与施工时机

| 处置 | 含义 | 什么时候做 |
|---|---|---|
| **本期修复** | 真实产品缺陷：会让用户静默丢数据、得到假结果、走进死路，或与已裁定规则直接冲突 | P2/P3 之前必须修完；其中数据丢失红线最优先（见 §2） |
| **本期补齐** | 已承诺但未兑现的必要能力与交互（有入口无出口、有设置无生效、有样式无 DOM） | 与「本期修复」同一批施工 |
| **体验改善** | 产品范围内的体验问题，不影响闭环与规则正确性 | 可随后续迭代，不阻塞 P2/P3 启动 |
| **可选/延期** | 可选增强，或已裁定本期不做 | 按需排期；「本期不做」的部分同时登记在 §8.1 |
| **P3 原型** | 原型自身缺陷（按钮未接线、文案失据、状态机与生产不一致） | P3 修原型时处理；**不得**因原型缺陷扩大产品定义 |
| **工程/部署** | 工程债、技术债、部署问题（命名债、旧构建观测、死代码清理、无唯一索引） | 随 P5/P6 与部署项处理 |

### 1.3 原 P0/P1/P2 优先级去哪了

原分级（P0×14 / P1×60 / P2×91）记录的是「发现时的严重度」，其中 14 条 P0 已在 §2 就地标注其处置。**优先级不再作为分类维度**，理由是：一条缺口该不该本期做，取决于它是缺陷还是增强、是否与已裁定规则冲突，而不是它被发现时有多疼。施工顺序见 §9。

### 6.1 判分与评级语义（7 条）

| 编号 | 最终规则 | 理由 |
|---|---|---|
| `Q-201` | 单选/判断**默认明确提交**（选择后必须点提交才判分）；另提供「点选即判」**可选模式**，用户在设置里切换。**明确不做** 800ms 内可修改的模糊判分窗口 | 明确提交给用户反悔机会，且不依赖计时魔法；即判提升节奏但只作可选项；模糊窗口会让「什么时候定的型」变得不可解释 |
| `Q-202` | 已清除错题**不出队**：清除只改错题状态，不删 FSRS 卡、不移出调度；以「巩固」低优先级原因继续出现在到期队列 | FSRS 的意义就是抗遗忘；因错题被清除就让用户的复习进度作废，违背产品主线 |
| `Q-203` | 交卷确认里列出未评级题数并给「回去评级」入口；不强制逐题评级，不静默 | 透明且不加强制步骤；强制逐题会让快速刷一组变重 |
| `Q-204` | 到期 = `due_at <= now 且未被当前用户斩杀`，全产品唯一口径；队列/今日/趋势/推荐/计划共用同一个服务端方法；错题/薄弱/巩固是叠加**原因标签** | 三套口径必然导致「推荐说该复习、队列说没有」，这比队列变长更严重 |
| `Q-205` | 无数据时返回 null，界面显示「暂无数据」/「—」；不使用 0% 或 100% | 0 像「什么都没复习」，100 像「都复习完了」，只有「无数据」诚实 |
| `Q-207` | 普通练习**不暴露**「是否记录错题」开关，默认记录学习过程；只有模考暴露，默认开 | 不给无明确需求的开关；普通练习的记录是主线数据，不是可选副作用 |
| `Q-210` | 评级按钮能算出真实到期日就动态显示；算不出就**不显示间隔**。禁止写死的 `+10m/+1d/+3d/+7d` | 用户评级的唯一依据是「点了之后什么时候再见」；假间隔比没有间隔更糟 |

### 6.2 模考口径（9 条）

| 编号 | 最终规则 | 理由 |
|---|---|---|
| `Q-206` | 今天页/侧栏常驻「有未交卷模考」提示，一键去交卷或放弃；不限时会话 N 天无活动后**明确失效并告知**，不无限期挂网 | 前者解决「不知道」，后者解决「无限期」；`time_limit=0` 时永久挂会话的代价无限扩大 |
| `Q-301` | 总分同时给原始分与百分制；报告头部显示「满分 N」与折算百分制 | 原始分保留负分与部分得分精度，百分制便于跨档案比较 |
| `Q-302` | 蓝图级开关 `floor_at_zero`，默认不设下限；规则摘要说明「负分无下限」 | 默认不设下限保持可解释，需要时按档案开启 |
| `Q-303` | `record_mistakes` 蓝图级可配 + 会话覆盖，默认 true；开始前确认信息显式显示本场取值 | 蓝图是考试配置的载体，避免每次开考重勾 |
| `Q-304` | 交卷确认打开后仍可回改答案 | 家用场景误点交卷代价太高，冻结增加焦虑 |
| `Q-305` | 多设备同时续考：后开者只读，并提示该会话正在另一设备进行 | 成本低，能消除大部分「我改的怎么没了」 |
| `Q-306` | 基础题库模式顺序抽题 + 界面说明；随机应由用户显式选 | 重复抽同一批反而利于对比进步 |
| `Q-307` | 同时记服务端 `time_spent`（在线作答时长）与墙钟 `completed_at - created_at`，报告都给 | 两者意义不同，都有价值 |
| `Q-308` | 未答 > 0 **或**有待复查标记时，交卷给警告；仅计数不够 | 不加点击成本，但把用户的自我怀疑显式化 |

### 6.3 协作、角色与实例（7 条）

| 编号 | 最终规则 | 理由 |
|---|---|---|
| `Q-401` | 只有三种题库角色（所有者/编辑者/成员）；删除 `VIEWER`；原型 `VIEWER` 一律按「成员」 | `MEMBER` 本身只读，第四值不带来新能力，只让权限矩阵从 3×3 变 4×4 |
| `Q-402` | 实例角色固定「管理员/普通用户」，题库角色固定「所有者/编辑者/成员」，两套词永不共用且来自不同字典键 | 关键是任何界面不得同句出现两个「管理员」 |
| `Q-403` | 「保持登录」映射服务端 TTL：勾选 = 30 天，不勾选 = 12 小时 | 否则复选框是说谎的控件——用户有理由相信取消勾选能降低 token 被盗用窗口 |
| `Q-404` | 退出题库**不销毁**个人学习记录：作答/错题/FSRS/掌握度全部保留；界面标注来源题库与「已退出」 | 学习记录是用户私有资产，退出共享库不应销毁个人档案；与 `CR-02` 一致 |

| `Q-407` | 不提供自助转回；实例管理员可仲裁强制转移；转移对话框明写「转移后你变成编辑者，如需转回请联系对方或实例管理员」 | 实例管理员本就是家庭/团队运维者，给个仲裁入口比做状态机小得多 |

### 6.4 AI 与资料（12 条）

### 6.5 题库与内容（8 条）

| 编号 | 最终规则 | 理由 |
|---|---|---|
| `Q-101` | 只做归档，术语降级；空库（无题目且无作答引用）才可物理删除，须输入库名确认 | SQLite + 外键历史下，归档已满足「移出视野、可恢复、不丢数据」；真删除收益低于数据风险 |
| `Q-102` | 卡片显示两个数：「共 N 题」（内容量，公共语义，斩杀不影响）与「我可练 M 题」（个人语义）；只有 M=0 时禁用开始 | 用户对「4 题」的心智是「能练 4 题」；但斩杀是个人状态，不得改变题库公共内容语义 |
| `Q-103` | 批量章节/标签修改只写当前版本 + 审计日志，不生成题目版本 | 元数据变更频率高、版本噪声大；审计日志已满足「谁在何时改了哪些题的章节」 |
| `Q-104` | 不提供「回滚到历史版本」 | 避免「回滚」被误用为覆盖他人工作；冲突解决已给出显式采用路径 |
