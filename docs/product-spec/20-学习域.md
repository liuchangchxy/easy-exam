## 1. 域定位与边界

学习域是 EasyExam 的核心主航道：把「题目版本」通过「作答尝试」转化为「掌握度、复习计划与成绩报告」。它覆盖从「今天」到「报告」的完整闭环，以及支撑这条闭环的调度、档案与同步机制。

**主线**（SPEC §1）：

```text
题目版本 → 作答尝试 → 判分/错因 → 解释版本 → FSRS 复习状态 → 掌握度/斩杀 → 下一次复习
```

**域内**：

| 层 | 内容 |
|---|---|
| 入口层 | 今天页（继续上次 / 今日队列 / 概览）、开始学习面板与活跃会话决策 |
| 会话层 | PRACTICE / MISTAKE / FSRS / ELIMINATION / EXAM 五种模式的会话生命周期、两个 runner（PracticeViewV1 / ExamView）、草稿、断点、离线、幂等 |
| 判定层 | score_ratio / correctness / mastery_status 三者分离（SPEC §3.1）、部分得分、主观题不判分 |
| 调度层 | FSRS-5 评级与 `card_snapshot_json`、错题与错因、`mark_weak`、斩杀题库 |
| 汇总层 | 复习队列（当前可执行复习集合 + 可叠加原因标签，`CR-05`）、学习档案与趋势、学习计划、提分推荐、练习报告 |
| 横切层 | 跨设备事件同步、AI 在练习中的嵌入（无 AI 时完整可用，SPEC §2.3/§2.4） |

**域界（不属于本册）**：题库/工作区/题目页与题目编辑（题库域）、模考档案与蓝图的可视化配置（模考域，本册只接管「模考会话对学习域产生的写入」这一接口）、导入、资料/笔记、设置、实例管理与成员权限（各自分册）。本册只定义这些边界向学习域暴露的契约。

**核心设计约束**（SPEC §2.4）：未配置 AI、联网、蓝图、章节时，今天、练习、错题、FSRS、斩杀、趋势、计划必须全部正常工作。学习域的推荐与计划是纯确定性规则（`recommendation.py`、`study_plan.py`），不依赖任何外部服务。

## 2. 功能定义

### FN-201 今天页

- **存在目的与场景**：用户打开产品后第一屏，回答「我现在该干什么」。同时承担三个职责：接住上次未完成的工作、给出今日队列、给出总体概览。对应 UX §7.1 目标信息架构中「今天 = 继续上次 · 今日队列（到期/错题/薄弱/推荐，带原因）· 四个概览」。
- **入口与适用条件**：路由 `/`（`router/index.js:23`）。任何已登录用户；不需要任何前置配置（无题库时走建库空态，`HomeView.vue:120-126`）。
- **可执行操作**：
  1. 主操作按钮：有未完成会话时文案为「继续练习」（续上最近会话）并提供次级「结束并新建」（作用范围只结束**同模式**会话，按钮写明范围）；无未完成会话时按「今日计划 → 第一个有题题库 → 建库引导」的顺序决定行为（`HomeView.vue:612-622`）。
  2. 「待复习 N」按钮 → 跳 `/review`（默认视图 = 当前可执行复习集合，`CR-05`/`CR-29`）。
  3. 未完成会话卡：继续 / 查看全部 N（**未完成会话总数 > 1** 时出现，`CR-14`）/ 放弃本次；「查看全部」是今天页内的轻量弹窗（**不是**全会话管理页，`CR-14`），弹窗内列出每个会话的模式/题库/进度/更新时间，可继续任一、放弃任一；**不提供「放弃全部」这类跨模式批量动作**——跨模式会话允许并存、互不提示、互不代管（`CR-14`）。**出现条件写「未完成会话总数 > 1」而不是「同模式 ≥2」**：跨模式会话本就允许并存，选择器要回答的是「我有好几件没做完的事，先继续哪一件」，这与它们是否同模式无关；同模式是否冲突由 FN-203 的开始门负责，两件事不要混。
  4. 今日计划三行（**完成度按真实学习记录计算**，不要求必须从计划入口开始）：01 到期复习 → `/review`；02 错题重做 → `/review?tab=mistakes`；03 新题练习 → 按计划首日任务开始练习。
  5. 题库列表行：名称 → `/banks/:id`；「开始练习」→ 该库普通练习；该库「我的可练题量」为 0 时按钮**禁用并解释原因**（`CR-04`），不进入空范围态。
  6. 右侧栏：7 日计划柱状图 + 「接下来」题库入口。
  7. 空态：无题库时「新建题库」。
- **操作结果**（含数据与状态变化）：
  - 挂载时并发拉取 `listBanks` / `listActiveSessions` / `listDueMistakes` / `listMistakes` / `getLearningSummary` / `getLearningTrends(window_days=7)` / `getStudyPlan(days=7, minutes_per_day=30)`；学习类四个请求用 `Promise.allSettled`，任一失败只把对应数字降级为「—」，**不得降级为 0**（无数据与请求失败都不是 0；诚实的空值优于误导性的数值，同 `Q-205` 裁定）。
  - 四个概览数字：累计作答（`summary.attempts`）、到期复习（`listDueMistakes` 长度）、近 7 天正确率（`trends.recent.correct_rate`）、错题（`listMistakes` 长度）。
  - 点击「开始练习」→ 走 `useStartStudy`（见 FN-203）→ 无活跃会话时 `POST /practice/sessions` → 路由到 `/practice/:id` 或 `/exam/:id`。
  - 点击「放弃本次」→ 确认框 → `POST /practice/sessions/:id/abandon` → 刷新活跃会话列表；该会话 `status` 变为 `abandoned`、`is_completed=1`，其草稿与未提交作答全部失效。
  - 收到 `easyexam:events-synced` 且事件含 `BANK`/`QUESTION` → 刷新题库列表；含 `SESSION` → 刷新活跃会话并重算学习统计（`HomeView.vue:1221-1234`）。
- **与其他功能的关系**：是 FN-203（开始面板）、FN-210（复习队列）、FN-211（档案）、FN-212（计划）、FN-215（会话生命周期）的共同入口；向 AppLayout 提供 `@start`/`@mock-exam`/`@resume-session` 事件（`AppLayout.vue:100-110`）。
- **当前缺失与不合理之处**：
  - 主操作「开始练习」在无活跃会话且无今日计划时，落到 `startBankPractice(banks.find(b => b.question_count > 0))`，payload 只有 `{bank_id, mode:'PRACTICE'}`，**不带 `total_questions`**，即整库开始；而同页计划行 03 的 `startSprint` 用 `total_questions = min(20, count)` 限量（`HomeView.vue:627-636` vs `670-685`）。同一页两个入口一个全量一个限量，行为不一致。且判断条件用的是**题库内容量**（`question_count`），不是**我的可练题量**——用户斩杀掉该库全部题目后按钮依旧可点，点进去才落到空范围态，违反 `CR-04`（可练量为 0 应禁用并解释）。
  - 有活跃会话时主操作直接续上 `activeSessions[0]`，完全忽略今日计划（`HomeView.vue:614-617`）；用户无法从今天页主动「放弃旧会话并开始今日计划」——该路径必须先手动放弃。按 `CR-14`，正确形态是主操作提供次级「结束并新建」，且其作用范围**只结束同模式会话**，不连坐其他模式。
  - 侧栏「学习状态」只有「到期复习 N 题 + 覆盖率 + 正确率」（`AppSidebar.vue:29-43`），原型 `screens/home.html` 侧栏为「学习状态 / 今日待复习 2 / 未完成会话 1」，生产缺「未完成会话」这一计数与入口。
  - 原型今天页的未完成会话卡只有「放弃本次」，没有「继续」按钮，也没有多会话时的「查看全部 N」；生产 `HomeView.vue:51-57` 两者都有。原型落后于生产定义。
  - 死词典条目：`ep.today.figure_done`（今日完成）、`ep.today.figure_streak`（连续学习）、`ep.today.active_many`、`ep.today.resume_latest`、`ep.today.restart`、`ep.today.next_weak`（薄弱章节）、`ep.today.quick_mistakes_hint`、`ep.today.sprint_hint` 在 `.vue` 中零引用（`locales/ep-zh-CN.js:149-205`）。
- **理想完成态**：
  1. 主操作按钮的决策顺序固定为：① 有未完成会话 → 「继续练习」+ 次级「结束并新建」（只结束**同模式**会话，按钮写明范围）；② 无未完成会话且有今日计划 → 「开始今日计划（N 题）」；③ 无计划 → 「开始练习（20 题）」并明确标注数量；④ 我的可练题量为 0 → 「新建题库」或禁用并解释（`CR-04`）。四种状态的按钮文案与次要操作都可预期。
  2. 未完成会话卡每个会话都有「继续」；**未完成会话总数 > 1** 时出现「查看全部 N」，弹窗内列出模式/题库/进度/更新时间，并支持单个放弃；**不做「放弃全部」**（跨模式会话互不代管，`CR-14`）。出现条件与是否同模式无关：选择器回答「先继续哪一件」，同模式是否冲突由开始门负责。
  3. 侧栏「学习状态」固定四项：今日待复习、未完成会话、覆盖率、近 7 天正确率；点击「今日待复习」跳到 `/review`（默认视图即可执行复习集合），点击「未完成会话」打开活跃会话弹窗。
  4. 任何学习类接口失败只降级对应数字，页面骨架与可操作入口保持可用，并在数字旁给出可重试标记。

### FN-202 今日计划与 7 日计划

- **存在目的与场景**：把「今天该学多少、学什么」变成可执行的一组题。服务「每天打开就知道做什么」的家庭自用场景。
- **入口与适用条件**：今天页右栏柱状图与计划行 03（`HomeView.vue:130-143, 82-89`）；完整计划见 FN-211 学习档案（路由 `/review/diagnosis`）。任何已登录用户；无题库时计划为空态。
- **可执行操作**：查看 7 日计划分布（每天题数与预估分钟）；点击计划行 03 按首日任务开始练习；在 `/review/diagnosis` 中按天开始、调整天数/题库/配额或时长。
- **操作结果**：`getStudyPlan` 返回 `days[]`，每天含 `day_number/title/focus/focus_description/question_count/estimated_minutes/question_ids/bank_tasks`（`study_plan.py:33-60`）。点击开始 → `start('PRACTICE', bankIds[0], questionIds, bankIds)`，多题库时传 `bank_ids`（`ReviewView.vue:810-821`）。计划本身只读，不产生任何学习状态写入。
- **与其他功能的关系**：消费 FN-213 推荐的有序结果；产出 FN-204 会话；与 FN-211 共享 `plan` 状态。
- **当前缺失与不合理之处**：
  - 计划是**请求时即时计算**的，不落库、不记「第几天已完成」。用户第二天打开看到的「第 1 天」仍是同一个排序结果，不会因为昨天学过而前进——「第 N 天」只是推荐列表的切片序号，不是真实的日程锚点（`study_plan.py:69-83`）。
  - 原型的诊断 tab 计划结构为「到期复习 / 错题重做 / 薄弱专项 / 新题练习 / 复盘日 / 模考」六类焦点（原型 `screens/review.html` 诊断 tab），生产的 `get_phase_focus` 只按天数比例输出「基础攻坚 / 薄弱突破 / 抗遗忘冲刺」三档（`study_plan.py:24-31`）。两者不是同一个模型。
  - 「复盘日」「模考」在原型的计划里是可直接跳转的条目，生产计划里没有对应概念，也没有跳转到模考中心的入口。
  - `LearningView.vue` 里有一套完整的计划调优 UI（天数/题库/配额/时长，参数按设备本地持久化、不跨设备同步），但 `/learning` 已 redirect 到 `/review`（`router/index.js:31`），该文件整体不可达（见 GAP-214）。
- **理想完成态**：
  1. 计划按「自然日」锚定：服务端记录用户选择的开始日与每日配额，第 N 天 = 开始日 + N-1；已完成的天数在 UI 上标记完成，未完成的天数可补做。**完成进度按真实学习记录计算，不要求必须从计划入口开始**——同一道题无论从今天页、复习页、题库页还是计划入口做，完成判定一致，档案/趋势用同一口径（`FN-211`）。**未完成任务允许补做，并明确后续安排**：补做后该日标记完成，剩余任务按「补做日之后顺延 / 按剩余预算重新切分」的固定规则重排，规则在计划页可见。**调整计划参数或重新计算时保留已完成进度，只调整剩余任务。** 计划不是每天重置的推荐清单；不引入复杂任务管理系统（无依赖图、无提醒推送、无多人协作）。
  2. 每日任务的组成固定为四类且各带数量与原因：到期复习、错题重做、薄弱专项、新题练习；「复盘日」与「模考」作为可跳转的辅助条目，不作为题目来源。
  3. 调整参数（天数/题库/配额或时长/新题比例）后立即重算并在原地刷新，**重算保留已完成进度、只调整剩余任务**，不需要跳页；参数本地持久化，跨设备不同步（个人偏好）。
  4. 计划中的每一题都可展开看题干与推荐原因（`item.reason`），点击「开始」只启动勾选的部分。

### FN-203 开始学习面板与活跃会话决策（统一 startSession 入口）

- **存在目的与场景**：全产品只有一个「开始学习」动作。任何入口（今天页、题库列表、题库工作区、题目页、复习页、命令面板）都调用同一个 composable，由它先问服务端「有没有没做完的活」，再决定直接开始还是先让用户决策。这是 UX §7.3「一个开始面板」的落地，也是 P6 §14.1「开始决策唯一」的成果。
- **入口与适用条件**：`useStartStudy`（`composables/useStartStudy.js`），被 `HomeView.vue:514`、`ReviewView.vue:709`、`BankManageView.vue:1012`、`BanksView.vue:452`、`QuestionPageView.vue:244`、`AppLayout.vue` 共用。面板组件 `components/StartStudyPanel.vue`。
- **可执行操作**：
  1. `start(payload, {navigate})`：先 `listActiveSessions(token, payload.mode)`；返回非空 → `{blocked}`，由调用方渲染面板；为空 → `POST /practice/sessions` 并导航。
  2. 面板三选：取消（不新建）/ 继续（`continueSession` 导航到既有会话）/ 结束并新建（`endAndStart`）。
  3. `endAndStart`：只结束**同模式**的未完成会话（逐条 `abandonSession`），然后 `startSession`（`useStartStudy.js:65-90`）。**不提供跨模式的「结束全部」**：一个 PRACTICE 和一个 FSRS 会话可以同时挂着，互不提示、互不代管（`CR-14`）。
- **操作结果**：取消 → 无任何写入，停留原页；继续 → 不产生新会话，跳到 `/practice/:id` 或 `/exam/:id`；结束并新建 → **同模式**旧会话 `status=abandoned`、`is_completed=1`，新会话 `status=active`；其他模式的进行中会话不受影响。面板列出每个待处理会话的模式标签、题库名与 `answered/total` 进度（`StartStudyPanel.vue:12-18`）。
- **与其他功能的关系**：是所有练习/复习/模考入口的前置门；与 FN-215（会话生命周期）共同保证「同一用户不会在不知情的情况下堆第二个**同模式**会话」；跨模式并存是允许的（`CR-14`）。
- **当前缺失与不合理之处**：
  - **普通刷题没有开始配置面板**。全产品不存在「来源/数量/题型/模式/是否记录错题」的可选面板：`BankManageView.startPractice`、`BanksView.startPractice`、`HomeView.startBankPractice` 的 payload 都只有 `{bank_id, mode:'PRACTICE'}`；`QuestionPageView` 只有 `{bank_id, mode, question_ids:[id], total_questions:1}`。词典里 `ep.practice.scope/scope_all/scope_unseen/scope_mistakes/scope_due/type/chapter/count/setup` 八个键在 `.vue` 中零引用（唯一命中的 `ep.practice.setup` 是 `HomeView.vue:604` 拿来当模式标签用）。原型 `flows/practice.html` 第 2 步与 `screens/home.html` 的开始浮层同样只读展示「范围/题型/模式」，没有数量与错题开关——**原型与生产一致地缺失了这一层**。
  - `record_mistakes`（「本场是否纳入学习记录」）只在模考设置里可配（`HomeView.vue:256-260`）；练习、错题、FSRS、斩杀四种模式一律按 `record_mistakes=True` 处理（`practice_repository.py:411-420`）。**这不是缺陷而是已裁定规则**：普通练习不暴露此开关，默认记录学习过程（`CR-08`、`Q-207` 裁定 A）。普通刷题真正缺的是上段参数里的来源/数量/题型/章节/模式。
  - 活跃会话检测是**同模式**的（`listActiveSessions(token, payload.mode)`）。有一个进行中的 FSRS 会话时再从题库开始 PRACTICE，不会弹面板，直接叠第二个会话。**按 `CR-14` 这是正确行为，不再是缺陷**：冲突门只比较同 mode，跨模式允许并存、互不提示。本条从「刻意没做的」清单移出，改登记为已确认规则。
  - 模考入口**完全不走**这个门：`HomeView.beginExam` 直接调 `startExam`（`HomeView.vue:919-938`），`POST /exams/sessions` 也没有活跃会话检查（`routes/exams.py:63-79`）。

### FN-204 普通刷题会话（PRACTICE）

- **存在目的与场景**：产品最高频的操作。顺序练习一个范围的题目，作答后立即得到判定、标准答案与解释，并按模式决定是否进入 FSRS 评级。
- **入口与适用条件**：FN-203 的各入口；模式 `PRACTICE`。题库为空、或模式为 MISTAKE/FSRS/ELIMINATION 且候选题集为空、或显式传入的 `question_ids` 全部不在候选集内时，服务端返回 400「当前题库没有符合条件的题目」（`practice_service.py:109-118`），前端渲染空范围态（`PracticeViewV1.vue:547-551`）。开始前即按**我的可练题量**判断：为 0 时「开始练习」禁用并解释原因（`CR-04`），不应让用户进入会话后才落到空范围态。
- **可执行操作**：
  1. 选项点选 / 键盘 A–D / 数字 1–8（`PracticeViewV1.vue:1696-1715`）；多选可反复增删。
  2. 「提交答案」（有作答才可点）→ 判定并展示反馈。
  3. 上一题 / 下一题 / 跳题 / 答题卡跳转 / 跳到下一道未答题。
  4. 作答卡内「标记」待复查旗（`toggle-flag`）；顶栏图标与右栏按钮「标记薄弱」；「更多」菜单只放低频动作，**会话内不提供题目编辑入口**；「不再练这道题」（斩杀）。
  5. 底部「完成练习」→ 交卷确认 → 报告。
  6. 顶部「退出」→ 退出确认。
  7. 左右滑动手势翻题（`PracticeViewV1.vue:908-931`）。
  8. 顶栏常驻本次计时，可在设置里关闭（`FN-516`，50 册）；判定模式（明确提交 / 点选即判）在设置里切换（`Q-201` 裁定）。
- **操作结果**：
  - 提交 → `POST /practice/sessions/:id/attempts`，返回 `score_ratio/correctness/mastery_status/is_objective/is_correct/fsrs_rating/mistake_cause`；服务端同事务内写 `answer_attempts`、更新 `practice_sessions.answers_json`、`learning_records`、`mistake_records`（错题）、`fsrs_cards`、`learning_events`（`practice_repository.py:363-505`）。
  - `PRACTICE` 模式下答错：`mistake_count+1`、`consecutive_correct=0`、`is_cleared=0`，进入错题队列；`fsrs_rating` 自动取 1（Again）。答对：`consecutive_correct+1`，满 2 次 `is_cleared=1`；答对且本题已有 FSRS 卡时 `fsrs_rating` 自动取 3（Good）并写卡；答对且本题此前没有 FSRS 卡、也未标记薄弱的题**不建 FSRS 卡**（统一建卡原则见 `BR-218`；`practice_repository.py:469-501`）。

  - 交卷 → 见 FN-214。
  - 退出 → 保存当前题状态、flush 草稿、跳回来源页，会话保持 `active`（`PracticeViewV1.vue:627-645`）。
- **与其他功能的关系**：是 FN-206（评级）、FN-207（薄弱）、FN-208（斩杀）、FN-209（错题）的共同写入点；消费 FN-215 的会话状态机与 FN-216/217 的草稿与离线机制。
- **当前缺失与不合理之处**：
  - **单选/判断的判分时机已裁定**：默认保持**明确提交模式**——选择后点「提交答案」或按 Enter 才判定（`PracticeViewV1.vue:839-852, 1733-1747`）；可提供「点选即判」作为用户可选的模式。**明确不做「800ms 内可修改」的模糊判分窗口**（`Q-201` 裁定 A + C，覆盖 80 册原推荐 B）：判定必须是非此即彼的明确事件，要么提交前可改，要么提交后定版，不存在「点了但还能偷偷改回去」的中间态。SPEC §3.1 的「支持点选即判」按可选模式落地，不按唯一模式。多选保持「提交后判」。

  - 空范围态只给「返回题库 / 去导入」，没有「换一个范围重试」（原型的空范围态明确区分「读取失败（可重试）」与「没有符合条件的题目（只给返回与换范围）」，原型 `screens/practice.html` `st-empty`/`st-fail` 两态）。

### FN-205 判定反馈、解释与 AI 嵌入

- **存在目的与场景**：判定之后立刻给出「为什么对、为什么错、正确答案是什么」。AI 是可选增强，不参与判分（SPEC §2.3）。
- **入口与适用条件**：`result` 非空时渲染反馈块（`PracticeViewV1.vue:354-456`）。所有题型；主观题（ESSAY/SHORT_ANSWER/SUBJECTIVE）**保存答案即「已作答」，判分状态为「未判分」**，`is_objective=false`、`score_ratio` 不参与得分计算，判分区显示「已保存，不自动判分」与参考解析，**不得显示为未作答**（`CR-06`；`scoring.py:27-33`）。
- **可执行操作**：看判定标题与得分率；看标准答案与自己的作答；看官方解析；在 FSRS/MISTAKE 模式下评级（FN-206）；展开 AI 面板：生成解释、联网核查、生成变式、追问、采纳某一版本、编辑并另存为用户解释。
- **操作结果**：
  - 反馈区展示 `correctness`（CORRECT/PARTIAL/INCORRECT，仅已判分时有值）、**判分状态（已判分/未判分）与作答状态（已作答/未作答）**、`score_ratio` 百分比、`question.answer`、官方 `question.explanation`。
  - AI 操作写 `explanation_versions`（AI/WEB/PERSONAL 三种来源）与 `explanation_evidence`；重新生成、联网核查都新增版本，不覆盖旧版本；`adopt` 只改主版本标记。
  - 未配置 AI 时：按钮可点但返回明确的不可用原因，判分、答案、解析、评级、错题、FSRS 全部不受影响（SPEC §2.4）。
- **与其他功能的关系**：与解释版本域（题库/内容域）通过 `answer_versions` 交互；AI 变式草稿进题库域草稿箱。本册只定义「练习会话内 AI 的嵌入契约」。
- **当前缺失与不合理之处**：
  - 多选部分得分时，反馈区不指出「漏选了哪个 / 多选了哪个」，只给 50% 得分率与标准答案；用户无法从反馈直接看到差距。
  - AI 面板的「生成解释」在无 AI 配置时没有差异化的空态说明，只有通用的错误文案。
  - `formatVerdictTitle` 的判定标题对 `PARTIAL` 与「未判分」的区分依赖 `is_objective`；按 `CR-06`，主观题的「已作答 / 未判分」必须有独立可见表达，不能与「未作答」混在同一句文案里。
  - AI 追问记录（`chatMessages`）在切换题目时整体丢弃，不按题目保留会话上下文；虽然 `listQuestionConversations` 在切题时重取，但当前题的新追问不会并到已有会话的可见历史里（`PracticeViewV1.vue:1241-1254`）。
- **理想完成态**：
  1. 判定区固定四行：结论（对/部分对/错/未判分）+ 得分率 + 标准答案 + 我的作答；多选漏选/多选逐项标出。
  2. 官方解析、AI 解释、联网核查、用户解释四个来源分区展示，各带来源标签、时间与联网状态；默认展示当前主解释，证据按需展开（SPEC §2.3）。
  3. 无 AI 时 AI 区显示「未配置 AI 助教」+ 前往设置的入口，其余功能完整可用。
  4. AI 只读题目上下文，任何 AI 输出都不得改写标准答案；无标准答案时只能作为候选答案并需用户确认（SPEC §2.3）。

### FN-206 FSRS 评级与调度（Again / Hard / Good / Easy）

- **存在目的与场景**：把一次作答转化为「下次什么时候再见这道题」。是学习域算法核心。
- **入口与适用条件**：反馈区在 `session.mode` 为 `FSRS` 或 `MISTAKE` 时渲染四个评级按钮（`PracticeViewV1.vue:375-384`）；键盘 1–4 等价（`:1718-1730`）。PRACTICE 与 ELIMINATION 模式不显示评级块，由服务端自动定级。EXAM 模式单题不调度，交卷时统一结算（FN-219）。
- **可执行操作**：
  1. 提交答案后点选 Again(1)/Hard(2)/Good(3)/Easy(4)，或先答后评（两步交互）。
  2. 答错时仅 Again 可点并默认预选；部分得分时 Hard 及以上禁用；答对时四个都可点（服务端另有约束，见 BR-215）。
  3. 改评级：对同一题再次点选不同评级。
- **操作结果**：
  - 服务端 `submit_attempt` 校验评级与 correctness 的相容性（`practice_service.py:242-248`），再由 `save_attempt` 落库。
  - 首次提交：写 `answer_attempts`，`card_snapshot_json` = 作答前卡片状态（无卡则为 `{state:0, stability:0, difficulty:5, due_at:null, last_review_at:null}`），随后按 `FSRS5.schedule(rating, stability, difficulty, elapsed_days, now)` 写 `fsrs_cards`（`practice_repository.py:353-359, 469-501`）。**建卡受 `BR-218` 三条件约束**：本题已有 FSRS 卡、或本次作答为错/部分得分、或本题当前被标记薄弱；三者皆不满足（首次答对且未标记薄弱）不建卡。
  - 评级提交（两步交互第二步）：`client_attempt_id` 与答案提交相同 → `_find_replay_attempt` 命中同一行 → `_settle_duplicate_attempt` 只更新 `fsrs_rating`，并**从该行的 `card_snapshot_json` 重新计算**后覆写 `fsrs_cards`（`practice_repository.py:197-311`）。这保证「两步交互」与「一次性提交评分」的 `state/stability/difficulty/due_at` 严格等价（SPEC §4.2）。
  - 存量无快照记录的三种处理（SPEC §4.2 迁移安全策略）在 `practice_repository.py:226-256` 实现：历史上已调度过的（有评级，或卡片 `last_review_at` 与作答时间吻合）→ 只更新评级反馈，冻结卡片，**不**二次叠加、**不**用默认值重置；从未调度过的 → 以当前卡片（或初始新卡）为基准首次调度并即时生成快照；升级/迁移脚本不得把当前卡片伪造成历史快照。
- **与其他功能的关系**：直接决定 FN-210 到期队列与 FN-211 复习完成度；受 FN-215 终结态保护（已交卷会话的评级提交被 422 拒绝）。
- **当前缺失与不合理之处**：
  - **评级按钮的间隔提示与调度器实际输出不符（已裁定，本期必须修）**：UI 写死 `重来 (+10m) / 困难 (+1d) / 一般 (+3d) / 轻松 (+7d)`（`PracticeViewV1.vue:378-381`），而 `FSRS5.schedule` 对 `rating=1` 固定 `scheduled_days=1`（即明天，不是 10 分钟），`next_interval` 由稳定度反解，初值下 Hard≈1 天、Good≈2 天、Easy≈6 天（`legacy/services/fsrs.py:193-232`）。用户看到的间隔是假的。**裁定（`Q-210`）**：间隔必须与实际调度一致——能算出真实到期日就动态显示，算不出就不显示间隔，**不得展示写死的假间隔**。
  - **交卷时未显式评级的作答会被服务端自动定级且无提示**：`complete_session` 会把仅有草稿答案的题补分，`save_attempt` 在 `fsrs_rating=None` 时自动推导（错/部分→1；答对且本题已有卡片→3；答对且本题无卡片→不建卡），即 `Q-203` 保留的默认规则，与 `BR-218` 的建卡三条件同源（`practice_service.py:388-404`、`practice_repository.py:469-473`）。FSRS/MISTAKE 模式下用户若答完直接点「完成练习」而不评级，会得到一个他没选过的默认评级。**已裁定（`Q-203` A）**：默认规则本身保留，但交卷确认必须列出未评级题数、写明默认调度规则并提供「回去评级」入口；不强制逐题评级，也不静默。
  - 答错时「默认预选 Again」只写本地 `selectedFsrsRating`，**不会**自动提交评级（`PracticeViewV1.vue:1438-1444`）；若用户随即交卷，实际生效的是服务端推导的 Again——结果相同但用户看不到确认。
  - 四个按钮旁的 `+10m/+1d/+3d/+7d` 与「稳定度」在队列里展示的值（生产根本没展示，见 GAP-202）无法互相印证。
- **理想完成态**：
  1. 评级按钮不写死间隔；在用户悬停/点选后显示该题按当前快照计算出的**实际到期日期**（如「重来 → 11 月 27 日」），由服务端在同一次提交响应里返回 `next_due`；**算不出真实到期日时不显示间隔**，只保留四个评级词，绝不用固定值填充（`Q-210` 裁定）。
  2. 交卷确认框在存在未评级作答时明确写出「还有 N 题未评级，将按默认规则调度（错/部分 → 重来；答对且本题已有卡 → 一般；答对且本题无卡 → 不建卡）」，并提供「回去评级」入口。
  3. 答错时 Again 自动提交（而非只预选），减少一次无意义点击；答对时不预选。
  4. 存量无快照记录的三种处理保持现状（SPEC §4.2 已确认），但在 UI 上对「本次只记录了反馈、未重新调度」给出可见说明。

### FN-207 薄弱标记 mark_weak

- **存在目的与场景**：让用户主动把「犹豫但没错」的题拉进复习队列。SPEC §4.2：FSRS 调度错题与 `mark_weak` 标记题，不默认调度所有做过的题。
- **入口与适用条件**：练习会话顶栏图标按钮、右栏「标记薄弱」按钮、快捷键 F。任何对该题库有成员资格的用户。
- **可执行操作**：标记 / 取消标记（同一按钮切换）。
- **操作结果**：`POST /learning/weak/:qid` → `weak_question_flags` 插入一行，并 `INSERT OR IGNORE INTO fsrs_cards(state=0, stability=0, difficulty=5, due_at=CURRENT_TIMESTAMP)`，即标记后立即到期（`practice_repository.py:863-879`）。取消 → 删除 flag；若该卡从未被复习且没有未清除错题，连同卡片一起删（`:881-891`）。
- **与其他功能的关系**：是 FN-210 复习队列「薄弱」原因标签的唯一来源；**薄弱视图（`CR-29`）是全部薄弱题（含未到期）的权威列表**（`GAP-222`），待复习视图只呈现其中已到期的部分（`CR-05`）。
- **当前缺失与不合理之处**：
  - **没有薄弱题的集中管理入口**：只能回到做过的那道题去取消标记。UX §11.2 明列「没有给薄弱/斩杀补专门的复习入口页」，§14.3 保留五页签的口径已由 `Q-208` 裁定 B 改为拆分路由。用户在复习队列里看不到「哪些是我标过薄弱的」全貌，也无法批量取消。按 `CR-05`/`CR-29`，**薄弱视图**就是这个入口，是薄弱题的**权威列表**：未到期的薄弱题**不进任何到期视图**，只出现在薄弱视图；从那里开始的会话是普通练习（`PRACTICE`），不是 FSRS 专项（FSRS 专项的集合约束保持「必须属于当前已到期集合」，`BR-210`）。
  - 取消标记的卡片删除条件是「从未复习且无未清除错题」，这意味着**标错过又复习过的题取消标记后会留下一张孤儿 FSRS 卡**：它既不在待复习视图（`list_due_reviews` 要求 weak 或未清除错题），也不会再被任何列表引用。
  - 快捷键 `F` 在练习里是「标记薄弱」，在模考里是「标记待复查」，两个 runner 同一键不同义；UX §7.3 提出统一为「F 只在标记语境下使用，或改为 W/B 区分」。**已裁定（`Q-603` B）**：拆键——`W` = 标记薄弱（仅练习），`B` = 待复查旗（两个 runner 同键同义），`F` 不再绑定任何动作。
  - 生产库真实数据显示 `薄弱标记 = 0`（UX §3），该功能从未被真实使用过，其可用性没有经过真实流量检验。
- **理想完成态**：
  1. 薄弱题有集中管理入口（薄弱视图，`CR-29`/`GAP-222`），列出**全部**薄弱题（含未到期），支持行内取消标记与批量取消；未到期薄弱题从该入口开始的会话是普通练习（`PRACTICE`），不是 FSRS 专项。待复习视图中的「薄弱」只是到期题上的一个原因标签（`CR-05`）。
  2. 取消标记时，若因此产生孤儿卡片（无 weak flag、无未清除错题、无斩杀），应一并清理或在档案里显式列出。
  3. 快捷键统一（`Q-603` 裁定 B）：`W` = 标记薄弱（仅练习 runner）；`B` = 标记/取消待复查旗（**两个 runner 同一个键、同一个动作**）；两者在快捷键帮助里都写明。`F` 不再绑定任何动作。

### FN-208 斩杀题库

- **存在目的与场景**：用户主动把「已彻底掌握、不想再见到」的题移出所有练习与复习流（SPEC §4.3）。
- **入口与适用条件**：练习会话「更多 → 不再练这道题」；错题视图错题行的「斩杀」按钮；斩杀视图的「恢复」。
- **可执行操作**：斩杀；恢复；在斩杀视图启动「查漏补缺」专项（ELIMINATION 模式）。
- **操作结果**：`POST /kills/:qid` → `kill_records` 插入；该题从 `list_for_bank`（普通刷题）、`list_mistakes`、`list_due_reviews`、`list_weak_questions`、`recommendation_candidates` 中全部消失（各自 SQL 均有 `k.question_id IS NULL`）；**卡与错题记录不删除**——斩杀只改变可见性，该题的 FSRS 卡、错题记录与历史作答一律保留（`CR-05`）。恢复 → 删除 kill 记录。ELIMINATION 专项中答错 → `DELETE FROM kill_records`，恢复为未斩杀并重新进入复习流程（`practice_repository.py:434-435`）。斩杀不因时间自动恢复。
- **与其他功能的关系**：斩杀题从一切到期视图中消失（已斩杀即非到期，`CR-05`），斩杀视图是复习页的**独立视图**与查漏补缺入口，不是待复习视图的原因标签；与 FN-204 的候选集构建直接相关（服务端集合约束）。
- **当前缺失与不合理之处**：
  - 斩杀只在单题上下文里可执行（做题时、错题行），没有「批量斩杀」；UX §3 显示真实库 141 题，逐题斩杀成本高。
  - 斩杀视图没有「斩杀时间/题库」之外的任何信息，也没有「为什么斩」的记录；恢复后用户看不到自己斩过什么。
  - 原型斩杀视图明确写出「斩杀题答错一次会自动恢复；在恢复前，它不会出现在练习、到期与错题队列里」，生产斩杀视图只有一行计数与「开始」按钮，缺这句关键规则说明。
  - 斩杀确认用原生 `window.confirm`（`PracticeViewV1.vue:1597`），是 UX §14.3 明列的两处未接入 seam 之一。
  - 原型在复习队列行上直接把「斩杀恢复」作为原因标签展示，并带「斩杀于 YYYY-MM-DD」。这与 `CR-05` 冲突：**斩杀题不属于可执行复习集合**，不能作为待复习视图的原因标签出现；斩杀信息归斩杀视图展示，含斩杀日期。
- **理想完成态**：
  1. 斩杀入口保持「只能用户主动」，但在错题列表与复习队列支持多选批量斩杀，批量前二次确认并预告影响范围。
  2. 斩杀视图列出斩杀时间、所属题库、题型，支持筛选与批量恢复；提供「斩杀原因」可选备注。
  3. ELIMINATION 专项的服务端集合约束保持现状（`question_ids` 必须属于已斩杀集合），前端不得因漏传参数退化为整库练习。
  4. 斩杀/恢复全部走应用内确认与 toast，不用原生对话框。

### FN-209 错题与错因

- **存在目的与场景**：答错的题自动进入个人错题队列，并可按错因归因（SPEC §4.1）。
- **入口与适用条件**：练习与 FSRS 复习中答错自动入库；模考是否入库由「本场是否纳入学习记录」开关决定（`CR-08`，仅模考暴露、默认开）。**错题视图 = 全部未清除错题，不受是否到期限制**（`CR-29`），加错因筛选，允许主动重做（MISTAKE 专项）；已到期的部分同时在待复习视图中以「错题未清除」原因标签出现。
- **可执行操作**：查看错题列表（按题库/错因筛选）；行内改错因；单题重做（MISTAKE 模式）；斩杀；按筛选结果批量开始错题重做。
- **操作结果**：答错且纳入学习记录 → `mistake_count+1`、`consecutive_correct=0`、`is_cleared=0`，`mistake_records` upsert；连续 2 次答对 → `is_cleared=1`（错题清除，记录保留）。**已清除错题不出队**（`CR-05`、`Q-202` 裁定 B）：清除只改错题状态，不删 FSRS 卡、不移出调度；该题之后到期时以「巩固」原因低优先级出现在复习队列。错因可持久化修改：`PUT /mistakes/:qid/cause` 同时更新 `mistake_records.mistake_cause` 与该题最近一次 `answer_attempts.mistake_cause`（`practice_repository.py:848-861`）。
- **与其他功能的关系**：`mistake_records` 与 `learning_records` 是两张表，一次作答在同一事务内同时更新（SPEC §6 实现约束，`practice_repository.py:400-468`）；错题是 FN-210「错题」原因与 FN-211 薄弱点统计的来源。
- **当前缺失与不合理之处**：
  - **错因标签不一致**：ReviewView 的 `causes` 用 `t('ep.review.cause_concept')` 渲染键值 `'概念欠缺'`，而 `ep.review.cause_concept = '概念不清'`，存储值与另一套词典 `ep.mistakes.cause_concept = '概念欠缺'`（`ReviewView.vue:519-526`；`locales/ep-zh-CN.js` review 块 vs mistakes 块）。用户在下拉里看到「概念不清」，库里存的是「概念欠缺」。
  - `ep.review.cause_careless/cause_time/cause_guess`（粗心/时间不足/蒙对）是死条目，不属于 SPEC §4.1 的六种错因，遗留自旧版。
  - 错题视图只显示当前筛选出的数量，不提示「另有 N 道已到期（在待复习视图可见）」（原型的错题 tab 有「另有 3 道在队列里」）。
  - 错题专项的服务端集合约束已实现（`practice_service.py:102-108`），但错误提示只有 400「当前题库没有符合条件的题目」，用户分不清「错题已清零」与「传错了题」。
  - 错题行的错因修改失败时会回滚本地值并把错误塞进顶部 `notice`，与同页其他操作的反馈位置不一致。
- **理想完成态**：
  1. 六种错因（审题遗漏/概念欠缺/思路不熟/陷阱诱导/计算错误/其他手误）全产品一套词典、一套标签；删除遗留的粗心/时间不足/蒙对。
  2. 错题行内可直接改错因并即时生效；批量选中多题统一设错因。
  3. 错题列表显示「错题 N 道，其中 M 道当前已到期（在待复习视图可见）」，点击可跳到待复习视图的对应筛选。
  4. 错题清零时给出明确空态与「错题已全部掌握」的正向反馈，而不是通用空列表。

### FN-210 复习队列（当前可执行复习集合 + 原因标签）

- **存在目的与场景**：一条队列回答「现在该复习什么」。UX §7.3「一条队列」。**口径唯一（`CR-05`）分两层**：**到期是卡片属性（`due_at <= now`）**；**当前可执行复习集合 = 到期 ∧ 未被当前用户斩杀 ∧ 未被归档 ∧ 当前用户对该题所属题库仍有访问权**。`list_due_reviews(user, bank?)` 供给的是**可执行复习集合**（方法名是实现载体，P-12）；复习队列、今日队列、趋势、推荐、计划全部调用它，禁止各处各写一套。不满足集合条件的题**保留原有学习状态，不删除不重置**；条件恢复时凭原有卡片状态重新进入，不重新从零开始。队列按 `(bank_id, question_id)` 去重，每行带可叠加的**原因标签**：错题未清除 / 薄弱 / 巩固（可多选叠加）。
- **入口与适用条件**：路由 `/review`，默认视图「待复习」（默认值不写地址）。**「全部」与「到期」已合并为一个「待复习」视图**：它是同一集合（当前可执行复习集合，`CR-05`）的两种呈现（默认列表 / 按到期时间排序与分组），**不设成两个独立页签**（`CR-29`）。学习档案是**独立路由 `/review/diagnosis`**（`Q-208` 裁定 B、`CR-29`），不是复习页的页签；旧值 `diagnosis` 与 `/learning` 重定向到它。`?tab=due|mistakes|weak|killed`（默认 `due`，默认值不写地址；旧值 `all`/`due` 重定向到 `due`，旧值 `diagnosis` 重定向到 `/review/diagnosis`）、`?source=all|mistakes|weak|consolidation`、`?q=`、`?scope=`、`?bank=`、`?cause=` 全部进 URL（`ReviewView.vue:544-661`）；默认值不写地址。
- **可执行操作**：
  1. 四个视图（`CR-29`）：**待复习**（默认，当前可执行复习集合；同一集合内可切换「默认列表 / 按到期时间排序与分组」两种呈现，**不设成两个页签**）/ **错题**（全部未清除错题，**不受是否到期限制**）/ **薄弱**（全部主动标记的薄弱题，含未到期，薄弱题的权威列表）/ **斩杀**（已斩杀题管理 + 查漏补缺，独立视图）。学习档案是独立路由 `/review/diagnosis`，不是页签（`Q-208` 裁定 B、`CR-29`）。
  2. 待复习视图内：原因筛选 chips（全部/错题未清除/薄弱/巩固）、题干搜索（250ms 防抖、replace 写 URL）、题库范围下拉、行内「重做」。
  3. 待复习视图：按题库分组的「练这个题库」、题目列表（按到期时间排序）、单题重做、右栏次级入口（错题/薄弱/斩杀/学习档案）。

### FN-213 提分推荐

- **存在目的与场景**：在没有 AI 的情况下也能给出「接下来练什么最提分」的可解释建议。SPEC §8：推荐结果显示简短依据，用户可调整题型、章节、数量、难度和新题/复习题比例。
- **入口与适用条件**：`/review/diagnosis`「建议」区；`LearningView`（不可达，GAP-214）另有一套带筛选栏的完整版。`GET /learning/recommendations`。
- **可执行操作**：按题库分组开始练习；调整题型过滤、新题比例、新题/薄弱/到期开关、难度、章节、数量。
- **操作结果**：`build_recommendations` 对每条学习记录打 `priority` 与 `reason`，按原因优先级降序：**错题待复习(100+min(mistakes,20)) > 薄弱(90) > 复习到期(80) > 新题覆盖(50) > 巩固练习(20)**（`BR-234` 细化表）；按 `(-priority, last_attempt_at, question_id)` 排序（`last_attempt_at` 无则视为最早）；同一题命中多个原因时取最高优先级原因作为分组依据。开关关闭时按结构化 `category` 与 `reason` 双重过滤（`:79-90`）。`new_ratio` 在 0–1 之间时按比例切分新题池与复习池，一侧不足从另一侧补足（`:97-119`）。难度过滤只按题目标注的 1–5；启用具体难度时排除未分级题（difficulty=0），未启用时未分级题正常参与；**绝不**从用户作答推断难度（`:54-67`，SPEC §8）。
- **与其他功能的关系**：是 FN-202 计划的数据源；与 FN-210 复习队列共用同一个到期口径（`CR-05`，历史上各有口径的问题见 GAP-209）。
- **当前缺失与不合理之处**：
  - 可达 UI（`/review/diagnosis`）只暴露「按题库分组 + 开始」，**没有** SPEC §8 要求的题型/章节/数量/难度/新题比例调节控件；这些参数只在 API 层与不可达的 `LearningView` 里存在（`ReviewView.vue:366-385` vs `LearningView.vue:491-505`）。
  - 依据只显示 `reason` 一句话，不显示「为什么是它」的可核查细节（错题次数、距上次几天、稳定度、到期日）。
  - `new_ratio` 的语义是「新题占 limit 的比例」，但 UI 里没有说明，用户看到「50%」不知道是什么的 50%。
  - 斩杀题已被 `recommendation_candidates` 排除（`:1141-1142`），但归档题（`questions.is_deleted`）没有排除——推荐可能推出已归档题（`GAP-235`，与 `CR-03`/`CR-04` 冲突）。
- **理想完成态**：
  1. 推荐区固定一行筛选：题型、章节/标签、数量、难度（1–5 + 未分级）、新题比例滑杆、新题/薄弱/到期三个开关；每次调整即时重算并更新依据。
  2. 每一行展示：依据一句话 + 可展开的细节（错题 N 次、连续对 M 次、上次作答日期、稳定度、到期日、难度与未分级标记）。
  3. 未分级题在启用具体难度筛选时明确排除并给出「已排除 N 道未分级题」的提示；未启用时正常参与。
  4. 推荐结果排除斩杀与归档题；按题库分组开始，多题库时一次会话跨库启动并保留各自 `bank_id` 上下文。

### FN-215 会话生命周期（新建 / 进行中 / 暂存 / 完成 / 放弃）

- **存在目的与场景**：会话是学习域唯一的有状态实体。UX §7.6 要求 `status(active/completed/abandoned) + completed_at + result_json`。
- **入口与适用条件**：所有 `POST /practice/sessions` 与 `POST /exams/sessions`。
- **可执行操作**：新建；作答推进；退出暂存（会话仍 active）；交卷（completed）；放弃（abandoned）。**不提供「放弃全部」**（`CR-14`：跨模式会话互不提示、互不代管）；「结束并新建」也只结束**同模式**会话。
- **操作结果**：
  - `status` 迁移：`active → completed`（`complete`，写 `completed_at`、`result_json`、`score`、`time_spent`）；`active → abandoned`（`abandon_session`/`abandon_all_sessions`，写 `is_completed=1, status='abandoned'`）。`is_completed` 是派生列，历史 `is_completed=1` 已回填为 completed（UX §11.1 迁移 20）。
  - 终结态拒绝写入：`save_attempt` 见 `is_completed` → `ValueError("session already completed")` → 422；`update_draft`/`toggle_flag` 同理 → 409（`practice_repository.py:336-337, 540-541, 640-641`；`routes/practice.py:65-139`）。
  - 幂等：`client_attempt_id` 参与确定性 `uuid5`，同 key 的重放收敛到同一行（含 payload 已变的迟到重放）；无 key 的 legacy 提交只在答案与**最近一次**作答等价时判为重放（`practice_repository.py:56-68, 166-195`）。`complete` 对已有报告的会话逐字返回旧报告。
  - 退出暂存：`flushDraft()` 后 `doExit()`，会话保持 active，`current_index/answers_json/flags_json/time_spent` 已落服务端。
- **与其他功能的关系**：是 FN-204/206/214/219 的状态基础；`list_active_sessions` 是 FN-201 与 FN-203 的数据源。
- **当前缺失与不合理之处**：
  - **「退出」的文案与行为在模考里相反**：`ExamView` 退出确认标题是「放弃考试」，正文「放弃这场模考？本次作答不会计入成绩」，但 `handleConfirmExit` 实际只 `persistDraft(true)` 后离开，会话仍 active、之后还能继续（`ExamView.vue:349-356, 400-404`）。UX §7.3 要求「退出时明确二选一：暂存，稍后继续 / 结束本次」。练习侧已按此实现（「继续练习」/「保存并退出」），模考侧没有。
  - 放弃会话无独立可见状态（GAP-206）。
  - `list_active_sessions` 按 `updated_at DESC` 排序，`answered_count = len(answers_json)`，`total_questions` 为空时回退为 `len(questions_json)`（`practice_service.py:134-155`）——一个刚建、还没答的会话 `answered_count` 可能是 0 而 `total_questions` 正确，反之若 `total_questions` 列为 0 则显示错误总数。
  - 模考会话的自动交卷由服务端 `_exam_expired`（时限 + 60s 宽限）判定，客户端只在提交时收到 `EXAM_TIME_EXPIRED`；用户若不主动提交，永远不会看到「已自动交卷」的明确提示，只会在某次提交时突然失败。
  - 会话可跨模式并存（`CR-14`：只有同模式才被开始门提示，跨模式互不阻塞、互不提示），今天页只展示 `activeSessions[0]`，其余从「查看全部」轻量弹窗进入。
- **理想完成态**：
  1. 五种状态齐全且各自有可见表达：进行中（进度）、暂存（今天页未完成会话卡）、已完成（报告）、已放弃（明确的已放弃态）、已过期交卷（模考）。
  2. 退出统一二选一：「暂存，稍后继续」（会话保持 active）/「结束本次」（abandon，二次确认并预告后果）；文案与行为一致。
  3. 所有写入接口在终结态返回稳定的错误码与可读文案；离线队列在收到终结态错误时**停止重试**并丢弃该条（已实现 404/409/422 分支，保持）。
  4. 幂等键由客户端在一次用户动作时生成、重试与离线队列原样复用；一次新的用户动作必须换新键（已实现，保持）。
  5. 模考到点后客户端主动提示「时间已到，正在自动交卷」并导向报告，不依赖用户误触提交。

### FN-216 断点恢复与跨设备草稿冲突

- **存在目的与场景**：SPEC §3.1「支持断点恢复，但客户端缓存只作为保护层，服务端记录为主」。
- **入口与适用条件**：会话 runner 挂载时；`/practice/:sessionId` 深链、刷新、切设备。
- **可执行操作**：自动恢复（题目光标、已答答案、评级、旗标、用时）；处理跨设备冲突（保留服务器 / 使用本机）；重试同步。

  - `getSession` 返回 `current_index/answers/flags/time_spent/status/report/is_expired`；`hydrateSessionPractice` 把 `current_index` 钳到 `[0, len-1]`（`domain/practice.js:15-31`）。
  - 本地备份按「用户 + 会话」隔离，只在**比服务端 `updated_at` 更新**时合并，且从不覆盖已有 `result`/`correctness` 的答案（`practice.js:265-286`）。
  - **三类数据、三种合并策略**（`CR-23`）：① **学习记录类**（不可重建：已提交/已判分的作答、错题、FSRS 卡、掌握度、成绩报告）；② **用户创作类**（不可重建：人工编辑过的导入草稿、AI 草稿、未提交的答案内容）；③ **临时状态类**（可重建/低价值：题目光标、旗标、展开/折叠、滚动位置、计时、尚未提交的中间输入）。①②两类跨设备分歧时**保留两个版本并提示用户选择**，禁止静默覆盖；③类后写覆盖，但**覆盖时必须明确告知**「已被另一设备更新，已用较新版本替换」——允许覆盖，不允许静默覆盖。**判据是「这份内容是不是用户花力气做出来的」，不是「它存在哪张表里」**：同一条草稿在用户未编辑前可按临时状态处理后写覆盖，被人工编辑后必须升格为用户创作类。
  - 草稿同步带 `base_answers`（本机最后观察到的服务端值）；服务端发现本地值与非空服务端值分歧且 base 不吻合时，保留服务端值并回传 `conflicts`（`practice_repository.py:587-608`）。未解决冲突的题被 `withoutProtectedAnswers` 屏蔽，不再参与后续同步（`practice.js:385-395`）。
  - 冲突态跨刷新存活（草稿冲突标记持久化（具体键名是实现载体，P-12）），用户显式选择一侧后才解除保护。
  - 时间戳解析把无时区的 SQLite `CURRENT_TIMESTAMP` 钉为 UTC，避免本地草稿被误判为更新（`practice.js:215-223`）。
- **与其他功能的关系**：与 FN-217（离线队列）、FN-218（同步）共同构成「换设备/断网不丢答案」。
- **当前缺失与不合理之处**：
  - 冲突提示是一条常驻 banner，用户不处理也能继续做别的题；已保护题的答案在答题卡上看不出「这台设备上的作答未被保存」。
  - 草稿 flush 由答案变化触发（600ms 防抖），只读不答的用户在 `pagehide`/`visibilitychange`/卸载时才同步 `current_index` 与 `time_spent`；中途杀进程会丢光标。
  - 恢复后 `elapsedSeconds` 从服务端 `time_spent` 起算，但服务端取的是 `max(当前, 传入)`（`practice_repository.py:623`），跨设备会各自累加后取最大，不是真实总时长。
- **理想完成态**：
  1. 光标与旗标在每次翻题时即同步（不等答案变化），`time_spent` 由服务端按「会话维度累计」而不是客户端覆盖。
  2. 未解决的冲突在答题卡对应格上给出标记，banner 提供「批量保留服务器 / 批量使用本机」。
  3. 恢复时若服务端该题已有判分结果，本地草稿绝不回填（已实现，保持）。

### FN-217 离线作答队列与重试

- **存在目的与场景**：NAS 内网弱网场景下不丢已作出的答案。
- **入口与适用条件**：提交/评级请求遇到网络错误时入队；`online` 事件、重试按钮、恢复挂载时排空。
- **可执行操作**：自动重试（两档防抖（短档约 0.25s、长档约 0.6s；取值为实现载体，P-12））；手动「重试同步」；查看待同步提示。
- **操作结果**：`queuePendingAttempt` 按 `sessionId::questionId::clientAttemptId` upsert，答案与评级共用一条（`practice.js:321-335`）；`drainPendingAttempts` 逐条重放，成功后按 key 精确出队，收到 404/409/422 直接丢弃并提示，其他错误中止本轮（`PracticeViewV1.vue:1372-1419`）。交卷前若有未同步条目，拒绝交卷并提示（`:2117-2122`）。离线编辑队列只服务题目页编辑（题库域）：会话内编辑入口取消后，runner 不再维护题目编辑队列。
- **与其他功能的关系**：与 FN-215 幂等键强耦合（重放不产生第二次 attempt）；与 FN-216 共享本地备份。
- **当前缺失与不合理之处**：
  - 待同步状态只在 runner 内可见；用户离开练习页后，今天页与复习页都不知道「还有 N 条作答没上传」。
  - 网络恢复只在 `online` 事件与手动重试时触发；如果 `online` 事件丢失（部分移动浏览器），队列会一直挂着。
  - 队列按用户隔离已实现，但切换账号后旧账号的队列不会被提醒，也不会在新账号下误放（已实现，保持）。
- **理想完成态**：
  1. 全局待同步计数进入侧栏「学习状态」，点击跳到对应会话。
  2. `online` + 定时轮询（如 30s）+ 手动重试三重触发；队列非空时常驻一个可展开的同步状态条。
  3. 队列条目展示题目摘要与失败原因，支持单条丢弃。

### FN-218 跨设备同步

- **存在目的与场景**：SPEC §2.1「同一用户的手机、电脑、平板需要实时同步」。
- **入口与适用条件**：`useSyncLoop` 挂在 `App.vue`（全应用生效），30s 轮询 + focus/online 触发。
- **可执行操作**：无（用户不可见）；业务侧通过 `triggerSyncEvent` 上报。
- **操作结果**：`listEvents(token, cursor)` 拉取 `learning_events`，**同步游标按设备（或按独立消费方）维护**：每个消费方各自记住自己消费到的事件序号，**禁止因另一设备/另一个标签页推进游标而导致本端漏收事件**；同一浏览器多标签页视为多个独立消费方（`CR-23`）。请求序号锁防止切账号时旧账号事件误派发（`useSyncLoop.js:37-82`）；拿到事件后派发同步完成事件。练习 runner 收到当前题的题目事件会重取题目与版本、检测答案冲突；今天页收到题库/题目事件刷新题库、收到会话事件刷新活跃会话。
- **与其他功能的关系**：是 FN-216 冲突检测的上游；与同步域分册共享事件契约。
- **当前缺失与不合理之处**：
  - 只推送「事件发生了」，不推送状态本身；刷新动作由各页面自行决定，容易出现「事件到了但页面没重取」的缝隙（例如复习页不监听 `SESSION` 事件，作答后到期计数不会自动变）。
  - 轮询 30s + 游标**按用户**存在客户端，同一浏览器多标签会各自推进游标、互相吞事件。**按 `CR-23` 这是错误实现**：必须改为按设备/按独立消费方维护游标，禁止一个标签页推进游标导致另一个标签页漏收事件。
  - `emitSyncEvent` 失败只 `console.warn`，用户无感知。
- **理想完成态**：
  1. 学习域的四类聚合（BANK/QUESTION/SESSION/USER）都有明确的页面级响应矩阵，测试锁定。
  2. 游标按设备（或按独立消费方）维护，存服务端亦可；**删除「按用户单一游标 + 多标签共享」的写法**——每个消费方各自记住自己消费到的事件序号，禁止因另一设备/另一个标签页推进游标而导致本端漏收事件（`CR-23`）。
  3. 上报失败进入与 FN-217 同一条待同步通道，对用户可见。

### FN-219 模考会话在学习域中的接口（低频）

- **存在目的与场景**：模考的组卷与配置属于模考域，但「模考结果如何进入学习域」由本册定义。SPEC §4.1：模考是否进入错题由考试配置决定。
- **入口与适用条件**：`POST /exams/sessions`（`routes/exams.py:63-79`）；今天页模考设置浮层（题数/时长/蓝图/**本场是否纳入学习记录**）。模考开始与练习共用同一个开始决策门（`CR-14`）。
- **可执行操作**：设置并开始模考；交卷；查看成绩报告。
- **操作结果**：
  - 未交卷前模考 runner 自身不透露对错与答案：`submit_attempt` 对 EXAM 只回 `feedback_available:false`；`get_session` 对未完成 EXAM 剥离 `answer/explanation`，`answers` 只留 `answer/user_answer`（`practice_service.py:253-261, 307-318`）。**遮蔽只作用于模考 runner**：题库内容管理、题目页、版本历史、普通练习、错题视图在任何情况下都不因「有未交卷模考」而隐藏答案或解析（`CR-26`）。
  - 单题不写 FSRS（`practice_repository.py:469, 475` 的 `if not is_exam` 守卫）；交卷跃迁时按「本场是否纳入学习记录」（会话级优先、蓝图回退）给客观题排卡：**错/部分 → Again；答对且本题已有卡片 → Good；答对且本题无卡片 → 不建卡**（统一建卡原则见 `BR-218`）；主观题跳过；只在 `active → completed` 执行，天然幂等（`practice_service.py:347-369`，`practice_repository.py:727-777`）。
  - 「本场是否纳入学习记录」是模考会话级总开关，**默认开**；关闭时本场完全不写入学习域：不写错题、不写也不推进 FSRS、不计入任何学习统计与趋势；会话快照与作答记录仍保存，报告仍可正常生成与回看，报告内的错题列表是这些错题的唯一可见出口（`CR-08`、`Q-207` 裁定 A）。半写入（写了错题却不调度）明确禁止。
  - 到点 +60s 后服务端拒收**继续作答**与草稿，返回稳定的 `EXAM_TIME_EXPIRED`（`practice_service.py:7-19, 190-192`）；`is_expired` 不是终结态，**交卷（complete）与报告读取必须放行**（`CR-31`）。
  - 报告用 `grade_report(attempts, blueprint)` 计总分（支持负分等规则）；计数口径统一为 `CR-06` 的五项：**已答（含未判分）/ 未答 / 未判分 / 客观题得分与客观题满分 / 卷面总分与满分（主观题标注「未判分，不计入」）**，正确率按客观题总数计（`practice_service.py:418-473`）。
- **与其他功能的关系**：是 FN-209/FN-210/FN-211 的写入源之一；复用 FN-215 生命周期与 FN-216/217 草稿离线机制。
- **当前缺失与不合理之处**：
  - **生产仍存在三处旧脱敏实现，按 `CR-26` 方向是删除，不是统一**：① `question_repository` 读侧脱敏 + `locked_by_active_exam` 标记，对 `time_limit > 0` 的会话应用「时限 + 60s」失效判定（`question_repository.py:510-527`）；② `practice_repository.list_mistakes` 自算的 `active_exam_qids`，**没有任何失效判定**（`practice_repository.py:803-816`）；③ `time_limit = 0`（不限时）的未交卷模考会**永久**遮蔽这些题的答案与解析，直到用户显式放弃该会话——而用户没有任何地方被告知这件事。`CR-26` 已裁定：遮蔽只作用于模考 runner 自身，题库与普通练习侧的旧脱敏规则**彻底清除，不是留着不用**；保留的只有「常驻『有未交卷模考』提示 + 一键去交卷/放弃」与「不限时会话长期无活动后明确失效并告知」（`Q-206`，N 由 30 册统一定义，默认 30 天）。
  - 模考开始不走 FN-203 的活跃会话门（GAP-203）。**这是已裁定的缺陷，不是刻意不做**：`CR-14` 要求所有入口（含模考）共用同一个开始决策，同模式冲突时提示「继续 / 结束并新建 / 取消」，本期必须修（模考侧登记见 30 册 `GAP-312`）。
  - 模考退出确认的文案与行为相反（FN-215）。
  - 交卷报告里未作答题也列出标准答案（`practice_service.py:453-466`），但 `answers` 的 `mastery_status` 一律写 `UNSEEN`，与「这道题我见过但没答」混淆。
- **理想完成态**：
  1. **删除题库侧与普通练习侧的旧脱敏实现**：读侧脱敏、`locked_by_active_exam` 标记、错题/练习侧各自计算的「活动模考题目集合」、`time_limit=0` 永久遮蔽、60s 宽限脱敏判定一律移除；遮蔽只保留在模考 runner 自身（`CR-26`）。
  2. 侧栏/今天页常驻「有未交卷的模考」提示，一键去交卷或放弃；不限时会话连续无活动达到阈值（默认 30 天，可配）后**明确失效并告知**，失效后仍由用户显式选择交卷或放弃，不静默、不自动判成绩（`CR-31`）。
  3. 模考开始与练习共用活跃会话门。
  4. 交卷报告对未作答题明确区分「未作答」与「无学习记录（UNSEEN）」；主观题按「已作答 · 未判分」计入已答数，不计入客观题得分（`CR-06`）。

## 3. 业务规则（BR-2xx）

| 编号 | 规则 |
|---|---|
| BR-201 | 学习状态按 `(user_id, question_id)` 聚合，不按题库。同一用户在不同题库看到同一道题（复制产生的新实体除外）的同一份错题/FSRS/斩杀/薄弱状态。UX §7.6 明确「不建议改成 (user, question, bank) 三维主键」。用户退出题库**不销毁**任何个人学习记录：作答、错题、FSRS 卡、斩杀、薄弱全部保留，界面标注来源题库与「已退出」（`CR-02`；相关界面清晰度问题见 40 册 `GAP-427`）。**失去访问权后的可执行学习队列、进行中会话与恢复规则见 `CR-30` 与 `PR-202`**：该库题目移出一切可执行学习队列但历史资产全部保留并继续进统计，进行中会话可按快照答完交卷，重新成为成员后凭原有学习状态恢复学习能力。 |
| BR-202 | `mistake_records` 是用户级错题事实表，`learning_records` 保存掌握状态与统计；一次作答必须在同一事务内同时更新两者（SPEC §6 实现约束；`practice_repository.py:400-468`）。 |
| BR-203 | 判分必须拆成 `score_ratio`（得分比例 0–1）、`correctness`（CORRECT/PARTIAL/INCORRECT，**只在已判分时有值**；`UNANSWERED` 取值废止，`CR-06`）、`mastery_status`（MASTERED/PARTIAL/WEAK/UNSEEN）三个字段，不得用一个布尔代替，也不得让一个字段同时表达「答了没有」与「判了没有」（SPEC §3.1；`scoring.py:56`）。 |
| BR-204 | 多选漏选（用户选项是正确选项的真子集）得 0.5 分、`correctness=PARTIAL`，**不得**视为完全答对、不得置 `mastery_status=MASTERED`、不得触发错题出库（SPEC §3.1；`scoring.py:41-42`）。 |
| BR-205 | 主观题（ESSAY/SHORT_ANSWER/SUBJECTIVE）不自动判分（`CR-06`）：**保存答案即「已作答」，判分状态为「未判分」，不得显示为未作答**；`is_objective=false`，不计入客观正确率，`score_ratio` 不参与得分计算（SPEC §5.1；`scoring.py:27-33`）。**本期不增加主观题自动判分功能**。 |
| BR-206 | 单选/判断：答案与标准答案去空格、大写后全等才算 CORRECT；判断题接受 TRUE/1/正确/对/YES/Y/T 与 FALSE/0/错误/错/NO/N/F 的同义词（`scoring.py:16-22, 45`）。 |
| BR-207 | 连续 2 次答对使错题 `is_cleared=1`（出库但保留记录）；任一次答错或部分得分使 `consecutive_correct=0`、`mistake_count+1`（`practice_repository.py:422-429`）。 |
| BR-208 | 错因固定六种：审题遗漏、概念欠缺、思路不熟、陷阱诱导、计算错误、其他手误。错因持久化到 `mistake_records` 且可修改；新作答不带错因时保留旧值（`practice_repository.py:465`）。 |
| BR-209 | 错题专项（MISTAKE）的服务端集合约束：`question_ids` 必须属于该用户**未清除**的错题集合，否则该题被剔除；候选题集为空时直接 400，不得退化为整库练习（SPEC §4.1；`practice_service.py:44-47, 102-118`）。**「未清除错题」是一个原因标签，不是独立的到期口径**：到期集合唯一定义见 `CR-05`；错题连续 2 次答对后 `is_cleared=1`，只改错题状态，不删 FSRS 卡、不移出调度（`Q-202` 裁定 B）。 |
| BR-210 | FSRS 专项（FSRS 模式）的服务端集合约束：`question_ids` 必须属于当前已到期集合（`practice_service.py:48-51`）。已到期集合口径唯一，见 `CR-05`；**未到期的薄弱题不进任何到期视图**，它只出现在薄弱视图（`GAP-222`、`CR-29`），从那里开始的会话是普通练习（`PRACTICE`），不是 FSRS 专项。 |
| BR-211 | 斩杀专项（ELIMINATION）的服务端集合约束：`question_ids` 必须属于已斩杀集合，且必须保留 `bank_id` 上下文（SPEC §4.3；`practice_service.py:42-43`，`question_repository.list_for_elimination`）。 |
| BR-212 | 任何专项模式都不得因客户端漏传或伪造筛选参数而退化为整本普通刷题（`EASYEXAM_GUARDRAILS.md`「专项题目集合」）。 |

| BR-237 | 复习队列 = **当前可执行复习集合**（`CR-05`）：**到期是卡片属性 `due_at <= now`；可执行复习集合 = 到期 ∧ 未被当前用户斩杀 ∧ 未被归档 ∧ 当前用户对该题所属题库仍有访问权**。四条条件任一不满足即不进集合，但**该题保留原有学习状态，不删除不重置**；条件恢复（取消斩杀 / 取消归档 / 恢复成员资格）时**凭原有卡片状态重新进入，不重新从零开始**。集合由同一个服务端方法 `list_due_reviews(user, bank?)` 供给（方法名是实现载体，P-12），队列/今日/趋势/推荐/计划共用，禁止各处各写 SQL。按 `(bank_id, question_id)` 去重，一行可带多个原因标签；原因标签固定三种：**错题未清除 / 薄弱 / 巩固**（可叠加）。行序按主原因分桶：错题未清除 → 薄弱 → 巩固（`domain/reviewQueue.js:72-111`）。斩杀题不在队列内，斩杀题库是独立视图。 |

| BR-239 | `mark_weak` 立即建一张 `state=0, stability=0, difficulty=5, due_at=now` 的卡，即标记后立刻进入到期队列（`practice_repository.py:874-878`）。 |
| BR-240 | 取消薄弱标记时，仅当该卡从未被复习且无未清除错题才连同卡片删除（`practice_repository.py:881-891`）。 |
| BR-241 | 多用户之间无法读取彼此的作答、错题、AI 解释、斩杀状态与复习计划（SPEC §2.1；所有仓储查询都带 `user_id`）。 |
| BR-242 | 跨设备数据保护分三类（`CR-23`，细则见 `BR-227`）：**学习记录类**（作答、错题、FSRS 卡、掌握度、成绩报告）与**用户创作类**（人工编辑过的草稿、未提交的答案内容）不可重建，多设备修改按服务端事件顺序合并，无法自动合并时保留两个版本并提示用户选择，禁止静默覆盖；**临时状态类**（题目光标、旗标、展开/折叠、滚动位置、计时、尚未提交的中间输入）后写覆盖 + 覆盖时明确告知（SPEC §6；FN-216 冲突流）。 |

**推荐排序优先级表（`BR-234` 细化）**：

| 顺位 | 原因 | 优先级 | 含义 |
|---|---|---|---|
| 1 | 错题待复习 | 100 + min(mistakes, 20) | 有未清除错题；错题次数越多越靠前 |
| 2 | 薄弱 | 90 | 用户主动标记薄弱 |
| 3 | 复习到期 | 80 | 属于 `CR-05` 的可执行复习集合 |
| 4 | 新题覆盖 | 50 | 从未作答过 |
| 5 | 巩固练习 | 20 | 错题已清除、FSRS 卡仍在调度的低优先级补充项 |

同优先级按 `last_attempt_at`（无则视为最早）、`question_id` 稳定排序。同一题可同时命中多个原因时，取最高优先级的原因作为其分组依据。**推荐排序与复习队列行序是两套不同的排序**：复习队列按主原因分桶（错题未清除 → 薄弱 → 巩固，`BR-237`），推荐按上表优先级；推荐池可以容纳未到期题（否则「新题覆盖」「巩固练习」没有意义），到期视图不能。

### 3.1 操作与交互（OP-2xx）

- **OP-201 开始学习唯一入口**：所有「开始练习/开始复习/开始错题/开始斩杀/开始模考」按钮都调用同一个动作；带完整参数时直接开始，否则打开开始面板。开始前必须询问服务端是否有**同模式**未完成会话；有则先决策，不静默叠第二个同模式会话。取消路径零写入。面板三选：取消 / 继续 / 结束并新建；「结束并新建」的作用范围写在按钮或正文里，且**只覆盖同模式会话**——跨模式会话允许并存，互不提示、互不代管（`CR-14`）。
- **OP-202 作答与判定的操作序列**：单选/判断——默认「选择后点提交答案」再判定并展示反馈、标准答案与解释；提供「点选即判」可选模式（`Q-201` 裁定）；两种模式都**不提供**提交后的模糊改判窗口。多选——可反复增删选项，点「提交答案」后判定；填空/主观——输入后提交，只保存不自动判分。判定后选项与输入框禁用，不能再改；要改只能重开一轮。
- **OP-203 评级操作序列**：仅在 FSRS / MISTAKE 模式的反馈区出现。提交答案后点选 Again/Hard/Good/Easy，或先答后评（两步交互）。答错只允许 Again 并默认预选；部分得分最高 Hard；答对四项全开。改评级对同一次作答生效，不产生第二次 attempt。键盘 1–4 等价；浮层打开时快捷键挂起。**评级按钮旁不展示写死间隔**：能算出真实到期日时显示该题按当前快照的实际到期日期，算不出时不显示间隔（`Q-210` 裁定）。
- **OP-204 会话内导航**：上一题/下一题/答题卡跳转/跳到下一道未答/左右滑动（输入框、按钮、代码块上不触发）；翻题即保存光标与当前题状态；已作答题回看时展示当时的判定与评级，不重新判分。
- **OP-205 会话退出二选一**：退出必须二选一——「暂存，稍后继续」（保存草稿、会话保持 active）或「结束本次」（放弃会话、二次确认并预告后果）。文案与行为必须一致； Esc、遮罩、关闭按钮等于「继续练习」。已交卷/已放弃的会话点退出直接离开，不再确认。
- **OP-206 交卷确认**：有未作答题时确认框列出未答数量并警告「交卷后不能再修改答案」；FSRS/MISTAKE 模式下还需列出未评级题数、写明默认调度规则，并提供「回去评级」入口（不强制逐题评级，`Q-203` 裁定 A）；确认后交卷，交卷中按钮禁用防重复点击。
- **OP-207 弹窗与取消路径**：学习域每个弹窗（开始面板、交卷确认、退出确认、放弃确认、草稿冲突、斩杀确认、答题卡抽屉、快捷键帮助、报告）都必须同时有确认与取消/关闭两条出口；Esc 与遮罩等于取消；危险动作用危险样式且初始焦点在取消；取消路径不得产生任何写入。禁止原生 `alert`/`confirm`/`prompt`。
- **OP-208 复习队列 URL 契约**：`?tab=due|mistakes|weak|killed`（默认 `due`，默认值不写地址；旧值 `all`/`due` 重定向到 `due`，旧值 `diagnosis` 重定向到 `/review/diagnosis`，`Q-208` 裁定 B、`CR-29`）、`?source=all|mistakes|weak|consolidation`（原因子集，只对待复习视图有意义）、`?q=`（题干）、`?scope=`（题库 id 或 all）、`?bank=`、`?cause=`；地址↔控件双向同步（后退、粘贴、刷新都复现同一现场）；搜索 250ms 防抖且用 `replace` 写回，不产生历史条目；未知题库 id 与未知原因值回退到默认值并修正地址。只收「值得回来还在、值得分享」的状态；展开/hover/未提交输入/滚动等临时交互态不进 URL（`CR-16`）。
- **OP-209 行内操作的即时反馈**：改错因、斩杀、恢复、标记薄弱、采纳解释版本都是行内/就地操作，必须即时反映在列表上；失败时回滚本地值并把错误保留在原处（不塌成整页错误、不弹原生框）。
- **OP-210 请求竞态与降级**：今天页与复习页的多接口并发用 `allSettled`；只有「页面主题数据源」失败才整页报错，次要来源（薄弱、计划、趋势、推荐）各自降级并给重试；整页加载失败才升级为整页状态。列表请求用单调序号，只有最新请求能写状态。
- **OP-211 离线与重试的操作可见性**：待同步条目在 runner 内可见（横幅 + 重试按钮），并在侧栏给出全局计数；`online`、定时轮询、手动重试三重触发；交卷前有未同步条目时拒绝交卷并说明原因。
- **OP-212 跨设备冲突的操作**：冲突以横幅呈现，逐题列出「服务器值 / 本机值」，提供「保留服务器」「使用本机」两个明确动作；未解决的题在答题卡上带标记，且不再参与后续草稿同步；冲突状态跨刷新存活。

## 4. 数据关系与状态变化

### 4.1 实体关系（学习域视角）

```text
users ──< answer_attempts >── questions ──< question_versions
  │                                │
  ├──< practice_sessions >─────────┤   (questions_json 快照 = [{question_id, version_id, bank_id}])
  │        └─ result_json（完成报告）
  ├──< fsrs_cards >────────────────┤   PK (user_id, question_id)
  ├──< mistake_records >───────────┤   PK (user_id, question_id)，冗余 bank_id
  ├──< learning_records >──────────┤   PK (user_id, question_id)
  ├──< weak_question_flags >───────┤
  ├──< kill_records >──────────────┘
  ├──< learning_events（跨设备同步）
  └──< explanation_versions / explanation_evidence（经题目）
```

学习域五张「每题一份」的状态表（`fsrs_cards` / `mistake_records` / `learning_records` / `weak_question_flags` / `kill_records`）主键都是 `(user_id, question_id)`，没有 `bank_id` 维度（仅 `mistake_records` 冗余存了一个）。UX §5.4 与 §7.6 明确这是有意的取舍：真实数据 1:1，不做三维主键。

### 4.2 会话状态机

```text
                    ┌──────────────────────────────────────────────┐
                    │                                              │
  POST /sessions    ▼                                              │ 退出（保存草稿）
  ─────────────►  [ active ] ── 交卷 complete ──► [ completed ]      │
                    │  │                        （result_json 写入） │
                    │  └── 放弃 abandon ────────► [ abandoned ]      │
                    │                                                 │
                    └── 模考超时（limit + 60s）──► is_expired = true  │
                                          （拒绝继续作答；交卷与报告读取放行，CR-31）
                                                       │             │
                                                       └─ 交卷 ──────┘
```

| 状态 | 判定 | 允许的写入 | 界面表达 |
|---|---|---|---|
| `active` | `status='active' AND is_completed=0` | attempts / sync(draft) / toggle-flag / complete / abandon | 答题器 + 进度 |
| `active` + `is_expired`（仅 EXAM） | 超时未交卷；**会话本身仍是 `active`**，`is_expired` 是派生态，不是终结态（`CR-31`） | **拒绝的是继续作答**：attempts / 草稿同步 / 标记（422/409 + `EXAM_TIME_EXPIRED`）；**交卷（complete）与报告读取必须放行** | 客户端应停止重试并导向报告 |
| `completed` | `status='completed'`，`result_json` 非空 | 无；`complete` 幂等返回旧报告 | 报告页 |
| `abandoned` | `status='abandoned'`，`result_json` 为空 | 无 | 明确的「这个会话已放弃」态 + 返回，不给重试（现状被渲染成「读取失败」，`GAP-206`） |

状态迁移的写入点：`practice_repository.complete`（`active → completed`，写 `completed_at`）、`abandon_session` / `abandon_all_sessions`（`active → abandoned`）。`is_completed` 是派生列，所有既有查询沿用（UX §11.1 迁移 20）。`is_expired` 是 `active` 上的派生态而非终结态：它只拒绝继续作答（attempts / 草稿同步 / 标记），`complete` 与报告读取必须放行（`CR-31`）；「`is_expired` 后全部拒绝」的历史口径废止。

### 4.3 FSRS 卡片状态机

```text
  mark_weak ──► [ New(0) ] ◄── 首次评级且 stability<=0
                   │  rating=1 → state=1(Learning), due=+1d
                   │  rating=2 → state=1, due=next_interval(S)
                   │  rating>=3 → state=2(Review), due=next_interval(S)
                   ▼
              [ Learning(1) / Review(2) ]
                   │  rating=1 → state=3(Relearning), due=+1d
                   │  rating>=2 → state=2, due=next_interval(S')
                   ▼
              [ Relearning(3) ] ── rating>=2 ──► [ Review(2) ]
```

- `state`：0=New、1=Learning、2=Review、3=Relearning（`legacy/services/fsrs.py:33, 200-232`）。
- `stability` / `difficulty`：`difficulty` 线性阻尼 + 向 `D0(4)` 均值回归，钳在 [1,10]；`stability` 按评级走 lapse 或成功回忆公式，同一天内的复习走 `same_day_stability` 防通胀。
- `due_at` = `now + next_interval(stability)`，`next_interval` 由保持率 0.9 反解；下限 1 天。
- `elapsed_days` = 作答时间 − 卡片 `last_review_at`，用于检索率计算；快照里 `last_review_at` 为 null 时取 0。
- 快照基准：每次**新** attempt 落库前读取当前卡片写入 `card_snapshot_json`；两步交互的评级更新从该行快照重算，不在已更新过的卡片上叠加。

### 4.4 关键联动写入（一次作答的同事务副作用）

```
submit_attempt
  ├─ answer_attempts        （id = uuid5(namespace, user|session|question|key|seq)，带 card_snapshot_json）
  ├─ practice_sessions.answers_json
  ├─ learning_records       （mistake_count / consecutive_correct / mastery_status / is_cleared / last_attempt_at）
  ├─ mistake_records        （仅当 mistakes>0 且 record_mistakes）
  ├─ fsrs_cards             （仅当非 EXAM 且满足 `BR-218` 建卡三条件：本题已有卡 / 本次错或部分得分 / 本题已标记薄弱）
  ├─ kill_records           （仅 ELIMINATION 且答错 → 删除，即恢复）
  └─ learning_events        （ANSWER_ATTEMPTED，跨设备同步用）
```

「本场是否纳入学习记录」的解析顺序：**会话级设置优先**，缺省回退蓝图同名字段（仅模考），再缺省为**开**（`practice_repository.py:411-420`，`record_mistakes_for_session` 与之保持一致）。普通练习不暴露该开关，恒为开（`CR-08`、`Q-207` 裁定 A）。

### 4.5 状态定义（ST-2xx）

- **会话（ST-201）**：`active → completed | abandoned`；`active`（EXAM 且超时）叠加 `is_expired` 后**只拒绝继续作答**（attempts / 草稿同步 / 标记），**交卷（complete）与报告读取放行**（`CR-31`）——`is_expired` 不是终结态，会话本身仍是 `active`。异常转换：对 `completed`/`abandoned` 提交作答 → 422「session already completed」；对已放弃会话补交卷 → 409；`complete` 对已有报告的会话是幂等只读，不产生新状态。`abandoned` 与 `completed` 在 `is_completed` 上同值，靠 `status` 区分（迁移 20 起）。
- **FSRS 卡片（ST-202）**：`New(0) → Learning(1) | Review(2) → Relearning(3) → Review(2)`；`rating=1` 一律进 Relearning 且间隔 1 天；`rating>=2` 进 Review；`rating>=3` 在首次调度时也可直接进 Review。异常转换：快照缺失时的二次评级更新（见 BR-217）不推进状态机，只写反馈。
- **作答判定（ST-203）**：`correctness` 取值 `CORRECT` / `PARTIAL` / `INCORRECT`，**只在已判分时有值**；`UNANSWERED` 取值**废止**（`CR-06`）。「答没答」由**作答状态**（未作答 / 已作答，依据是用户是否为该题保存了非空答案）表达，「判没判」由**判分状态**（已判分 / 未判分）表达，两者不得互相替代。主观题永远停在「**已作答 · 未判分**」。`mastery_status` 由判定 + 历史推导（`MASTERED/PARTIAL/WEAK/UNSEEN`），不直接等于「对/错」，也不因「保存了答案」变成已掌握、不因「不能自动判分」变成未作答。
- **错题（ST-204）**：`未清除 → 已清除`（连续 2 次答对）；`已清除 → 未清除`（任一次答错或部分得分，`mistake_count+1`）。异常转换：本场不纳入学习记录的会话完全不进入本状态机；斩杀使错题从所有学习域列表消失但记录保留。**已清除不出队**：FSRS 卡继续调度，题之后到期时以「巩固」原因低优先级进队列（`CR-05`）。
- **斩杀（ST-205）**：`未斩杀 → 已斩杀`（仅用户主动）；`已斩杀 → 未斩杀`（用户恢复，或 ELIMINATION 专项中答错一次）。**没有**任何时间驱动的自动恢复。异常转换：系统自动斩杀 → 禁止。
- **薄弱标记（ST-206）**：`未标记 → 已标记`（用户主动，同时建一张立即到期的卡）；`已标记 → 未标记`（用户主动；卡片仅在从未复习且无未清除错题时一并删除）。异常转换：答错不会自动标记薄弱；答对也不会自动取消。
- **练习报告（ST-207）**：`不存在 → 已生成`（`active → completed` 跃迁时一次性写入 `result_json`）；已生成后不可再生成、不可被题目后续修改影响。异常转换：缺少 `result_json` 的历史完成会话 → 可重试的「报告不可读」态，不是「加载失败」也不是「已放弃」。
- **草稿与冲突（ST-208）**：`无冲突 → 有未解决冲突`（跨设备写入分歧）→ `已解决（保留服务器 | 使用本机）`。未解决冲突的题处于「本机值被屏蔽」态，不参与后续同步；冲突状态跨刷新与跨页面存活。

## 9. 待裁问题与裁定结果（Q-2xx）

> 本册 Q-201～Q-210 **全部已裁定，0 条留给用户**。每条只保留问题与最终裁定（含一行结论）；候选方案与「未裁定时的默认行为」随裁定失效，过程记录见 `80` 册 §6。裁定结果的正文规则已写入上方 FN / BR / OP 对应条目。

### Q-201 单选/判断是否「点选即判」
- **问题**：SPEC §3.1 写「单选/判断支持点选即判并展示反馈、标准答案和解释」；生产实现与原型都是「选择后必须点提交答案/按 Enter 才判」。
- **状态**：**已裁定**（A 为主 + C 可选；**覆盖 80 册原推荐 B**）。
- **裁定**：单选/判断保留**明确提交模式**为默认路径——选择后可改，点「提交答案」后判定并展示反馈、标准答案与解释；「点选即判」作为**可选模式**提供（设置项切换）。**「点选即判」的设置入口属本期必须提供（`FN-516`，50 册），不是可选项**；自动保存开关暂不增加，保持默认自动保存。**明确不做「800ms 内可修改」的模糊判分窗口**：判定必须是明确事件，要么提交前可改，要么提交后定版，不存在「点了但还能偷偷改回去」的中间态。多选保持「提交后判」。SPEC §3.1 的相关表述按「可选模式」落地，不得写成唯一模式。
- **结论**：默认两步提交，点选即判降为可选开关，模糊改判窗口明确否决。

### Q-202 已清除错题的 FSRS 卡是否还应进入到期队列
- **问题**：错题连续 2 次答对后 `is_cleared=1`，但 FSRS 卡仍在调度。现行 `list_due_reviews` 要求「有 weak 标记或有未清除错题」，因此这类卡到期后永远不会出现在队列里。
- **状态**：**已裁定**（B，即 `CR-05` 的「巩固」口径）。
- **裁定**：错题连续 2 次答对后只把错题状态改为「已清除」，**不删除 FSRS 卡、不移出调度**。该题之后到期时仍进复习队列，但带「巩固」原因标签并以低优先级呈现。「巩固」= 错题已清除、FSRS 卡仍在调度的低优先级复习原因，与「错题未清除」「薄弱」一样是叠加在到期题上的原因标签，不是独立的到期口径。档案需能分别展示「已清除错题数」与「仍在调度的卡数」。
- **结论**：已清除错题不出队，卡继续调度，以「巩固」低优先级原因出现在队列。

### Q-203 交卷时未评级作答的默认定级是否应告知
- **问题**：FSRS/MISTAKE 模式下答完不点评级直接交卷，服务端按「错/部分→Again；答对且本题已有卡片→Good；答对且本题无卡片→不建卡」自动定级（`BR-218`）。
- **状态**：**已裁定**（A）。
- **裁定**：默认调度规则本身保留（错/部分→Again；答对且本题已有卡片→Good；答对且本题无卡片→不建卡，即 `BR-218` 的建卡三条件），但交卷确认框必须列出未评级题数、写明默认规则，并提供「回去评级」入口。不强制逐题评级，不静默定级。
- **结论**：交卷确认告知未评级题数 + 默认规则 + 「回去评级」入口，不强制、不静默。

### Q-204 「到期」的统一口径
- **问题**：`list_due_reviews` / `trends.due` / `recommendation_candidates.is_due` 三处定义不同（见 GAP-209）。
- **状态**：**已裁定**（A，即 `CR-05` 的唯一定期口径）。
- **裁定**：全产品只有一个到期口径——卡片属性 `due_at <= now`；可执行复习集合 = 到期 ∧ 未被当前用户斩杀 ∧ 未被归档 ∧ 当前用户对该题所属题库仍有访问权。复习队列、今日队列、趋势、推荐、计划全部调用同一个服务端方法 `list_due_reviews(user, bank?)`（方法名是实现载体，P-12），禁止各处各写 SQL。「错题未清除 / 薄弱 / 巩固」是叠加在到期题上的原因标签，可多选叠加，不是独立的到期口径；未到期题不进任何到期视图（错题视图与薄弱视图不受此限，`CR-29`）。
- **结论**：到期收敛为一个服务端方法、一个口径，三类原因降为可叠加标签。

### Q-205 复习完成度在无数据时的取值
- **问题**：`review_completion_rate` 在无到期且无完成时返回 100.0（`practice_repository.py:1098`）。
- **状态**：**已裁定**（A）。
- **裁定**：无到期且无已完成复习时返回 null，界面显示「—」/「暂无数据」。统计类数字一律不得用误导性的 0% 或 100% 填充空态；请求失败同样降级为「—」而不是 0。
- **结论**：无数据返回 null 显示「暂无数据」，不用 0% 或 100% 冒充。

### Q-206 未交卷模考对答案的遮蔽是否应有显式提示
- **问题**：一个未交卷（尤其 `time_limit=0`）的模考会话会持续遮蔽其所含题的答案与解析，影响普通刷题与错题队列，且用户无从知晓。
- **状态**：**已裁定**（A + B）。
- **裁定**：今天页/侧栏常驻「有未交卷的模考」提示，提供一键「去交卷」或「放弃」；不限时会话连续无活动达到阈值（N，由 30 册统一定义，默认 30 天）后**明确失效并告知**用户，不无限期挂网。**遮蔽相关部分按 `CR-26` 作废**：遮蔽只作用于模考 runner 自身，题库与普通练习侧的答案遮蔽规则彻底清除，不再有「模考进行中，暂不显示答案」这类提示。
- **结论**：常驻未交卷提示 + 不限时会话 N 天无活动后明确失效并告知。

### Q-207 练习是否需要「是否记录错题」开关
- **问题**：`record_mistakes` 目前只对模考暴露（SPEC §4.1 也只规定模考由考试配置决定）。练习/错题/FSRS/斩杀一律记录。
- **状态**：**已裁定**（A，即 `CR-08`）。
- **裁定**：「本场是否纳入学习记录」是会话级总开关，**只对模考暴露，默认开**；普通练习不暴露此开关，默认记录学习过程。开启时交卷判分写错题并同样写 FSRS 卡；关闭时本场不写错题、不写也不推进 FSRS、不计入任何学习统计与趋势，报告仍可回看，报告内的错题列表是这些错题的唯一可见出口。半写入（写了错题却不调度）明确禁止。
- **结论**：普通练习不暴露该开关、默认记录；仅模考暴露且默认开。

### Q-208 学习档案是否提为一级视图
- **问题**：UX §7.1 要求「学习档案从复习的第 4 个 tab 提升为复习的第二个一级视图」，§14.3 以 Playwright 索引契约为由保留五页签。
- **状态**：**已裁定**（B）。
- **裁定**：拆成 `/review`（复习队列）与 `/review/diagnosis`（学习档案）两个路由；旧「诊断」页签、`/learning`、`/mistakes` 均重定向到规范路由。`/review` 的默认视图为「**待复习**」（当前可执行复习集合，`CR-05`/`CR-29`）。E2E 定位改按 `data-testid`，索引契约随之清理。
- **结论**：拆 `/review` 与 `/review/diagnosis` 两个路由，旧 tab 重定向，「待复习」为默认视图。

### Q-209 离线草稿冲突的默认立场
- **问题**：现行策略是「保留服务器值、屏蔽本地值直到用户选择」（`practice_repository.py:587-608`）。
- **状态**：**已裁定**（A）。
- **裁定**：已提交/已判分的作答属学习记录类、人工编辑过的草稿属用户创作类：跨设备无法自动合并时**保留两个版本并提示用户选择**，禁止静默覆盖；不提供「按时间戳自动取胜」或「实例级默认立场」这类会静默丢一侧的选项。尚未提交的中间输入与光标/旗标/计时属临时状态类：后写覆盖，但覆盖时必须明确告知（`CR-23`）。
- **结论**：保护服务端 + 显式选择（学习记录类与用户创作类）；临时状态类后写覆盖但必须告知。

### Q-210 评级按钮的间隔提示
- **问题**：UI 写死 `+10m/+1d/+3d/+7d` 与调度器实际输出不符（GAP-210）。
- **状态**：**已裁定**（B 细化）。
- **裁定**：评级旁展示的间隔必须与实际调度一致——能算出真实到期日就动态显示该题按当前快照计算出的实际到期日期（服务端在同一次提交响应里回传 `next_due`）；**算不出真实到期日就不显示间隔**，只保留四个评级词。不得展示写死的假间隔，也不得用「实际间隔由算法决定」的说明文案替代表格本身说谎。
- **结论**：间隔必须等于真实调度结果，算不出就不显示，禁止写死假间隔。
