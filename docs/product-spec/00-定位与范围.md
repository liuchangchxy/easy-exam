# 00 · 定位与范围

> 本册是 EasyExam 产品定义的总纲，规定产品是什么、为谁服务、边界在哪、术语怎么统一。
> 本册与 `README.md` 共同构成本规范的入口；分域规则见 10–60 册，跨域裁决见 70 册，缺口与待裁项见 80 册。

---

## 1. 一句话定义

易考宝（EasyExam）是一个面向**家庭与小团队**的自托管刷题、模考与个人学习档案系统。它以**题目为中心**记录一个人的学习过程：每一次作答、每一次判分、每一版解释、每一次复习调度，都可追溯、可回看、可跨设备续上。

---

## 2. 目标用户与使用场景

| 用户 | 场景 | 对产品的含义 |
|---|---|---|
| **独自备考的家庭成员**（主用户） | 一个大题库、长期刷题、靠错题与复习推进 | 高频学习与客观题练习是核心；学习效率优先于管理能力 |
| **家庭/小团队中的题库维护者** | 建库、导入、整理标签章节、把库共享给家人 | 协作是一等公民，但不占据主航道 |
| **小团队里的普通成员** | 使用共享题库刷题，学习记录私有 | 权限只改变能力，不改变页面结构 |
| **实例管理员**（家庭中的运维者） | 管账号、管注册开关、管 AI 与检索配置 | 管理员面真实存在，但只在需要时出现 |

**真实使用画像**（v1.0.24 生产库实测，UX_CORE_REDESIGN §3）：实际负载是「一个人 + 一个大题库 + 标签 + 刷题/错题/复习」；章节、蓝图、多解释体系、资料、协作在真实数据中从未被使用。**设计不能围绕未使用的能力展开，但也不能删掉已承诺的能力**——把它们降到不占主航道的层级。

---

## 3. 产品主线

```text
题目版本 → 作答尝试 → 判分/错因 → 官方解析 → AI/联网/用户解释版本
        → FSRS 复习状态 → 掌握度/斩杀状态 → 下一次复习
```

一切功能都为这条主线服务。**判断一个功能该不该留、该放哪一层，看它是否让这条主线走得更快或更可追溯。**

## 4. 模块树与目标信息架构

### 4.1 模块树（承自 SPEC.md §2.0）

```text
易考宝
├─ 题库与内容：题库、章节、知识点标签、题目版本、考试蓝图
├─ 刷题训练：普通刷题、模考、错题复习、FSRS、斩杀题库
├─ 学习诊断与计划：趋势、掌握度、提分推荐、每日/每周计划
├─ 资料：笔记与文件（题目与知识点的辅助材料，不独立成产品）
└─ 用户与同步：账号、共享题库、私有学习记录、跨设备同步

横向能力：AI（嵌入以上流程，不提供无题目上下文的独立聊天主入口）
```

### 4.2 一级导航（5 + 1）

| 导航项 | 职责 | 明确不做 |
|---|---|---|
| **今天** | 继续上次 · 今日队列（到期/错题/薄弱/推荐，带原因）· 学习概览 | 不做成第二个题库列表 |
| **题库** | 题库列表（我的 / 共享给我）→ 题库工作区 → 题目页 | 不按权限拆成两个页面 |
| **复习** | 一条到期复习队列（按原因标签筛选）· 薄弱管理入口 · 学习档案（趋势/掌握度/完成率） | 不把「到期」拆成多套口径；不按原因拆成多套并列队列；「薄弱」是原因标签 + 独立管理入口，不是又一个 tab |
| **模考** | 考试档案与蓝图 → 考试 → 成绩报告（含历史报告，永久不可变） | 不在交卷前泄露对错；不做历史重判 |
| **资料** | 笔记与文件，可关联到题目与知识点 | 不做成独立背卡产品 |
| **设置**（侧栏底部） | 个人偏好 · AI 与检索 · 账户 · 实例管理（仅管理员） | 不把六类主体同层平铺 |

**结构规则**（承自 UX_CORE_REDESIGN §7.0 四条设计原则）：

1. **一个实体，一个规范页面。** 页面数量由实体数量决定，不由权限或历史决定。
2. **返回就是历史。** 不声明父子关系；需要可预测性时用「回退基准」（fallback），不用「父级」。
3. **状态进 URL。** 凡是用户调整过、希望回来还在的东西（筛选、排序、页码、tab、选中、题目）都进 URL。
4. **权限改变能力，不改变结构。** 不能做的事禁用并解释，不能进的地方给明确的 403 页。

## 5. 产品设计原则

本规范的所有定义都必须通过下面十三条检验。冲突时按序号优先。

### P-1 高频学习与客观题练习是核心
打开产品后 3 次点击内必须能开始一次练习。管理类能力（成员、结构、导入历史、设置）不得占据默认视线，不得在开始练习的路径上插入步骤。

### P-2 学习效率优先于信息完整
同一时间只呈现当前决策所需的信息。统计、趋势、覆盖率是「需要时才看」的，不是「每次都看」的。能用一个数字说清的不用一张表。

### P-3 保留 Direction D 纸面式/编辑式理念
深色书脊侧栏 + 居中纸面 + 1px 编辑式分隔线 + 衬线标题的语言不变。原型已按此实现（`assets/ee.css` 为设计系统唯一来源）。本规范只定义结构与行为，**视觉细节归 P2**。

### P-4 统一稳定的空间秩序
同一个概念在全产品只有一个位置、一个名称、一种行为。进入实体的入口唯一（名称），行内只放行级动作。禁止「同一对象多个页面、同一任务多个入口、同一概念多个定义」。

### P-5 避免后台管理系统式布局
不出现「左侧菜单树 + 右侧密集表单表格」的默认形态。题库是学习材料的家，不是数据库管理台。成员管理、导入历史、审计这类内容是**工作区内的一个 tab**，不是顶层页面。

### P-6 避免无意义的复杂操作与信息重复
不为「将来可能用到」增加步骤；不在页头重复 breadcrumb 已说过的位置；不用两个控件表达同一个筛选；不让用户做系统能推断的选择。

### P-7 每个功能必须闭环
有入口、有适用条件、有可执行操作、有明确结果、有出口（含异常出口）。**没有出口的功能不允许进入本规范**——这是消灭死按钮与交互断裂的根本规则。

### P-8 没有 AI 也要完整可用
题库导入、普通刷题、模考、错题、趋势、计划、FSRS、斩杀题库在未配置 AI、联网搜索或本地资料时全部正常工作。AI 只做增强，不做门槛。

### P-9 不静默丢失用户数据
任何会减少用户可恢复数据的操作，都必须先告知范围并取得确认，或留下可恢复路径。允许「覆盖」，不允许「静默覆盖」；允许「用户主动选择不记录」，不允许「系统替用户丢」。

### P-10 同一概念一致语义，不同业务场景允许不同规则
一个概念在全产品只有一个定义；但两类对象的安全策略可以不同（如学习记录类保留冲突版本、草稿类覆盖并告知）。**不得把「对所有对象用同一套策略」当成一致性**——那是以实现便利替代业务合理性。

### P-11 同一功能可有多个合理入口，入口必须复用同一套操作逻辑
入口数量不机械受限；受限的是**逻辑重复**。所有同名操作必须调用同一个决策与同一套确认，不得出现两个行为不同的「开始练习」。

### P-12 不把实现细节当成产品规则
后端表名、字段名、URL 参数名、接口路径、存储位置是**载体**，不是规则。产品规则只规定「用户看到什么、能做什么、系统保证什么」；禁止因「数据库是一个字段」就推出「产品只有一个开关」。

### P-13 完整性不等于功能数量最大化；正式产品与原型都是参考，不是上限
每个功能必须闭环（P-7）且服务于主线（P-1）。已承诺的能力要补齐，但**不为旧规格里存在过的描述自动纳入本期**，也不因现有产品或原型没做就认为不该做。

## 6. 非目标

- 不复制考试宝的页面、品牌、内容或闭源实现；考试宝只作为产品逻辑的观察对象。
- 不整体移植 Moodle、Open edX、Anki、OpenTutor 等大型架构。
- 不把 AI 生成的解释当作标准答案。
- 不自动替用户斩杀题目。
- 不把 AI 资产做成独立的背卡产品或独立 FSRS 队列。
- 不要求配置 AI、联网或考试蓝图后才能使用核心刷题功能。
- 不做客观题之外的自动评分承诺（简答/论述只保存作答与参考解析）。
- 不引入 PostgreSQL；首期继续 SQLite + 事件记录 + 版本记录 + 事务同步。
- 本期（P1）不做视觉设计、不改生产代码、不改原型。
- 本期（P1 收口）明确不做的九项产品能力见 `80` 册 §8.1。

## 7. 术语表（全产品唯一用语）

分册必须使用下表术语，不得另造同义词。

| 术语 | 英文/代码 | 定义 | 禁用词 |
|---|---|---|---|
| 题库 | bank | 题目的家；一道题只属于一个题库 | 题库库、试题库、卷宗 |
| 题库角色 | bank role | 所有者 / 编辑者 / 成员，**只有三种**（`CR-11`） | 库管理员、只读成员、访客 |
| 实例角色 | instance role | 管理员 / 普通用户；与题库角色严格独立、互不授权（`CR-11`） | 系统管理员（易与题库角色混淆） |
| 章节 | chapter | 题库内的大纲章节树节点 | 目录 |
| 题库分类 | bank category | 题库的一个分组字段（非实体），用于题库列表筛选；与「章节」是两层，不要混用 | 分类（指章节时）、类别 |
| 知识点标签 | tag | 题目的多值标签 | 标记、关键词 |
| 题目 | question | 题库内的一道题 | 试题、题 |
| 题目版本 | question version | 题干/选项/标准答案/官方解析的一次变更快照 | 历史记录、修订 |
| 标准答案 | standard answer | 属于题库内容，只能通过新版本修改 | 正确答案（指题目属性时） |
| 官方解析 | official explanation | 属于题库内容的解释 | 答案解释 |
| 解释版本 | explanation version | 官方 / AI / 联网(WEB) / 用户 四类来源的解释 | 评论、备注 |
| 主解释 | primary explanation | 用户选定的当前生效解释 | 默认解释 |
| 考试档案 | exam profile | 一次考试的目标配置 | 考试、试卷 |
| 考试蓝图 | blueprint | 考试档案下的组卷规则（章节/题型/分值配比） | 组卷方案、模板 |
| 练习会话 | session | 一次练习/复习/模考的进行态 | 场次、轮次 |
| 会话模式 | mode | PRACTICE / MISTAKE / FSRS / ELIMINATION / EXAM | 类型 |
| 作答 | attempt | 一次作答记录，绑定题目版本与会话 | 答题、提交 |
| 判分三要素 | score_ratio / correctness / mastery_status | 得分比、是否完全正确、是否已掌握；三者不可互相替代 | 对错、得分（单值时） |
| 错题 | mistake | 用户级错题记录 | 错题本（指集合时用「错题队列」） |
| 错因 | cause | 审题遗漏/概念欠缺/思路不熟/陷阱诱导/计算错误/其他手误 | 错误原因（单值时） |
| 薄弱标记 | weak flag | 用户主动标记的薄弱题 | 弱项、不熟 |
| FSRS 卡片 | card | 一道题对一个用户的调度状态 | 复习卡、记忆卡 |
| 复习队列 | review queue | **到期题的统一列表**：`due_at <= now 且未被当前用户斩杀`（`CR-05` 唯一定期口径）；每行带原因标签（错题未清除 / 薄弱 / 巩固），原因可叠加 | 复习列表、待复习、到期列表（作为独立口径时） |
| 到期 | due | `due_at <= now 且未被当前用户斩杀`。全产品唯一口径，队列/今日/趋势/推荐/计划共用 | 该复习了、待办 |
| 巩固 | consolidation | 错题已清除但 FSRS 卡仍在调度的低优先级复习原因（`Q-202` 裁定 B） | 保持复习、长期复习 |
| 查漏补缺 | ELIMINATION 模式 | 在斩杀题库里主动练习，答错即恢复未斩杀 | 斩杀练习、补漏 |
| 候选答案 | candidate answer | 题目无标准答案时，AI/资料/联网结果的定位 | 参考答案、建议答案 |
| 个人采用答案 | adopted answer | 用户确认后采纳的候选答案，仍不得冒充官方答案 | 我的答案 |
| 降级补齐 | graceful fallback | 蓝图配额不足时按规则补足题量，必须在开始前确认信息中显式展示补了几题 | 自动补齐、容错 |
| 题库内容量 | bank content count | 该库全部未归档题目数，**公共语义**，所有成员看到同一个数；斩杀不影响它 | 总题数（与可练量混用时） |
| 我的可练题量 | my practice count | 内容量 − 归档 − 我斩杀的，**个人语义**；只有它为 0 时「开始练习」禁用 | 可练习题数（与内容量混用时） |
| 成绩报告 | exam report | 一场考试的裁定结果，**落库后永久不可变**（`CR-25`）；展示判分所依据的题目版本 | 成绩单、考试结果 |
| 历史重判 | rejudge | **本期不提供**。修改标准答案只影响之后开始的会话；报告页给「查看当前版本」入口让用户自行判断 | 重新阅卷、重算分数 |
| 纳入学习记录 | record_mistakes | 模考会话级开关，默认开；关闭时本场不写错题、不写 FSRS、不计入统计，报告仍可回看（`CR-08`） | 记入错题本 |
| 暂存 | stash | 退出进行中会话时保留草稿，稍后继续 | 保存草稿、暂停 |
| 回退基准 | fallback | 无历史可退时的固定去向 | 父页面 |
| 斩杀 | kill | 用户主动把题移出常规练习，进入斩杀题库 | 删除、消灭 |
| 斩杀题库 | killed set | 斩杀题的集合，可查漏补缺，答错恢复 | 斩题库 |
| 掌握 | mastery | 由判分与调度共同决定的独立状态 | 学会、记住了 |
| 资料 | asset | 笔记、AI 总结、口诀、上传文件 | 素材、附件 |
| 导入作业 | import job | 一次导入的审计记录 | 上传任务 |
| 导入草稿 | import draft | 可续做的导入中间态（含 PDF 校对） | 临时文件 |
| 归档 | archive | 库内隐藏、可恢复、不参与练习与统计；**题目与题库唯一的「移出视野」动作** | 回收站、删除 |
| 恢复 | restore | 归档的逆操作 | 还原、撤销归档 |
| 删除 | delete | 真正移除；**仅空库可用**（输入库名确认），题目无物理删除入口 | 归档、移除 |
| 题库工作区 | bank workspace | 一个题库的唯一规范页面（题目/结构/成员/导入历史/AI 草稿/设置） | 题库详情、题库管理 |
| 题目页 | question page | 一道题的唯一规范页面，可深链 | 题目抽屉、题目弹窗 |
| 今天 | today | 首页：继续上次 + 今日队列 + 概览 | 主页、仪表盘 |
| 开始学习面板 | start panel | 统一的「开始一次学习」配置面板 | 开始练习弹窗（多处时） |
| 实例管理 | instance admin | 仅实例管理员可见的账号与注册管理 | 系统设置、后台 |
| 命令面板 | command palette | Ctrl/⌘+K 唤起的全局跳转与动作 | 快捷搜索、搜索栏 |

## 10. 本规范的三层结构（读任何一条规则前先分清它在说哪一层）

P1 收口后，全产品每一条规则都属于且只属于下面三层之一。**P2/P3 的 Agent 只需要第一层。**

| 层 | 含义 | 写在哪 | 权威性 |
|---|---|---|---|
| **① 产品最终应该怎样工作** | 理想完成态的产品定义 | 各分册的 `FN-` / `BR-` / `OP-` / `ST-` / `PR-` 正文 | **唯一权威**，P2/P3 直接依据它施工 |
| **② 现状与理想态的差距** | 已登记但未兑现的能力、缺陷、口径不一 | 各分册 `GAP-` 表 + `80` 册 §2–§4 | 施工清单，**不是产品规则** |
| **③ 本期明确不做或延期** | 裁定不做、移交其他阶段、原型自身缺陷 | `80` 册 §5 分类表 + §8 | 边界，防止范围膨胀 |

- **历史调查证据保留但不具权威性**：`GAP-` 里的 `file:line` 与原型页面是「差距从哪来」的证据，用于施工时定位，**不得**被当成产品规则引用。
- **候选方案不具权威性**：`80` 册 §6 的候选与推荐是裁定过程的记录；裁定结果以各分册正文与 `70` 册为准。
- 一条规则若同时出现在 ① 和 ②，以 ① 为准，并把 ② 改成指向 ① 的一句话。
