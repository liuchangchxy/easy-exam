## 2. 跨域规则裁决

### CR-01 一道题只属于一个题库（已确认，落地）
复制到其他题库 = **生成新题目实体与初始版本**，学习状态从空白开始；移动 = **保留题目身份、更换归属**。存储层已由触发器强制（迁移 23，`trg_bank_question_single_bank`）。
→ 细则见 `BR-1xx`。**遗留的历史重复行不自动删除**，只拦新写入（UX §14.3）。

### CR-02 学习状态挂在题目上，不挂「题目 × 题库」
`fsrs_cards` / `mistake_records` / `learning_records` / `weak_question_flags` / `kill_records` 主键均为 `(user_id, question_id)`。因为 CR-01 已保证一题一库，`(user, question)` 与 `(user, question, bank)` 等价，**不改成三维主键**（UX §7.6 明确不建议）。
**但用户界面的单位是「这个库里的这道题」**：所有面向用户的列表、统计、越权提示，必须以题库为上下文呈现；退出题库后不得让历史从统计里消失（`mistake_records.bank_id` 为冗余展示字段，不是归属字段）。
**退出或被移除后这些个人学习资产的处置见 `CR-30`**（保留、标注来源、恢复成员资格后恢复学习能力）。

### CR-03 归档是唯一的「移出视野」动作；物理删除只在空库
`questions.archived_at`（迁移 19）承担「库内归档」语义，可恢复；`is_deleted` 仍是归档位（行为等价，命名债记入 DECISIONS）。
- 归档题目：默认从题库内容列表、普通刷题、专项集合、统计中隐藏；可在工作区 `?archived=1` 显式查看并恢复。
- 归档期间：不可编辑，不参与章节/标签/移动/复制等批量维护。
- **题目没有物理删除入口，也没有「回收站」这个概念**——归档不是删除，术语统一为「归档」。
- **题库**同理：`DELETE /banks/{id}` 实为归档，对外术语一律称「归档题库」。唯一的物理删除是**空库**（无任何题目、且无任何作答引用）由所有者删除，必须输入库名确认。
- 题库归档的确认只需一个对话框（标题带库名，`BanksView.vue:836-843`），**不要求输入库名**；要求输入库名的是**空库物理删除**与**转移所有权**（`BankManageView.vue:799-827`），三者不要混。

### CR-04 「题库内容量」与「我的可练题量」是两个数，都必须显示
历史上三处 SQL 口径不同（卡片计数不含归档含斩杀 / 练习池不含归档不含斩杀 / 内容管理含斩杀、归档可选）。
**裁决**：这不是三个口径，而是**两个语义不同的数字 + 三个视图**，允许不同；但每个视图的包含集合必须固定，且用户能说出每个数是什么。

| 数字 | 包含集合 | 语义 | 谁看到 | 斩杀是否影响 |
|---|---|---|---|---|
| **题库内容量** | 该库**未归档**题目（`archived_at` 为空） | 公共语义 | 所有成员看到同一个数 | **不影响**（斩杀是个人状态，不改变题库公共内容） |
| **我的可练题量** | **未归档题目中未被当前用户斩杀**的题目 | 个人语义 | 每人不同 | 影响 |

- **归档只扣一次**：「题库内容量」的定义本身已排除归档题，因此**可练题量不得再减一次归档**——正确关系是 `我的可练题量 = 题库内容量 − 我斩杀的该库未归档题数`。等价表述：**可练题量 = 未归档题目中未被当前用户斩杀的题目数**（`BR-122`）。
- 由此 `我的可练题量 ≤ 题库内容量` 恒成立；两者相等 ⟺ 我没有斩杀该库任何未归档题。
- 卡片与列表统一显示「共 N 题 · 我可练 M 题」；只有 **M = 0** 时「开始练习」禁用并解释（`GAP-102`）。两种禁用原因必须分开说：`N = 0` → 没有在用题目（可能全部已归档，去归档视图恢复）；`N > 0 且 M = 0` → 未归档题被我全部斩杀（去斩杀题库恢复）。
- 工作区给出「已归档 N / 已斩杀 N」两个计数作为出口。
- 同一道题在不同视图的出现/消失必须可由用户理解；**不得**用内容量充当可练量，也不得因个人斩杀改变公共内容语义。

### CR-05 「到期」的唯一定义，以及它与「可执行复习集合」的区别（**已裁定**）
**到期是 FSRS 卡片的属性：`due_at <= now`。** 全产品只有这一个到期口径：复习队列、今日队列、趋势、推荐、计划全部调用同一个服务端方法，禁止各处各写 SQL（现状三套口径互斥，见 `GAP-209`，属本期必须收敛项）。

但**「到期」不等于「现在能复习」**。本册把两者分开，是为了避免「口径统一」被误读成「所有学习活动都只能围着到期题转」：

| 概念 | 定义 | 用在哪 |
|---|---|---|
| **到期** | 卡片属性：`due_at <= now` | 排序、到期日展示、统计口径 |
| **当前可执行复习集合** | 到期题中同时满足：① 未被当前用户斩杀；② 未被归档；③ 当前用户对该题所属题库仍有访问权 | 复习队列、今日队列、FSRS 专项、推荐、计划——一切**会让用户开始作答**的入口 |

- **归档题、已斩杀题、无访问权限的题不进入可执行复习集合**，但**保留原有学习状态**：FSRS 卡、错题记录、掌握度、历史作答一律不删除、不重置、不算「已掌握」。
- 条件恢复时（取消斩杀、取消归档、恢复成员资格），该题**凭原有卡片状态**重新进入可执行集合，不重新从零开始，也不补做错题。
- 可执行集合的供给方法是唯一的（历史上叫 `list_due_reviews(user, bank?)`，**方法名是实现载体，P-12**；产品只规定「一个方法、一个集合」）。
- **错题未清除 / 薄弱 / 巩固** 是叠加在可执行复习集合里的**原因标签**，不是独立的到期口径。一个题可同时带多个原因。
- **巩固** = 错题已清除、但 FSRS 卡仍在调度的低优先级原因（`Q-202` 裁定 B）。
- **已清除错题不出队**：清除错题只改变错题状态，不删除 FSRS 卡、不把题移出调度。
- FSRS 只调度错题与 `mark_weak` 题，不默认调度所有做过的题（SPEC §4.2）。
- **未到期题不进任何「到期」视图**。未到期的薄弱题出现在薄弱管理入口（`GAP-222`），从那里开始的是普通练习会话，不是 FSRS 专项；FSRS 专项的服务端集合约束保持「必须属于当前已到期集合」（`BR-210`）。
- **错题视图与薄弱视图不受「是否到期」限制**：错题视图列出**全部**未清除错题，薄弱视图列出**全部**薄弱题（含未到期），两者都允许主动重做/主动练习（`CR-29`）。
- 服务端对 `question_ids` 做集合约束，严禁客户端伪造筛选退化为整本普通刷题。

### CR-06 判分三要素不可互相替代；「答没答」与「判没判」是两个维度
`score_ratio`（得分比）/ `correctness`（是否完全正确）/ `mastery_status`（是否已掌握）三者分离。
- 多选漏选可得部分得分，但**不得**视为完全正确、不得视为已掌握、不得触发错题出库。
- 部分得分**不得**直接映射为 Good 评级。

**作答状态与判分状态必须分开（本轮修正）**：一个字段不得同时表达「用户答了没有」和「系统判了没有」。

| 维度 | 取值 | 判定依据 |
|---|---|---|
| **作答状态** | `未作答` / `已作答` | 用户是否为该题保存了答案（非空）。这是「已答 / 未答」计数的**唯一**依据 |
| **判分状态** | `已判分` / `未判分` | 系统是否为该题给出了得分与对错 |

- **主观题（ESSAY/SHORT_ANSWER/SUBJECTIVE）写了答案就是「已作答」**，判分状态为「未判分」；**不得因为不能自动评分就显示成「未作答」**。
- `correctness` 的 `UNANSWERED` 取值**废止**（它与作答状态的「未作答」重复，且把主观题误标成未作答）。`correctness` 只在 `已判分` 时有值：`CORRECT` / `PARTIAL` / `INCORRECT`。
- `score_ratio` 对「未判分」题不参与得分计算，**不得按 0 分计入**客观题得分与正确率。
- 报告的计数口径统一为五项，全产品一致（`BR-205`、`BR-231`、`BR-313`、`FN-308`）：**已答**（含未判分）/ **未答** / **未判分** / **客观题得分与客观题满分**（只含已判分的客观题）/ **卷面总分与满分**（主观题部分标注「未判分，不计入」）。
- 主观题的 `mastery_status` 保持 `UNSEEN`/未掌握语义之外的独立处理：不因「保存了答案」变成已掌握，也不因「不能自动判分」变成未作答。
- **本期不增加主观题自动判分功能**（`80` 册 §8.1）。

### CR-07 会话状态必须三分
`practice_sessions` 历史上只有一个 `is_completed`，完成与放弃同值。
**裁决**：会话状态必须是 `active` / `completed` / `abandoned` 三态，`score` 与 `time_spent` 必须落值，报告必须落库并可回看（回看入口是产品要求；具体端点路径属实现，`20` 册 `GAP-212` 登记的「无独立报告端点」是施工缺口，不改变本规则）。
- `completed` 与 `abandoned` 都是终结态，**必须拒绝任何后续作答提交**（不存在第四种「已取消」态）。
- 提交与交卷必须幂等：网络重试不得重复插入作答、重复计入错题或重复推进 FSRS。
- **「作答窗口结束」不是会话终结态**：模考到点后进入的是 `active` + `is_expired` 派生态，会话本身仍是 `active`，仍必须能交卷与生成报告（`CR-31`）。

### CR-08 `record_mistakes` 是「本场是否纳入学习记录」的总开关，默认进入
`record_mistakes` 为真（默认）时，交卷判分写错题表并同样写 FSRS 卡（与 SPEC §4.1「由考试配置决定」一致）。
**为假时，本场完全不写入学习域**：不写 `mistake_records`、不写也不推进 FSRS 卡、不计入任何学习统计与趋势。半写入（写了错题却不调度）会产生无法被复习的孤儿错题，违反 P-7 闭环，明确禁止。

- 会话快照与作答记录**仍然保存**——成绩报告需要它们，报告属模考域产物，不是学习记录。
- 报告仍可正常生成与回看；报告内的错题列表是这些错题的**唯一可见出口**，用户可从中跳去普通练习。
- 开始前确认信息必须显式写明「本场不纳入学习记录：错题、FSRS、统计均不更新」，避免用户误以为关了开关只是「不进错题本」。
- 取优先级：会话 `config_json.record_mistakes` 优先，缺省回退蓝图同名字段（`BR-305`）。
- **普通练习不暴露此开关**（`Q-207` 裁定 A）：普通练习默认记录学习过程，不增加无明确需求的开关。

### CR-09 斩杀只能用户主动执行
系统不得自动斩杀。斩杀题从普通刷题、错题复习和 FSRS 队列移出，进入斩杀题库；**答错后恢复为未斩杀**并重新进入相应复习流程；**不因时间自动恢复**。
斩杀题列表必须透传 `bank_id` 上下文，服务端在 ELIMINATION 模式下校验题目属于已斩杀集合。

### CR-10 标准答案与解释分离
标准答案属于题库内容，修改必须生成新版本，历史作答绑定原版本。官方 / AI / 联网(WEB) / 用户 四类解释是不同来源的解释版本，**任何一类都不得覆盖另一类**；用户可选定主解释；AI/联网/用户解释都不得自动改写标准答案。
题目没有标准答案时，AI/资料/联网结果只能作为「候选答案」，用户确认后成为个人采用答案，仍不得冒充官方答案。

### CR-11 两层角色严格独立，互不授权
**实例角色**：管理员 / 普通用户。**题库角色**：所有者 / 编辑者 / 成员。两套词、两套授权，**任何一层都不因另一层而获得能力**。

- **实例管理员不因实例角色获得任何题库编辑权或成员管理权**。他要编辑某个库，必须在该库被显式授予所有者或编辑者。
- 实例管理员访问自己不是成员的题库 → 与其他人一样拿到 403 页（`CR-12`）。
- 实例管理员的管理面只在实例管理页（账号、注册开关、AI 与检索配置、所有权仲裁），不进入任何题库的工作区。
- 账户菜单与设置显示实例角色；题库内只显示「你在本题库的角色」。任何界面不得同句出现两个「管理员」（`Q-402`）。
- 因此本册 §5 的权限矩阵**按实例面与题库面拆成两张表**，不再用「实例管理员」列去回答题库能力。

### CR-12 权限改变能力，不改变结构；表达方式按「相关性」分流
同一个能力在不同页面必须表现一致（历史上存在 隐藏/禁用/banner 三套语义，已收敛为下面两条判据）。

- **与当前用户相关、但此刻不可用的控件 → 禁用并解释**（置灰 + 原因）。例：成员看到「编辑题目」按钮；可练量为 0 时的「开始练习」。
- **与当前用户完全无关的管理入口 → 不显示**。例：普通用户看不到实例管理入口；非成员看不到成员管理页签。
- 判据是「这个入口说的事，对这个用户有意义吗」：有意义但不能做 → 禁用并解释；没意义 → 不出现。**不得**用顶部英文 banner 或错误码当作唯一反馈。
- 非成员访问题库给 403 页，带 `?from=` 回跳；无 `from` 时主按钮回题库列表（`GAP-410`）。
- 后端 403 的 `detail` 必须转成用户可理解的中文呈现（`GAP-402`）。

### CR-13 学习记录私有
每个用户的作答、错题、AI 解释、斩杀状态、复习计划、资料必须私有。共享题库只共享内容，不共享学习记录。多用户之间无法读取彼此的学习记录。

### CR-14 开始学习只有一个决策点；冲突判定只看同模式
所有「开始练习 / 开始复习 / 开始模考」入口——包括模考入口——都调用同一个开始决策；参数完整时直接开始，否则打开开始面板。

- **冲突门只比较同 `mode`**：已存在同模式未完成会话时，统一提示「继续 / 结束并新建 / 取消」，取消不新建会话。
- **跨模式允许并存**：一个进行中的普通练习和一个进行中的模考可以同时挂着，互不阻塞、互不提示。同模式开第二个才是真冲突（同一件事做两遍会重复计数据）。
- 现状缺陷：模考入口完全不走该门，可再开一场（`GAP-203`、`GAP-312`）——本期必须修。
- 不引入「全会话管理台」：**不做独立的会话列表/管理路由**（不检索、不排序、不批量结束全部、不跨模式代管）。恢复入口收敛为**同一处语义**——今天页「继续上次」与各入口的同模式提示复用同一个组件。
- **允许的轻量形态——会话选择器**：今天页内「查看全部 N」弹窗，出现条件是**未完成会话总数 > 1**。**不是同模式 ≥ 2**：跨模式会话本就允许并存，选择器要回答的是「我有好几件没做完的事，先继续哪一件」，这与它们是否同模式无关；同模式是否冲突由上面的冲突门负责，两件事不要混。
- 该弹窗只做「列出模式/题库/进度 → 继续某一个 / 放弃某一个」，不提供「放弃全部」这类跨模式批量动作。**这是选择器，不是管理台**——判据是「它替用户决定下一步做什么」，而不是「它有多少行」。

### CR-15 返回就是历史
不声明静态父子关系。返回先回退应用内历史，无历史时走页面声明的 fallback。全屏 runner 与普通页面使用同一套返回模型。

### CR-16 只有「值得回来还在、值得分享」的状态进 URL
进 URL：筛选、排序、页码、tab、选中、当前题目、向导步骤、草稿 id、403 的 `from`。
不进 URL：默认值；展开/折叠、hover、进行中未提交的输入、滚动位置、一次性 toast。
设备级偏好（每页条数、外观、语言）留 localStorage，**不跨设备同步**（`Q-503`）。
**URL 参数是实现载体，不是产品规则**：产品只规定「这个状态回来还在、这个链接能分享」，不规定参数名与结构。

### CR-17 一个实体一个规范页面
题库工作区一个页面（题目/结构/成员/导入历史/AI 草稿/设置）；题目页替代抽屉；`/banks/:id/manage` 仅为 redirect；实例管理是独立路由（实例级权限），不是设置的 tab。

### CR-18 资料与笔记是辅助，不是主线
笔记 / AI 总结 / 口诀 / 上传文件是题目与知识点的辅助材料，**不生成独立 FSRS 任务，不改变刷题主线**，不做成独立背卡产品。

### CR-19 AI 是横向能力，不是产品
没有 AI 时核心功能完整可用。AI 不提供无题目上下文的独立聊天主入口。
AI 可生成解释版本、候选答案、变式题草稿，均需用户确认；AI 变式题先作草稿，不直接进入共享正式题库。
**AI 建议知识点标签、AI 建议考试蓝图本期不做**（`Q-506` 裁定 A）：真实使用画像中蓝图为 0、标签是人工组织决策，AI 建议需逐条人工确认，成本高于收益。原 SPEC §2.3 的相关表述需修订，登记见 `80` 册 §7。
不允许把 AI 失败或未配置时的兜底文案保存为有效解释版本（`GAP-501`）。

**AI 服务鉴权（本轮修正）**：
- **支持无需 API Key 的自建 AI 服务**。判断一个服务「能不能用」的依据是**服务类型 + 用户显式配置 + 实际连接结果**，**不得仅凭地址不是 `localhost` 就认定必须填写密钥**。
- 用户显式配置的服务不可用时，必须**明确告知原因**（连不上、缺密钥、模型不存在、返回不可用），**不得静默回落到其他 provider**（`BR-528`）。
- 实例默认配置与个人配置的继承边界必须清楚：个人留空 = 继承实例默认；个人填了任一字段 = 用个人的；**不得把实例默认的密钥发送到用户显式指定的地址上**，也不得把用户指定的服务换成实例默认的服务。
- 「不使用 AI」是独立于「留空继承」的第四态（`ST-505`）。

### CR-20 导入必须可续做、可对账
导入是向导（来源 → 校对 → 重复项 → 结果），草稿落库并可续做；离开时给「稍后继续 / 放弃」两个明确出口；重复项属于（文件 + 映射 + 当前题库）三者的函数，必须由用户显式选择 `skip` / `new` / `merge` 后才写入；每次导入留 `import_jobs` 审计记录；预检失败不得落盘。

### CR-21 无复杂配置也要可用
未配置 AI、联网搜索或本地资料时，题库导入、普通刷题、模考、错题、趋势、计划、FSRS、斩杀题库均正常工作。未配置蓝图、章节权重或知识点树时，使用基础题库模式，仍可按题型、标签、历史正确率和复习状态工作。

### CR-22 难度筛选只依据标注
只依据题目明确标注的 1–5 级难度；未标注视为「未分级」：未启用具体难度筛选时可参与推荐，启用后排除。**不得依据用户作答数据推断题目难度，不得跨用户聚合答题表现。**

### CR-23 跨设备合并不静默丢数据；策略按数据可否重建分流
按「丢了能不能重建」分三类，**不同业务场景允许不同规则**：

| 类别 | 对象 | 策略 |
|---|---|---|
| **学习记录类**（不可重建） | 已提交/已判分的作答、错题、FSRS 卡、掌握度、成绩报告 | 按服务端事件顺序合并；**无法自动合并时保留两个版本并提示用户选择**，禁止静默覆盖 |
| **用户创作类**（不可重建） | **人工编辑过的导入草稿、AI 草稿、未提交的答案内容** | 同上：**保留两个版本并提示用户选择**，禁止静默覆盖 |
| **临时状态类**（可重建/低价值） | 题目光标、旗标、展开/折叠、滚动位置、计时、尚未提交的中间输入 | **后写覆盖 + 覆盖时明确告知**「已被另一设备更新，已用较新版本替换」 |

- **判据是「这份内容是不是用户花力气做出来的」，不是「它存在哪张表里」**：导入草稿与 AI 草稿一旦被人工改过，就是用户创作，与「是不是草稿表」无关；同一条草稿在用户未编辑前可按临时状态处理后写覆盖，被编辑后必须升格为创作类。
- 临时状态类允许覆盖，但**不是静默覆盖**：同步成功必须有可见提示。静默是禁止项，覆盖本身不是。
- **同步游标按设备（或按独立消费方）维护**：每个消费方各自记住自己消费到的事件序号，禁止「另一设备/另一个标签页推进了游标，导致本端漏收事件」。同一浏览器多标签页视为多个独立消费方（`FN-218`）。
- 改密时吊销其他会话。
- 多设备同时续考同一会话：后开者只读，并提示该会话正在另一设备进行（`Q-305` 裁定 B）。

### CR-24 一次作答同事务更新
`mistake_records`（用户级错题事实）与 `learning_records`（掌握状态与统计）必须在同一事务内更新。导入必须创建 `import_jobs` 审计记录，解析预检失败不得产生题目。

### CR-25 历史成绩报告永久不可变；本期不提供历史重判
成绩报告一旦落库即**不可修改、不可重新计算、不可覆盖**。报告是「当时那一场按当时版本做出的裁定」，是用户的学习证据。

- **本期不提供历史作答重判**（`Q-104` 同类裁定：不做回滚、不做重判）。修改标准答案只影响之后开始的会话。
- 报告页必须展示「本报告按题目版本 vN 判分」，并提供「查看该题当前版本」入口——用户自行判断差异，系统不替他改历史。
- 若未来要做重判，必须生成**新报告版本**（`report_version + 1`）并保留旧版可查，禁止覆盖；本期不排入。
- 与 `BR-230`、`BR-302` 一致：报告只写一次，后续 `complete` 调用逐字返回已存报告，题目后续修改不影响历史成绩。

### CR-26 模考不使用题库锁定；隔离靠会话快照 + 题目版本
**取消「模考进行中锁定题库/题目」的机制。** 会话在开考时持有题目与版本的快照（`BR-309`），编辑题库内容不会污染进行中的考试；锁定的协作阻塞（他人的模考阻断你编辑共享题库，`GAP-309`）远大于其防护价值。

- **连带取消题库读侧脱敏**：过去「模考进行中，题库与题目页对参考者清空答案与解析」是锁定机制的一部分（`question_repository.py` 的读侧脱敏与 `locked_by_active_exam`）。锁定取消后它失去存在理由——能进题库的人本就能在工作区看到答案，这层脱敏只给同一个人添堵。**一并取消**。
- **保留的只有一条**：模考 runner 自身**交卷前不展示对错与解析**（`BR-301`，SPEC §3.2 硬约束）。这是会话内规则，不是题库读模型规则。
- **遮蔽只作用于模考 runner**：题库内容管理、题目页、版本历史、普通练习、错题视图在任何情况下都不因「有未交卷模考」而隐藏答案或解析。**旧的读侧脱敏规则要彻底清除，不是留着不用**——包括 `question_repository` 的读侧脱敏、`locked_by_active_exam` 标记、错题/普通练习侧各自计算的「活动模考题目集合」，以及随之而来的 60s 宽限脱敏判定。
- 超时（`ST-302`）**不解除任何锁定**，因为本来就没有锁定；超时只结束作答窗口并驱动自动交卷（`CR-31`）。
- 编辑者**归档或删除**已被进行中模考引用的题目时，不阻断，但必须提示「有 N 场进行中的模考引用本题；这些考试仍按快照进行，新考试将不再包含本题」，确认后执行。
- 因此 `FN-312`、`BR-311` 的锁定口径、`ST-302` 的「不解锁题库锁定」、`BR-117`/`BR-118` 的模考互斥、以及题库/普通练习侧的一切答案遮蔽规则全部作废，改为本条。

### CR-27 选择集与筛选解耦；批量操作必须说清影响范围
批量操作的选择集是**按题目 id 记住的独立集合**，与当前筛选/分页/搜索解耦。

1. **切换筛选不清空已选**：用户显式勾过的项不会因为翻页或改筛选而消失。
2. **批量条常驻显示「已选 N」**，其中含「M 项当前不可见」时明确标出。
3. **允许操作不可见项**（用户明确勾过），但执行前确认对话框必须列出**实际将受影响的题目数与范围**（含不可见项的数量）。
4. **不得按可见行修剪后静默少做**：要么全做并说清数量，要么不做。
5. 执行结果按「成功 X / 跳过 Y」报告，跳过的必须给原因（已归档、已被他人删除、无权限），**不静默**。
6. **整批校验、整批生效**（本轮修正）：任一条目校验失败——无权限、对象不存在、不属于当前题库、目标章节不属于当前题库、题库已归档——**整批拒绝且零写入**，不得部分生效。
7. **「已经处于目标状态」不是校验失败**：对未归档题执行归档、对已归档题执行恢复，这类条目作为**「无须变更 N 项」单独计数**，不影响其余条目生效。成功提示按「成功 X · 无须变更 Y · 跳过 Z」三项真实对账，不得把无须变更说成成功，也不得因为它把整批判失败。
8. 选中含被进行中模考引用的题时不阻断，确认对话框须提示引用场数（`CR-26`）。
9. `OP-102` 原第 ⑥ 条「归档/恢复各自只作用于能改变状态的行」的语义废止，以本条为准。

### CR-28 底部导航只在侧栏不可见时出现
底部导航与侧栏是同一职责的两种形态，**不得并存**（并存即重复入口，违反 P-4/P-6）。

- **侧栏可见（> 640px）→ 不显示底部导航**：桌面完整侧栏，平板（641–1024）收窄为图标轨。
- **侧栏不可见（≤ 640px）→ 显示底部导航**（6 项）+ 移动顶栏。
- 这是一条可由「侧栏是否可见」推导的规则，不按设备名记忆；修正 `70` 册 §6 表格与 `OP-623` 的口径。

### CR-29 复习的信息架构：五个视图，语义固定（本轮新增）
复习区是**一个视图集合**，不是一堆并列页签。五个视图的语义在本轮冻结；**视觉组织（页签/路由/分组怎么摆）归 P2/P3**，P1 只规定每个视图装什么。

| 视图 | 集合 | 允许的动作 |
|---|---|---|
| **待复习** | **当前可执行复习集合**（`CR-05`：到期 ∧ 未斩杀 ∧ 未归档 ∧ 有访问权） | 按原因筛选（错题未清除/薄弱/巩固）、按到期时间排序与分组、开始复习 |
| **错题** | **全部未清除错题**，**不受是否到期限制** | 主动重做（`MISTAKE` 专项）、改错因、斩杀、批量开始 |
| **薄弱** | **全部主动标记的薄弱题**，含未到期 | 管理（行内/批量取消标记）、主动练习（`PRACTICE`，不是 FSRS 专项） |
| **斩杀** | 全部已斩杀题 | 管理（恢复/原因备注/筛选）、查漏补缺（`ELIMINATION` 专项） |
| **学习档案**（独立路由 `/review/diagnosis`） | 不是题目集合，是统计面 | 趋势、掌握度、覆盖率、薄弱点、学习计划、提分推荐 |

- **「全部」与「到期」是同一个集合的两种呈现，不设成两个独立视图**：待复习视图内部可提供「按到期时间排序/分组」的呈现切换，但那是同一集合的排序方式，不是第二个页签。
- **待复习视图受「是否到期」约束；错题与薄弱视图不受**。理由是三者服务不同问题：待复习答「现在该复习什么」，错题答「我错过哪些」，薄弱答「我标过哪些」。把错题/薄弱也限制成「仅到期」，会让未到期的错题与薄弱题无处可看、也无处可练。
- **统一到期计算口径 ≠ 所有学习活动都必须围绕到期题展开**：口径统一指的是「什么叫做到期」只有一个定义，不是「只有到期题才允许被练习」。
- 学习档案保持独立路由（`Q-208` 裁定 B），不并回复习页签。

### CR-30 失去题库访问权 ≠ 题库归档（本轮新增）
「成员权限被撤销」与「题库被归档」是两件不同的事，**不得互相套用规则**。

| | 题库归档（`CR-03`） | 成员权限撤销（移除/退出，`FN-417`/`FN-418`） |
|---|---|---|
| 影响谁 | **所有人**：整个库移出视野 | **只影响这一个人**：其他成员照常 |
| 题库内容 | 库内隐藏、可恢复 | 内容本身不变，别人照样能用 |
| 该用户的历史 | 保留（随题目存在而保留） | **保留**：作答、错题、FSRS、斩杀、薄弱、成绩报告、个人笔记全部保留，且继续进个人统计（`BR-414`） |
| 该用户的可执行学习 | 该库题目从可执行复习集合移出（`CR-05`） | 同样移出；**已失去访问权的题不再进入任何可执行学习队列** |
| 历史记录呈现 | — | 必须**标注来源题库与「已退出 / 已失去访问权」状态**，不得让人以为历史凭空消失 |
| 恢复后 | 取消归档即恢复 | 重新成为成员即**恢复对应学习能力**：该库未归档题重新进入可执行复习集合，凭原有学习状态继续，不重新从零开始 |

- **进行中的会话在权限撤销后的处理**（本轮新增，`FN-417`/`FN-418`）：
  - **普通练习会话**：可以按**会话快照**继续答完并交卷——会话建立时已持有题目与版本快照，做题不依赖持续的成员权限；交卷后报告正常落库、可回看。**但交卷后该会话涉及的题不再进入新的可执行学习队列**（已无访问权）。
  - **模考会话**：同上，按快照继续，超时/交卷规则照 `CR-31` 执行，报告永久可回看（`CR-25`）。
  - **不得**因为权限撤销而删除或作废任何已存在的会话、作答或报告。
- **必须区分的边界**：归档可以允许会话按快照继续，**但权限撤销不能机械套用归档规则**——归档是「库的事」，权限撤销是「这个人与这个库的关系的事」，后者不改变库对其他人的可见性，也不赋予该用户任何回看题库新内容的权利。
- **回看权与访问权的边界**：个人历史记录（作答、成绩、笔记、错题、FSRS 状态）的**回看权始终属于用户本人**；共享题库内容的**访问权**随成员关系消失。用户可以回看「我在这道题上得过几分」，不等于可以再看这道题现在长什么样。

### CR-31 模考到点：作答窗口结束 ≠ 会话终结（本轮新增）
统一 `FN-307` / `BR-311` / `OP-307` / `ST-201` / `ST-302` 五处口径。限时考试的时间线固定为三段：

1. **作答窗口**（开考 → 服务端硬截止）：正常作答、同步草稿、标记。
2. **宽限**（硬截止 → 硬截止 + 宽限时长，默认 60s，显式产品参数）：**只用于把截止前已经产生的答案同步上服务端，不用于继续答题**。宽限内不接受新的作答、不接受改答案、不接受标记；界面明确告知「已到交卷时间，答案已停止收录」。
3. **收卷**（宽限结束）：**由服务端完成交卷并生成报告，不要求用户保持页面打开**。客户端再次打开该会话时，直接看到已生成的报告。

- **超时禁止的是「继续作答」这类写入操作，不得同时禁止必要的终结与报告生成**：`is_expired` 态下 `complete`（交卷）与报告读取**必须放行**。历史上「`is_expired` 后全部拒绝」的口径废止（`ST-201`）。
- **未成功同步的答案必须明确告知其处理结果**：收卷后报告页与终结横幅列出「本机有 N 题未同步成功，未计入本场成绩」，并说明这些答案仍保留在本机、不计入。不得静默丢弃，也不得悄悄补进成绩。
- **交卷来源必须可区分**：`manual` / `auto_deadline`（到点自动交卷）/ `expired_server_answers`（超时后以服务端已存答案交卷），报告页与考试档案回看都据此显示（`ST-303`）。
- **不限时考试单独定义，不与限时考试混用**：不限时会话**没有硬截止、没有宽限、没有自动交卷**，只能由用户主动「交卷」或「放弃」；连续无活动达到阈值（默认 30 天，可配）后**明确失效并告知**，失效后仍由用户显式选择交卷或放弃，不静默、不自动判成绩（`ST-302`、`Q-206`）。
- `time_limit` 只接受**正整数分钟**或**明确的不限时标记**，不接受 `0` 这种既非限时又非不限时的歧义值（`GAP-329`）。
- 宽限时长、硬截止都是显式产品参数，在会话详情可见（`GAP-320`）；禁止把 `created_at + time_limit + 60s` 一类实现公式当产品规则（P-12）。

1. **三档（375 / 768 / 1440）不得出现横向滚动**；宽表格由自己的容器滚，不撑破纸面。

5. 每个动作都必须有**可见入口**；长按/滑动只作为增强，不作为唯一路径。
6. 外壳断点收敛为 **1280 / 1024 / 768 / 640** 四档；各视图残留的 scoped 旧断点见 `GAP-607`、`GAP-118`、`GAP-328`。
7. 移动端「更多」= 进入设置页（设置内含主题/语言），不做成第二层浮层菜单。
