## 3.1 现状基线（读诊断文档前必读）

本地源码树的当前 HEAD 就是 **v1.0.24 发布版本身**（`feat(ux): core UX redesign P1-P6 and release 1.0.24`）。因此：

- `UX_CORE_REDESIGN` 的 **§5「各域诊断」描述的是重设计之前的状态，不是现状**；
- **§9–§14「P1–P6 实施记录」是已经落地的修正**，属于现状；
- **§14.3「刻意没做的」与 §14.4「已知残留」是真实存在的能力边界与残留**，是本规范 GAP 清单的主要来源之一。

判定一条问题是否算「现状缺陷」：只有 ① 实施记录之后仍未解决（含 §14.3/§14.4 明确列出的），或 ② 实施记录未提及、由本次读代码新发现的问题，才进 GAP，且必须附 `file:line`。

原型（OpenDesign 项目）同样基于 v1.0.24 构建。若发现原型与生产代码的信息架构不一致，登记为 GAP，类别「配置与实际不一致」。

> ⚠️ **注意区分「源码现状」与「线上实例现状」**：本机 `127.0.0.1:3000` 上跑的是一个**早于本地 HEAD 的构建**（实测 `/api/v1/admin/*`、`/api/v1/sessions` 返回 404，`/auth/me` 不返回 `is_admin`）。因此凡涉及权限面、实例管理、会话管理的「现状」判断，**一律以本地源码为准**；线上实例只用于确认接口契约与旧行为，不得用它否定源码里的已实现能力。

### 6.3 最终修正（同日，第四轮）

在线 AI 直读 `aaba26f` 正文复核：整体通过，仅剩两处明确错误，本轮只改这两处及其直接关联条目。

- **批量「无须变更」示例写反**（`CR-27`、`BR-104`、`OP-102`、`OP-607`、40 册批量段）：正确规则是**归档未归档题 → 执行归档；归档已归档题 → 无须变更；恢复已归档题 → 执行恢复；恢复未归档题 → 无须变更**。原规格把四种情形的前两种写成了无须变更，等于把该做的说成不做的。同时**清除与整批校验冲突的残留「跳过」表述**：校验失败即整批拒绝零写入，不可能出现「跳过几条、做成几条」，故结果只有「**成功 X · 无须变更 Y**」两项且 `X + Y = 已选 N`，原「成功 X / 跳过 Y」「成功 X · 无须变更 Y · 跳过 Z」一律废止。
- **客观题满分与统计口径**（`CR-06`、`BR-205`、`BR-231`、新增 `BR-313.1`、`FN-308`、`FN-219`）：**客观题满分 = 本场全部客观题的分值之和，与用户是否作答无关**；未作答客观题按 0 分计入得分但仍占满分；「只含已判分的客观题」只用于排除主观题，不排除未作答客观题。**考试得分率**（客观题得分 ÷ 客观题满分，分母含未作答）与**已答客观题正确率**（答对的已答客观题 ÷ 已答客观题）分别计算、不混用分母。已冻结的部分得分、负分与零分下限规则不变。验收示例：100 道每题 1 分的客观题只答对 1 道 → **得分 1 / 满分 100 / 得分率 1% / 已答客观题正确率 100%**。
- 同步新增术语「考试得分率」「已答客观题正确率」，`00` 册 §11 补 `R41`/`R42` 两条索引。
