# EasyExam 领域避坑与验收护栏

这里保存本地真实项目中已经验证过的、比通用 Starter 更具体的领域规则。它是 `AGENTS.md` 中领域红线的展开，不新增产品需求；行为真理仍以 `SPEC.md` 为准。

## 专项题目集合

- 错题专项必须由服务端校验目标题目属于当前用户未清除错题队列。
- FSRS 专项必须由服务端校验题目当前已到期；客户端传入 `question_ids` 不能绕过集合约束。
- 斩杀查漏补缺必须校验题目属于已斩杀集合，并保留 `bank_id` 上下文。
- 任何专项模式都不能因为客户端漏传或伪造筛选参数而退化为整本普通刷题。

## FSRS 与历史数据

- 评级必须支持 Again/Hard/Good/Easy；答案相同但评级变化时也必须更新。
- 作答记录保存真实作答前 `card_snapshot_json`；两步交互与一次性评分必须得到等价调度结果。
- 历史记录缺少快照时不得把当前卡片状态伪造成历史快照。
- 已经调度过的无快照历史作答修改评级时，只更新反馈，不得基于当前卡片二次叠加或重置；从未调度过的记录才允许首次调度并生成快照。

## 迁移与导入

- 临时密码账号必须设置 `must_change_password=1`，完成改密前服务端阻断非豁免业务 API。
- 旧库孤儿题目进入 `unconverted` 报告，不能静默丢弃。
- 迁移后物理核对题库、题目、会话、作答和错题数量及关键关联。
- 批量导入预检失败不得落盘；批量写入使用单一事务，中途失败必须整批回滚。
- 重复导入必须先返回预检结果，只有用户明确选择 `skip`、`new` 或 `merge` 后才写入。

## 作答、会话与数据一致性

- 作答提交与交卷必须支持幂等重试，不能重复插入作答、错题或 FSRS 推进。
- 已交卷、已取消或其他终结状态的会话必须拒绝后续作答。
- `mistake_records` 保存用户级错题事实，学习掌握与统计单独保存；一次作答相关更新应在同一事务内完成。
- 主观题可以保存作答和解析，但不计入客观正确率；部分得分不能直接等同于完全正确或已掌握。

## 证据边界

- API 单测、Node 测试、Mock 或构建成功不能冒充真实浏览器 E2E。
- `skipped` 不等于通过；未运行必须明确报告。
- 目录、接口、数据库表存在不等于用户闭环完成。
- 修复一个缺陷后必须全局搜索同类实现，不能只修报错单点。
- 推进 OSS 复用时先读现有审计和总路线图，不让实现批次退化成重新泛扫仓库。
